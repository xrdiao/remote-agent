# Remote Agent 全功能排查与压力测试方案

日期：2026-11-02。功能依据：[基准索引](../baselines/README.md) 的 01—06、08、09 及当前实际界面。以用户入口和完整操作闭环组织，不沿用 problem.md 的问题列表。

## 范围与授权

- 覆盖 Cursor、Devin、Codex 的普通功能及共享工具；排除 Fusion 和 Devin err13 根因排查。Devin 依赖成功生成的场景若被 err13 阻塞，单独记录，不换代理、反复提交或冒充通过。
- 用户已授权将本方案写为文档并开始测试；只排查和记录，产品修复另列根因、逐文件改法及影响范围，确认后实施。
- 用户本次明确要求释放旧配对浏览器，使用独立的新浏览器资料完成一次新配对。本轮只允许生成一次真实配对会话、提交一次真实配对申请；失败保留现场，不自动重新配对。该要求优先于 workflow 的复用旧浏览器约定。
- 配对链接、配对码、批准凭据、令牌和私钥不进入文档、控制台、截图及测试结果。批准页只在本机测试浏览器使用，完成后关闭并消费一次性配对会话。
- 新浏览器不复制旧浏览器资料或身份。后续恢复只复用这次配对，不再创建真实入口；其他授权、取消、过期和 2FA 边界使用隔离受控测试。
- Ubuntu 为实际执行环境；桌面配对浏览器自动化与 Safari 真机分别记录。没有对应手机／构建的项目记待验，不以桌面模拟尺寸代替真机。

## 基准与现场

1. 开始时核对工作区、已有改动、实际 GitHub 远端；保存当前跟踪文件指纹、软件／扩展版本、网页资源版本、relay 启动参数、原生窗口及草稿摘要。
2. 当前起点为干净的 `c95b054c7257dead6dc18bf032a795479196331f`、源码 v377；执行中若有外部改动，按实际归属记录，不覆盖。
3. 测试文件、独立项目、脚本、截图和日志统一放 `_shots/full-functional-20261102/`。正式 relay 不重启，不发布、不提交、不推送。
4. 旧测试浏览器先记录状态，仅撤销旧测试入口并关闭其独立浏览器进程；旧资料保留作历史证据。新隔离 relay 使用独立数据目录，新登记替换 `_shots/paired-browser.json`，后续沿用既有恢复脚本。
5. 原生写操作只针对本轮独立项目、会话、文件和终端。测试前记录模型／参数与草稿，收尾恢复本轮改动；不刷新、停止或关闭用户原窗口。

## 压力与竞态

| 编号 | 场景 | 首轮规模与完成标准 |
|---|---|---|
| S01 | 同项目会话切换 | 每应用空／短／长历史会话；逐次切换 20 次，再以约 200–500ms 间隔快速切换 30 次。最后被接受的目标生效，不串正文／草稿、不多开窗口，旧读取结束 |
| S02 | 模型与参数 | 菜单开关 20 次，两个可用模型往返选择 10 次；覆盖强度、重开及读取中切会话。原生读回值与手机一致，失败后可继续操作 |
| S03 | 跨目标 | 项目、Agent、已有授权电脑各做 10 次往返，叠加未完成读取；目录、权限、用量和回包不串目标 |
| S04 | 长历史与滚动 | 分页、展开／收起、上下轮各 10 次，叠加更新与自由阅读；不丢／重消息、不误回底、不积压旧定位 |
| S05 | 文件与传输 | 快速预览 20 次，保存中切文件，批量小文件及符合现有限制的中等文件；内容／回执对应，只写一次、正确取消 |
| S06 | 前后台与断线 | 短后台返回 10 轮，五分钟边界先受控覆盖，Safari 另做实际对照；区分未发起连接、连接失败、认证及首屏等待 |
| S07 | 混合操作与资源 | 一轮约 10 分钟的导航／菜单／预览／刷新组合，记录开始、峰值、结束和空闲后的资源；结合缓存上限区分正常预热与持续增长 |

遵守真实界面禁用状态，不绕过按钮强行提交。压力主要来自导航、菜单读取和文件操作，真实生成使用少量短任务，复用任务验证队列、追加、停止和审批，不靠批量模型调用制造负载。不可用的原生长历史单独记待验，不修改原生数据库或扩展来构造历史。

## 网络与 RA 的分段对照

同一目标和操作比较：桌面原生 → RA 直连隔离 relay → 经实际入口／隧道。首次与缓存加载分开，复用 requestId／navigationId 和实际电脑、软件、窗口、会话身份关联。

记录：点击、请求发出、relay 收到、排队、原生操作／读取、响应发出、浏览器收到、页面完成。各端计算自身耗时，不相减未经校准的跨设备时钟。重复场景记录样本数、成功率、中位数、P95、最大耗时和失败后的恢复。

| 证据 | 归因规则 |
|---|---|
| 原生／直连正常，隧道明显慢 | 定位传输阶段，仍核对 WebSocket，不仅检查 HTTP |
| 请求已到 relay，取消／排队／读取持续积压 | 检查 RA 调度、归属及生命周期 |
| 原生值已更新，RA 仍旧值或等待 | 检查 RA 确认、读取与显示 |
| 原生同场景也失败 | 单列原生／上游，不直接归为 RA |
| 网络变慢触发 RA 串目标、重复写入或无结束状态 | 同时记录网络触发条件与 RA 缺陷 |
| 证据不足 | 标记未定，不凭慢、1006 或一段错误文字下结论 |

必要的 HTTP／WebSocket 延迟、断连和扣留响应只在隔离代理或临时测试页实施，明确是否真正覆盖对应链路，不影响正式服务或系统网络设置。

## 执行与交付

1. 写入方案、固定基准。
2. 释放旧测试浏览器，完成一次新配对，立即核对次数、设备数量、认证和链接清理。
3. 常规功能闭环，再执行固定规模压力；异常转最小复现和原生／网络对照。
4. 每个用例标明 Agent、环境、层次、目标、步骤、预期／实际、时序、证据及归因。状态只用通过／失败／受阻／未执行／原生不支持；受控与真实分列。
5. 手机、跨电脑、原生壳、麦克风等没有当前环境的部分列出实际待验，不计通过。
6. 统一运行 `npm run check`，核对差异、原窗口和本轮资源。新配对浏览器与隔离 relay 留供续验，不再次配对。
7. 输出 `_shots/full-functional-20261102/report.md`、`cases.json`、各阶段证据与缺陷表；问题附根因证据、影响、建议文件与验证办法，产品修复另行确认。
