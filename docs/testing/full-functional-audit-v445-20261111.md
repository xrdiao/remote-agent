## 二、范围、环境与能力

### 检查边界

- 四个普通应用、共享工具、Fusion、连接／安全、通知、PWA 和现有原生壳全部纳入清单；没有环境的项目保留待验，不能从总表删除。
- 用户已决定不处理 OpenCode 自动压缩策略及本地模型记忆能力。只检查 RA 对原生压缩提示、合成消息、错误、后续新消息的显示和同步；不调保留预算、摘要提示或模型参数，不专门触发压缩。
- Devin 的原生生成错误不预判持续存在或已经消失：先核对当前条件，原生仍失败则保留错误、停止依赖该结果的测试，不反复换模／换代理尝试。
- 原生软件、模型服务、网络及 RA 分别归因。模型生成质量不等于 RA 功能正确；原生已接收不等于任务完成，HTTP 可达不等于 WebSocket 正常。
- 普通功能按真实入口测试。内部函数和受控帧只用于定位及边界，不绕过禁用控件制造“真实通过”。

| X02 | 已启用工作台打开、未启用配置、主页／收藏／历史来源 | 按主绑定进入新鲜正文，摘要与详情分读；工作台名和原生主会话一致，返回位置保留 |
| X03 | 主控直接执行与零子任务 | 目标／范围／计划／验收可追踪；不为主控自己执行创建重复自派任务，交付有原生及产物证据 |
| X04 | 自主派工、依赖串行与独立并行 | 真实主 Agent 调用工具，记录 Task／Worker／Binding／Attempt；依赖先后和执行时间可核对，不按软件强行互斥，不允许嵌套派工 |
| X05 | Worker 复用、补做、相关新 Task | 复用原生 thread；同 Task 新 Attempt 与新 Task 独立；同 Worker 排队，不因未知结果重复提交；新建／复用有实际选择依据 |
| X06 | 主控问题、方案确认／修改／拒绝、原生审批 | 目标请求与主轮次对应、草稿保留；修改／拒绝不授权执行；原生权限不自动批准；原生操作结果明确 |
| X07 | 结果 → 评审 → 返工 → 交付 | 结束、完成、已验收分别有证据；真实一次含子任务及评审的闭环，不能以受控结果代替；不以模型自称通过代替文件／命令核对 |
| X08 | 摘要、任务板、详情／证据按需读取 | 列表不携完整历史，展开才读；分页／关闭／重连归属明确，监听释放，输入、展开、光标和滚动保留 |
| X09 | 档位、模型资料、成本与预算 | 原生可执行候选与公开资料来源区分；省钱／均衡／性能选项保存；未知费用不编造账单，预算仅按可核实单位判断 |
| X10 | 任务／工作项／工作台停止及恢复 | 仅停止所属本次原生执行；未确认保持 stopping；恢复核对已提交事实，不重发未知任务，不把停止当完成 |
| X11 | 普通会话与多个工作台隔离 | 后台执行不改用户前台项目／模型／权限／草稿；不同电脑／工作台不串事件；主会话和子会话按当前卡片规则展示 |
| X12 | 重命名／收藏／删除及清理 | 自有工作台按明确操作修改；删除范围按实际绑定核对，不删除普通会话或其他工作台；核对事件、监听和原生清理结果 |

真实生成控制在完成闭环必需的少量任务，先以 Codex 主控建立一组可追踪基线，再按实际可用主控／Worker 软件补覆盖；复用已有测试线程，不做全模型和全部主子组合。缺少 Devin／Cursor 原生生成条件时单列受阻，不用“Codex 成功”替代其他软件结果。

## 六、压力与竞态规模

先完成正常用例再执行压力。遇到确定性失败，保留最小复现并暂停依赖它的后续项；不重复制造真实写操作。

| 编号 | 场景 | 首轮规模和观察点 |
|---|---|---|
| S01 | 普通会话打开／返回／快速改选 | 四应用各 20 次正常开关，比较前后各 5 次；正常后再做 30 次约 200–500ms 快速选择，记录实际被接受次数；空／短／长历史各有覆盖，不串目标、无遗留导航 |
| S02 | 模型及参数读取／切换 | 各应用菜单 20 次开合；两个实际可用模型 5 次往返，每次读回并最终恢复；强度／权限按受影响分支检查，不为凑次数额外生成 |
| S03 | 项目／应用／电脑交叉 | 同项目、跨项目同名路径、普通 ↔ Fusion 各 10 次；两台已授权电脑可用时再做 10 次往返，否则受控／待验分别记 |
| S04 | 长历史和阅读 | 连续向前分页、工具／思考展开收起及上下轮各 10 次，叠加生成更新与自由阅读；保序、去重、一次保位、实时同步均正确 |
| S05 | 文件／媒体／传输 | 预览 20 次；小文件批量、目录／ZIP、中等文件及取消／恢复各一组，大小按现有限制；保存／下载校验哈希与归属 |
| S06 | 前后台／断线 | 短后台返回 10 轮；五分钟边界先受控，真机另验边界前／后；连接关闭、发送结果未知及迟到首屏分别覆盖 |
| S07 | 混合操作及资源 | 约 10 分钟，导航／菜单／预览／历史／更新混合，按阶段采样开始／峰值／结束／空闲后；CPU／内存／队列／监听／连接／缓存及WS排队无持续未回收增长 |
| S08 | OpenCode 重复进出及工具流 | 真实长会话 20 次进出、缓存／原生分页至少跨一次、同时展开 3 个工具；发送合并不堵导航，详情按选择发送，消息体积与页数相符 |
| S09 | Fusion 视图生命周期 | 工作台／任务／执行／证据切换 20 次；一次真实依赖闭环，停止／恢复／重连其他组合优先受控覆盖；订阅归零且Runner事实不丢 |
| S10 | 重复语音 | 两处输入框各连续 3 次系统识别；已安装电脑引擎各一组完成／取消／重开，真实麦克风由用户完成；检查第二次而非只测首轮 |

不使用绝对堆大小或一次峰值判泄漏；记录缓存预热、共享窗口、后台 Runner 和恢复上下文各自生命周期。未知写结果先核对原生，不以重试施压。

## 七、慢、阻塞和断线的分段归因

对同一应用、目录及会话，分别比较原生、当前源码的本机 QA relay、经真实隧道的同版本链路。先确认后端与资源一致；只有条件齐全的样本才进行跨路径比较，不借用正式手机凭据或建立第二入口。

| 阶段 | 记录与判断 |
|---|---|
| 用户意图 | 点击／目标／导航 ID，是否被禁用、是否真正发出请求、卡片等待提示 |
| relay 调度 | 收到请求、队列等待、取消／改选、绑定开始结束；“连接已建立”不等于“会话已就绪” |
| 原生读取 | 首屏／全部历史／模型目录／工具详情各自次数、耗时和返回身份；卡片与正文分别读了什么 |
| 数据与传输 | 首屏／历史／详情的原始及实际发送字节、快照频率、write完成、Pong、bufferedAmount；是否重复请求或重复发完整历史 |
| 客户端 | 收到、解析、合并、绘制／图片完成，阅读位置与交互可用性；界面正常滚动不能单独排除导航阻塞 |
| 关闭与恢复 | 手机关闭原因、visibility／后台计时／lastRx、relay关闭码与来源、隧道事件、重连请求／认证／绑定／首屏；区分后台暂停、心跳、替换连接、授权和传输中断 |
| 资源 | 同期CPU、MemAvailable／换页、模型GPU、事件循环和连接队列；有显卡负载不等于RA CPU被占满 |

时长在同一端单独计算，不直接相减未校准的手机／电脑时钟。首开、热缓存、重开、读过旧页后的重开和恢复连接分别统计 n、成功率、中位数、P95、最大值；数据量不同的样本不可直接比较。v445 的 1491520→157807 字节仅为上一轮一个 OpenCode 样本，不作为全应用耗时保证。

本次已知 `1006` 记录和公网 HTTP 探测保留为线索，**断线根因仍待手机端来源和 WS 同期证据**。必要的帧延迟、断连和迟到响应仅在隔离代理／临时页进行，明确是否覆盖实际 WS 双向链路；不修改系统网络、代理或正式隧道来造故障，不新增产品埋点或兜底逻辑。

## 八、执行顺序和结果标准

1. 固定当前工作区及运行基准，核对能力、版本和旧未验项；先执行本轮 `npm run check`，确认907项历史基线有无增减与实际失败，不覆盖原记录。
2. 优先 R01—R08、R10—R12：导航阻塞／串目标、Cursor正文与图片、OpenCode历史／工具／空泡、统计及连接，先解决是否可继续检查的前置问题。R09 和真机布局／通知由用户在已有配对手机验收。
3. F01—F18、F20—F21 完成普通功能闭环，再执行 Fusion X01—X12；相关异常按依赖暂停，独立项继续。
4. 执行 S01—S10，先小规模再固定规模。原生生成、停止、审批、文件写入和删除仅操作明确属于本轮的测试对象，遵守本轮授权；旧文档的单次特例不是新的执行授权。
5. 将结果分别登记为 **通过／失败／受阻／未执行／原生不支持**，另设“源码／受控／真实原生／配对浏览器／手机／壳”证据层次。一个子场景通过不能让整项或其他软件、平台变为通过。
6. 初次失败与脚本夹具错误保留。产品问题必须给用户触发步骤、实际／预期、最小复现、请求／状态归属、证据与根因置信度；没有证据标未定，不用堆条件、隐藏入口或延时写成修复方案。
7. 修复另行列逐文件方案并确认；修复后只重验失败和受影响项，最后运行 `npm run check`。没有产品变化时不反复跑已通过相同检查；原方案编制阶段不记为已执行；当前实际执行状态以结果报告为准。
8. 收尾对照原窗口、草稿、模型、队列、终端、Fusion 事实、配对与存储，清理本轮临时页／监听／文件／测试对象，保留既有配对与证据。不归档／删除用户会话，不自动发布或重启正式服务。

### 台账及交付

- `baseline.json`：工作区、运行版本、原生软件／扩展、能力、环境、现场指纹；敏感字段不导出。
- `cases.json`：每个用例的 ID、功能、应用／平台、目标匿名标识、步骤、预期、实际、状态、证据层次、时间、限制及关联缺陷；F／R／X／S交叉验证可引用同一次执行，不重复计通过数。
- `timings.json`、`resources.json`：导航／分页／传输分段耗时、负载、资源前后及样本统计；没有观测的阶段留空。
- `findings.md`：产品缺陷、原生／网络问题、文档差异、测试环境限制分列；按丢数据／误操作、阻断、性能、外观排序。修复建议列文件、范围、根因证据与受影响回归。
- `report.md`：各应用及 Fusion 的覆盖矩阵、通过／失败／受阻／未执行／不支持数量、旧问题本轮状态、真机待验清单、现场恢复及未完成项。

完成标准是 **全部条目都有明确状态和证据／未执行原因**，不是宣称全部通过。源码自动化907项、受控浏览器和旧专项均不能替代本轮真实业务闭环或手机验收。Android／iOS／Windows／macOS／第二电脑缺环境时明确保留待验；不为取得“全绿”改变能力声明、范围或断言。
