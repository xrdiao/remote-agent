## 目标与顺序

让新增 Agent 的工作主要集中在自身适配模块，复用手机界面、中继连接管理、历史缓存等公共能力，同时保持现有功能与性能。

顺序：修复已确认问题 → 确定最小适配接口与能力声明 → 迁移一个现有 Agent → 分步迁移其他 Agent → 实际接入新 Agent → 整理接入模板 → 按实测瓶颈优化。

前置的两处问题已完成修复：终端初始化结束后遗留轮询、终端列表提前返回。定向检查和项目检查已通过；这不代表所有功能已完成真机验证。

### 基础接口范围

下表是职责清单，方法名称和文件位置待对照现有实现后确定。

| 职责 | 需要明确的内容 |
|---|---|
| 描述与发现 | Agent 标识、名称、图标、连接入口、窗口发现 |
| 连接与释放 | 连接到指定目标、断开连接、释放监听和定时器 |
| 聊天读取 | 消息内容、运行状态、草稿、当前会话标识 |
| 发送与停止 | 操作目标、发送结果、停止结果；保留各家原生语义 |
| 会话管理 | 列出、新建、切换会话，以及项目和窗口归属 |

### 可选能力声明（Capabilities）

| 能力 | 声明需要覆盖的内容 |
|---|---|
| 模型与参数 | 模型切换、思考强度及其他原生参数 |
| 排队与追加 | 是否支持排队、立即发送、追加及队列编辑 |
| 审批与提问 | 是否支持读取和响应原生待操作请求 |
| 附件与引用 | 图片、文件、项目文件引用 |
| 终端 | 是否具备终端读取及操作入口 |
| 设置与额度 | 可读取或修改的设置、额度读取 |
| Fork 等扩展操作 | 按实际能力提供，不要求每家实现全部功能 |

前端依据能力显示入口；当前连接暂不可用时保留明确状态。区分 Agent 能力与中继公共能力，例如独立文件传输不应要求每个 Agent 重复实现。

### 统一数据与生命周期

- [ ] 会话：区分 Agent、项目、窗口、会话标识，保留原生工作目录。
- [ ] 新建：明确创建中、空白可输入、已有正式 ID 等状态；支持首次发送后才产生正式 ID。
- [ ] 消息：统一用户消息、回复、思考、工作说明、工具记录和编辑记录的基本字段。
- [ ] 工具：提供执行/读取/搜索/编辑分类、运行结果及待操作状态，供共用界面筛选和折叠。
- [ ] 操作：保留原生目标和含义，不能将不同 Agent 的审批范围、排队方式强行视为相同。

交付物：接口表、能力表、数据字段约定、生命周期说明及最小迁移方案。

## 实施约束与验证规则

- 修改代码前取得确认；一次确认的范围内连续完成，不反复询问相同事项。
- 最小修改，不附带大范围整理，不擅自增加保护或兼容逻辑。
- 保留现有导航、新建会话、执行指令显示、发送语义、缓存、滚动与轮询优化。
- 不建设插件市场、动态安装或未经实际需要验证的通用框架。
- 测试使用独立项目、会话和配对浏览器，避免干扰正在运行的真实任务。
- 测试配对先备份设备列表，结束后仅删除本次新增的精确设备 ID；产物放 `_shots/`。
- 修改后只复测失败项和直接受影响项；必要检查通过后不重复全量测试。
- 修改公共聊天提取器时，按项目约定实际验证三个 Agent 的提取；受控测试不替代真机结论。
- 完成功能后更新开发记录，区分实现完成、受控验证和真机验证。
- 代码修改后的发布、重启及核对遵循项目约定，重启前确认 Fusion 状态；不自动提交或推送源码。Cursor试点完成后的发布重启依照开发记录执行，不自动提交源码。
