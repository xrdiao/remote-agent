# Codex Markdown 与图片编辑保存修复

日期：2026-10-27；网页交付：v277。仅修改用户确认的两项，原因见 [排查记录](markdown-image-save-audit-20261027.md)。

## 实现与范围

- `app/js/chat.js`：助手正文按当前会话已经确认的 Agent 身份启用 Codex Markdown。真实回包及旧缓存没有 `src` 也能渲染，不添加来源字段、兼容分支或缓存迁移；原生富文本仍优先，复制仍使用原文。
- `app/js/voice.js`：本地编辑结果加入现有 imageUploads 后返回；用一条有序 Promise 队列执行既有图片处理、二进制上传和原生附加。加入上传与原生完成分别确认，附件在完成／失败／取消前保留状态，既有发送检查仍阻止未完成或失败待处理图片发送。
- 执行阶段原来的连接、会话归属、取消与失败处理保留；没有自动重试层、新定时器或另一套附件状态。多图按入队顺序传输，替换成功前仍保留原图。
- 图片处理函数与原尺寸／质量参数逐字比较不变；图片编辑器源码、文档上传、历史分页、滚动、底部吸附和全部服务端源码均未改。其他产品改动仅为 core、入口 HTML 和 worker 的 v277 缓存交付。
- 功能基准 02、06 已同步明确当前 Agent 渲染身份与本地保存／后台上传的区别。保留工作区原有更改，没有提交／推送 master 或 debug，没有修改或测试 Fusion。

## 图片验证

在自有测试项目中，使用受控测试文件输入，通过实际编辑器旋转和保存按钮操作；没有发送聊天消息。完成后移除测试附件并恢复原选择。

| 场景 | 结果 |
|---|---|
| 新图编辑保存 | 本地保存关闭后 HTTP 仍在进行；附件仍为待完成，实际点击发送被阻止；最终原生附图回执成功 |
| 已附加图片再编辑保存 | 保存立即返回；上传中旧图保留，完成后只替换一次 |
| 取消替换 | 真实二进制上传完成后暂缓提交原生附图，点击附件取消；原图保留，没有提交替换 |
| 两图编辑保存 | 两个结果均加入上传；受控暂缓第一项时第二项没有开始传输；HTTP 和真实原生 paste 顺序均符合选择顺序 |
| 取消排队图片 | 队列内第二项取消后未上传，第一项正常完成 |
| 失败与重试 | 受控 HTTP 异常显示失败并保留文件；点击真实重试按钮后上传及原生附图成功 |
| 上传后切换 Agent | 在真实二进制上传后暂缓返回，再切 Agent；旧图片不提交到新目标，也未附加到旧目标，失败项可取消 |
| Cursor／Devin | 两者原生附图和移除均通过 |

共九组配对浏览器检查通过。七项隔离检查另覆盖入队不等 HTTP、有序执行、原生回执前保留待完成、队列取消、失败不阻塞后续任务、传输取消清理与目标切换。

保存耗时样本：修复前本地处理约 56 ms，却等待约 11.45 秒 HTTP 才关闭编辑器；工作区修复后编辑保存／替换为 72／78 ms。公开 v277 的相同操作分别为 63／85 ms，两图保存为 29 ms。该公开样本的 HTTP 本身等待约 24.35 秒，编辑器已先关闭，附件直到真实原生回执后才结束待完成。这说明修复的是软件将网络等待绑在本地保存上的问题，不代表公网传输被压缩成上述保存时间。
