## 原因与修复

| 功能 | 根因与最终修改 | 影响范围 |
| --- | --- | --- |
| Codex 排队消息编辑 | 旧实现从全部按钮的 React 属性里找回调，可能拿到普通历史消息编辑入口；列表还有 4000 字摘要限制。改为当前原生输入组件的队列控制器，读取完整队列文本，进入对应队列编辑态后保存，确认完整正文及新队列 ID，再更新手机回执。 | Codex 队列编辑／移除／立即发送共用的操作绑定；不改变普通消息编辑和发送意图。 |
| Cursor 排队消息编辑 | 原生 Enter 服从用户的发送／追加偏好，不能代表“保存且仍在排队”。改用 Cursor 自身 `saveEditedItemBackToQueue`，保留原队列身份、顺序及附加元数据。 | Cursor 队列保存；不改原生全局回车偏好。 |
| 编辑期间的草稿与回执 | 编辑队列临时借用原生主输入组件，不能让草稿读取或手机同步与它争写。编辑过程占有所属输入目标；保存后恢复主草稿，并认领保存回执。手机等完整文本再允许编辑，等实际保存成功才关闭；失败保留文本与重试入口。 | 队列编辑过程及其对应草稿同步、请求关联。 |
| Qwen 语音收尾 | 官方流式接口会固定较早的文字前缀，原收尾只补剩余音频，不能完整纠正前文；32-token 增量预算也不能用于整段输出。保留流式预览，松手后合并同一状态中的 `audio_accum` 与 `buffer`，以原生完整音频接口独立识别；最终预算用官方完整识别的 4096-token 默认值，随后恢复预览参数。 | 仅 Qwen worker 的最终识别；复用模型，不新增进程／模型，不落盘录音。CPU／手机系统识别及传输、背压、取消、草稿插入保持。 |
| Codex Markdown | 原先靠 HTML 字符串是否等于某种纯文本形式猜测格式，无法覆盖带包裹标签的旧正文；工作过程／思考仍直接写 `textContent`。读取端明确标识原生 HTML／Markdown；手机保留已确认原生富文本，其他从完整原文解析。工作过程与思考共用 Markdown 渲染，正文没变不重建节点。 | Codex 回复、工作过程和思考格式；共享消毒器补齐 H6。工具命令仍按字面显示，复制原文及文件、公式、代码、Copy／Fork／Retry 动作保留。 |
| Codex 发送确认 | 提交前四次重复读取，确认又反复处理整轮内容；真实接收不应等完整聊天或上下文。改为一次共享快照，只读取用户消息／队列身份，复用原生变更通知确认，回执先于完整聊天读取。 | Codex 接收确认及其原生读取；用户消息归一化与历史共用原有来源，不改变正文、顺序及分页规则。 |

CPU Sherpa 本来就把所有音频帧送入同一连续识别状态，不是每帧单独重置转录。本次保持该模型和末尾补齐；没有增加第二次 CPU 离线整段识别。Qwen 最终识别增加一次整段推理，收尾时间取决于音频长度及硬件；不承诺识别质量在所有录音上都提高。

发送确认仍以真实新消息／队列身份为准。没有证据时继续“待确认”，不提前清空用户草稿、不自动重发。同文本的独立发送分别确认，旧选择的迟到回执不能覆盖当前草稿。
