# 入口恢复与失败收尾修复（2026-10-28）

范围：当前入口的冷启动／刷新恢复、项目与会话绑定、打开失败回初始页。未修改聊天滚动、发送算法、模型、通知、文件、Fusion 或 Windows 专项代码。

## 根因与实现

- 旧恢复记录按电脑共享，多个配对入口会相互覆盖。本轮在电脑端按稳定电脑 ID＋独立配对入口 ID 保存最后成功目标，同时保存该入口各 Agent 的成功目标。新入口不继承旧电脑级共享记录；设备分组不合并入口身份。星标／名称的共享规则不变。
- 原先在异步读取项目、写盘之前就标记保存完成，失败后相同目标不再尝试。现在复用同目标在途保存，项目读取及保存成功后才标记；失败释放任务，下一次有效快照可重试。恢复记录清理本身写盘失败时明确报错，同时仍结束导航，不把清理异常变成串行队列永久阻塞。取消、缓存、其他会话及旧绑定结果不写入记录。
- 旧窗口关闭时，恢复可能选择任意同类窗口，再把旧会话塞入该窗口。本轮先绑定 Agent，再按已保存的真实项目路径／主机确定项目，复用既有项目打开及会话选择流程。没有项目身份的明确关闭窗口直接失败，不自行换到其他窗口。存在本轮启动标记时，将旧窗口、项目和会话作为一个旧目标整体清除，避免刚启动的 Agent 被旧窗口 ID 阻断；该项由隔离模块模拟启动标记验证。
- 所有本轮普通 Agent 导航失败共用结束流程：取消所属读取、清除当前入口该 Agent 的恢复记录及失败界面、结束等待。仍有连接时进入该 Agent 的项目／会话选择初始页，未连接时回连接页；不切到其他 Agent、不创建会话、不停止桌面任务。初始页停止失败会话的轮询，发送不可用；重新选择成功后恢复读取及监听。
- 失败取消旧元数据读取后，建立新的读取作用域，保证初始页能发起真实列表读取，不能依靠缓存假装可用。首屏绑定的异步异常也回到导航自身的结束流程。
- Codex 编辑器到聊天 WebView 的交接保留 v292 的既有修复。本轮没有根据插件版本号添加兼容分支。

## 已执行验证

临时目录中的真实模块及替身边界检查：

- 两个入口、同入口不同 Agent、模块重载持久保存、旧电脑级记录不继承、清理一个入口不影响其他入口。
- 相同目标在途读取去重；项目读取失败、写盘失败后可重试；迟到或缓存快照不覆盖恢复记录。
- 导航失败结束旧读取、清除选择，但保留桌面连接；初始页重新选会话恢复读取生命周期。
- 恢复先绑定项目再传入会话，不能把列表当前窗口代替保存目标。

复用既有配对 Chrome，加载工作区前端并连接仅监听本机的测试中继，使用真实原生 Agent：

- Codex 首屏及项目／会话列表读取。
- 无效会话打开失败后，结束导航、回同一 Agent 初始页，无旧内容／伪造运行态。
- 失败后收到新的服务端列表回包，再从列表直接选回会话，读取与监听恢复；该项检查回包，不能仅凭前端缓存判通过。
- Cursor、Devin、Codex 往返，实际读取身份与显示一致，Codex 恢复自己的原项目和会话。
- 正常关闭确认空闲的独立测试项目窗口，按已保存真实路径重新打开，恢复同一会话；实际一次恢复约 10.4 秒。
- 指定已关闭窗口且无项目身份时，明确回初始页，不改选其他窗口。

证据目录：`_shots/entry-recovery-fix-20261028/`。临时脚本一度使用失效窗口 ID／不完整替身，以及测试中继尚未重载的代码；修正后重新验证，保留失败记录，不将其记为产品验证通过。
