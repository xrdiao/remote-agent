# iPhone Duo 专项适配设计与实施方案（仅限 iPhone Duo）

更新日期：2026-10-21。基线：手机网页 v177、现有 iOS WKWebView 壳。

**最高优先级范围：本方案仅为 iPhone Duo 设备及其对应模拟器做专项适配。用户明确普通 iPhone 和 Android 当前表现正常；不得以本方案为由改变它们的现有布局、导航、控件位置、输入行为或性能。iPad、其他折叠设备及非 Duo 浏览器同样不纳入改造。**

**状态：已获授权实施网页 v179 与 iOS Duo 分支，部分模拟器验证通过；完整验收与发布未完成。** 原方案中的目标和验收项不能自动视为通过，实际范围见第13.1、13.2节。用户在实施期间明确要求不要发布，并自行在运行 `npm run public` 的设备重启 relay；本轮不发布、不重启、不提交推送、不上传 TestFlight。

## 1. 目标、依据与范围

### 1.1 适配目标

让 Remote Agent 在 Duo 外屏、内屏、部分折叠和分屏窗口中正确利用空间：正文不被系统状态遮挡，常用操作可以利用系统侧边操作区域，展开/收起保持同一会话与阅读状态，键盘和输入框正常工作。

保留现有 HTML/PWA 聊天、终端和中继架构。仅在已确认的 iPhone Duo 上，由原生壳的 Duo 专用分支负责系统导航工具栏、原生布局信息与网页失效时的刷新入口；网页的 Duo 专用分支继续复用现有业务状态与交互。其他设备完整沿用现有路径。

### 1.2 已有证据及其限制

- 用户提供 2026-10-21 21:45:49、21:45:59、21:47:20、21:48:33 四张 Duo 模拟器截图，覆盖窄屏连接页、展开连接页、窄屏聊天和展开聊天。
- 截图连接页显示 v170；用户已明确确认更新到 v177 后适配表现相同，因此不能把这些问题归结为尚未更新。
- 本轮只读核对了 v177 的布局、输入框和原生壳实现。
- 本机工具链读取结果为 Xcode 27.1（27A9275）、iPhoneOS27.1 SDK；工程最低 iOS 版本为 16.4。
- 未在本轮读取模拟器运行时的 size class、安全区、键盘框或保留区域；未做真机验证。截图不能证明实际命中的 CSS class，也不能证明悬浮按钮拖动后的坐标错误。
- 截图像素尺寸不作为原生 point 或 CSS px 尺寸使用。所有适配尺寸应从当前窗口和内容容器测量，不写死截图分辨率或设备型号。

### 1.3 本方案覆盖与排除

仅覆盖 iPhone Duo 上的连接/配对、聊天、输入框、终端、菜单与预览、侧边操作栏、刷新入口、折叠/旋转/分屏连续性，以及相关发布验证。初期承载环境为可由原生壳可靠确认 Duo 身份的 iOS App 和对应模拟器；独立 Safari/PWA 未具备可靠识别条件时继续使用现有路径，不宣称已获得本专项适配。

不包含 Agent 适配器重构、会话导航重做、原生聊天重写、双 WebView 聊天、Fusion 双会话并排、新增业务能力或实时活动协议改造。不能为了适配而改变桌面窗口选择、工作目录、消息提取、轮询频率或发送语义。

### 1.4 专项隔离是实施前提

1. **先确认设备是 iPhone Duo，再决定它当前如何布局。** Duo 资格判断与 size class、窗口尺寸、键盘和折叠姿态判断分开。
2. Duo 资格必须由原生侧经过核实的设备识别结果提供。具体采用 SDK 正式能力还是已核验的设备标识，实施前确认；本文不虚构 API 或型号标识。不能仅凭宽屏、regular size class、某个安全区值、iOS 版本、UA 或存在某种桥接能力就启用。
3. 无法可靠确认、旧壳未提供信号或当前环境不受支持时，保持现有行为，不猜测设备、不自动套用 Duo 布局。原生壳认定非 Duo 时不建立本专项的工具栏容器或区域观察。
4. 所有新增样式限定于明确的 Duo 根标记，例如 `body.iphoneDuo`；相关媒体查询也必须处于该作用域。该标记由已确认的原生信号控制，不能通过窗口宽度自动产生。
5. 新增布局、输入收起、额度测量、面板定位及原生操作交接均限定于 Duo 分支；非 Duo 仍执行原有 `fitOrientation`、`fitViewport`、`composeCompact` 等路径，不整体替换默认算法。
6. 原生 NavigationStack/工具栏、刷新气泡策略及入口迁移只在 Duo 分支生效。普通 iPhone 上不新增原生栏、不移动现有按钮、不改变气泡的位置或显示逻辑。
7. 共用文件可以承载隔离的 Duo 分支，但不能修改非 Duo 默认样式、阈值、文案、DOM 排列或行为。做不到隔离的修改应留待另行授权，不能以“通用修复”合并实施。
8. Duo 收起后仍是 Duo，不能因没有活动折叠区域就退出专项模式；重新创建 WebView 时重新确认资格，不能把上一份页面信号带到别的设备或普通浏览器。

本文件后续所有“修改”“修复”“迁移”“替换”和阶段完成条件，均受本节的 **仅限 iPhone Duo** 约束。对其他设备的测试只验证现有正常表现保持不变，不构成对它们重新设计或修复的授权。

## 2. 设备特点与官方指导

以下为官方平台行为；后续章节为结合本项目提出的设计选择。

### 2.1 外屏、内屏与当前窗口

Duo 外屏较宽且较矮；外屏竖向使用 compact width / regular height，外屏横向使用 compact width / compact height。内屏提供 regular width / regular height；内屏的布局方向不能单靠应用声明的 interface orientation 推断。分屏窗口还会进一步改变可用空间。[Apple：Prepare your app，2:46–5:01](https://developer.apple.com/videos/play/tech-talks/111461/?time=166)

因此，在通过 Duo 资格判断后，原生侧读取当前 scene/view 的 traits 和 bounds；网页侧读取当前内容容器。size class 表达已确认 Duo 的当前布局能力，不能用来确认 Duo 身份，也不能单独保证某一列一定放得下。

### 2.2 安全区、系统状态与侧边操作区域

外屏以及内屏适合纵向工具栏的配置中，系统状态、灵动岛、导航、工具栏和标签栏共享侧边空间；内屏竖向则可回到横向栏。系统控件的位置跟随当前硬件及窗口环境，左右安全区可能不对称。[Apple：Designing for iPhone Duo，Vertical controls](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo)

侧边区域并非整条都是禁止 App 使用的空白。系统状态本身必须避让，App 可通过标准导航容器把工具操作放在其下方。真机不会自动把网页按钮或其他 App 的普通界面填进空白；是否出现本 App 的操作取决于本 App 的实现。

标准导航容器提供的工具栏才能获得自动纵向排列行为。SwiftUI 使用 NavigationStack / NavigationSplitView 配合 toolbar；UIKit 使用 UINavigationController 等管理工具栏。单独创建 UIToolbar 或在网页里画一列按钮，不等于获得系统自动适配。[Apple：Raise the bar，2:00–3:09](https://developer.apple.com/videos/play/tech-talks/111462/?time=120)

### 2.3 安全区不等于折叠保留区

安全区描述内容应避开的边缘；保留区域描述视图内部可能被占据或分隔的区域。新的 ReservedRegion API 区分遮挡区域 `.occlusion` 与分隔区域 `.division`。区域 frame 使用所查询视图的坐标，包含其 margins；不能重复加 margins，也不能把非活动区域一直当作障碍。[Apple：UIView.ReservedRegion](https://developer.apple.com/documentation/uikit/uiview/reservedregion)

普通背景可以延伸，交互前景需要正确避让。外屏摄像头、灵动岛变化、内屏摄像头启用以及部分折叠，都可能改变区域。[Apple：Prepare your app，6:06–8:08](https://developer.apple.com/videos/play/tech-talks/111461/?time=366)

### 2.4 半折并不要求把所有内容一分为二

Apple 区分连续滚动内容与需要移动的交互元素。文章、文档、列表等连续滚动内容不应仅因折叠而强制搬到另一块区域；操作、弹出层等则应保持可见、易点，并尽量靠近其作用对象。[Apple：Strike a pose，2:26–5:12](https://developer.apple.com/videos/play/tech-talks/111463/?time=146)

本项目因此优先保持同一个聊天滚动容器，仅对输入框、菜单和固定操作区域做必要调整。横向半折的“上方阅读、下方输入”是待验证方案，不是所有半折姿态的固定规则。

## 5. 布局设计

### 5.1 决策输入与优先级

只有通过第1.4节 Duo 资格判断才进入下列顺序；非 Duo 不运行本专项布局决策：

1. 当前内容容器及原生横纵 size class，决定单列或有条件的侧栏。
2. 当前活动保留区域，约束固定交互控件及弹出层。
3. 实际可用宽度，决定标题/额度、工具行、表单是否收紧或换行。
4. 键盘可见范围，约束输入区高度和可滚动空间。
5. 用户的侧栏展开偏好，在当前空间容许范围内应用；临时收起不覆盖持久化偏好。

在 Duo 分支内，不以 `screen.width/height`、整窗方向、UA 或固定折叠角度作为主布局开关。普通手机低矮横屏及其他既有布局规则原样保留，只阻止 Duo regular 布局误入不适合它的分支。

### 5.2 Duo 外屏与 Duo 窄窗口

采用单列：轻量标题/额度、会话条、消息区、输入框。可迁入原生的全局按钮从网页标题行腾出位置；额度和会话文字仍属于聊天内容区。

外屏空间有限时优先保留消息阅读高度和发送入口。标题可省略，额度可使用已有紧凑显示，次要工具可滚动或收纳；完整名称、额度详情和操作仍可访问。不得靠缩小字号或缩小点击目标把所有控件硬塞进一行。

### 5.3 完全展开的内屏

标题、会话、消息、输入框属于同一聊天主列，不采用“左消息、右输入与标题”作为默认布局。

用户最新明确：已确认的 Duo 完全展开后，必须选用既有带左侧可折叠功能栏的 split UI，依据原生 fullyOpen 姿态选择，不改变任何原有 UI 选择阈值。保留现有侧栏收起/展开偏好；收起是图标栏，仍属于侧栏布局。半折、外屏、未知姿态保留既有 Duo 单列路径，画面模式沿用既有专用展示。原生已接管的重复操作仍按原规则去重。

主列内正文和输入框沿用现有阅读宽度约束作为起点；在 Duo 模拟器中测量后调整。不把空出的宽度填成第二个会话，也不让普通段落横跨整个内屏形成过长行。

### 5.4 部分折叠

| 场景 | 默认策略 | 必须验证 |
| --- | --- | --- |
| 纵向分隔，书本式 | 保持聊天滚动连续；输入框及其按钮组完整落在一个可用区域，菜单跟随触发位置避让 | 不把每个消息重新搬列，不丢阅读位置 |
| 横向分隔，桌面式 | 评估消息阅读在上、输入操作在下；依据区域及键盘大小限制输入框 | 最后一条消息可滚到、发送不在折叠区 |
| 完全展开 | 不为非活动折叠区域长期留白 | 恢复自然阅读宽度，不反复切布局 |
| 区域不足以容纳当前卡片 | 卡片内部滚动或在合适区域展示可滚动操作面板 | 所有选项和确认/取消均可到达 |

不能为了避开中央折痕在每条消息中插入空白，也不能复制输入框、创建第二个聊天 DOM 或重新挂载整个列表。若最终采用局部覆盖式输入框，消息区要有对应滚动空间，使被覆盖内容可完整滚入可见区。

### 5.5 分屏、旋转与状态连续性

分屏后按当前窗口能力选择单列/侧栏，不沿用“设备已展开所以一定宽屏”的结论。系统控件可能在窗口另一侧，必须重新读取安全区与工具栏状态。

任何布局变化只更新布局信息和必要样式，不触发 attach、项目选择、模式切换、消息重发或网页刷新。保存并恢复阅读锚点：跟随最新时继续跟随，阅读旧消息时保留原锚点附近位置；不能统一滚到底部。

## 6. 侧边原生操作栏

### 6.1 采用系统管理的工具栏

建议仅在已确认的 Duo 分支中建立管理工具栏的 NavigationStack，继续承载同一个 WKWebView；非 Duo 保留现有 ContentView/WebView/气泡结构。先验证 Duo 结构能获得系统纵向工具栏及正确安全区，不创建新的网页导航栈，不把每次聊天/终端切换做成原生 push。

不手动指定“始终在右边”、宽度或旋转整列图标。系统决定栏的位置、压缩和溢出；每项提供符号、中文/英文标题及无障碍名称。内屏竖向允许系统恢复横向，不强制纵排。

### 6.2 第一批迁移的操作

| 操作 | 建议位置/优先级 | 实现约束 |
| --- | --- | --- |
| 刷新页面 | 原生可达，优先保留 | 直接调用 Shell.refresh，不能依赖网页 JS 响应 |
| 聊天/终端 | 原生模式入口，常用 | 复用现有 setMode 流程，同步选中状态；不直接重复发 mode 请求 |
| 更多操作 | 使用系统溢出菜单承载已迁移入口 | 复用既有设置/文件传输等入口；细节面板仍可用网页，不重写全部设置 |
| 返回/关闭 | 仅在当前面板需要时出现，遵循导航顺序 | 关闭当前已有面板，不随意切会话或退出 App |

第一批不新增原生 Agent 标签栏。是否将现有应用选择入口迁入原生栏，作为后续可选设计另行评估，不能在本轮顺手改变导航层级。

保留在内容区的操作：消息输入和发送、排队/追加/停止/麦克风、附件、输入历史、模型、项目/会话、终端专用输入工具。它们与内容、草稿或当前输入强相关。

Apple 支持图标/标题表示和系统溢出优先级；本项目不需要为了填满侧边而添加按钮。侧边允许保留空白。[Apple：Raise the bar，5:56–14:21](https://developer.apple.com/videos/play/tech-talks/111462/?time=356)

### 6.3 网页与原生入口的展示所有权

- 只有已确认 iPhone Duo 且新原生壳与新网页完成能力确认后，才隐藏已被原生接管的对应网页入口；不是看到 `AgentRemoteApp` 对象就隐藏整组按钮。普通 iPhone 即使更新了壳与网页，也保持原入口及其布局。
- 判断依据是原生实际安装且可工作的能力，不能把“系统偏好纵向边缘”当成“当前已有纵向工具栏”。
- 原生未支持的操作继续在网页显示；独立 PWA、Android 和旧 iOS 壳保留原入口。
- 工具栏成为横向或进入系统溢出，不意味着能力消失，不应因此反复切换网页入口。
- 网页未就绪、断线或失效时，原生刷新仍工作；会话相关操作按真实可用状态禁用。恢复就绪后重新同步，不重放之前点击。
- 原生模式按钮使用明确目标 chat/terminal，不能模拟窄屏“再次点当前按钮切到另一模式”的叠放按钮语义。

### 6.4 刷新气泡的过渡与保留

仅在 Duo 上，在原生工具栏刷新尚未验证前，先修 Duo 气泡的安全区约束，不直接删除救援入口。确认刷新在冷启动、JS 卡住、网页进程退出和断网场景都可由原生触发后，才在已接管的 Duo 环境隐藏气泡。普通 iPhone 的气泡完全沿用当前实现，不应用本节定位或显示策略。

仍需保留气泡的 Duo 环境使用当前安全可用矩形计算贴边和拖动范围，避开活动遮挡/分隔区；折叠/旋转时重新约束保存位置。收起时部分露出是现有设计，不应仅凭截图把它当作裁切故障。

刷新继续只清 HTTP 磁盘/内存缓存并重建 WebView，不清 Cookie、localStorage、配对和 Service Worker。不因适配擅自改变刷新确认或草稿保存行为；先核对既有刷新行为，再保留其语义。

## 7. 原生布局信息与网页接口

### 7.1 能力来源

原生先可靠确认当前设备为 iPhone Duo，再从当前 WebView/容器的布局、safeAreaInsets、traits 和保留区域获取信息，延续现有 `AgentRemoteApp` 桥接。Duo 专项模块以资格信号及运行时可用性双重约束；普通 iPhone 不启用该模块。保留 iOS 16.4 最低版本，不通过提升最低版本规避旧设备支持。

采用当前 Xcode 27.1 SDK 编译后，仍需实际核对签名产物和运行效果。新工具链存在不代表已有安装包已经采用新 SDK 或已经适配。

独立网页不依赖 Duo 特定浏览器实验开关。Duo 的独立 Safari/PWA 支持需要另行确认可靠的设备识别与启用条件，在此之前保留现有路径。不能仅因浏览器提供折叠 API 就把 Android 折叠设备或其他环境纳入本方案。

### 7.2 建议的数据契约

下表是待实现的最小契约，不是现有 API。具体命名在实施时结合已有桥接统一，数据仅在原生壳与当前网页之间传递，不增加中继 WebSocket 消息。

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| version | 本地桥接数据版本 | 旧网页忽略不认识的能力 |
| duoEligible | 原生确认当前设备属于本专项的 iPhone Duo 资格信号 | 必须基于可靠设备识别；缺失、false或无法核实时保持原路径，具体名称待实施 |
| revision / documentGeneration | 当前布局序号与网页生命周期标记 | 旧 WebView 的迟到结果不能覆盖新页面 |
| bounds | 当前 WebView 的实际非零尺寸 | 不是 UIScreen 主屏尺寸 |
| sizeClasses | 当前 horizontal / vertical traits | 不等同于设备型号 |
| safeInsets | 相对当前 WebView 的四边剩余安全区 | 不包括已被父容器排除的同一块区域 |
| reservedRegions | region ID、kind、frame、isActive | 查询后明确过滤活动区域，保留稳定标识 |
| nativeActions | 已安装的原生操作及支持状态 | 用于逐项交接网页入口 |

设备资格、侧边栏状态和布局数据需要区分。先确认 duoEligible，之后才消费 Duo 布局及动作能力；系统 preferred edge 只是布局信息，不能替代设备资格或 nativeActions 的能力确认。

网页另行维护现有的 mode、连接状态、当前面板及可用操作；只在这些状态变化时向原生更新最小摘要。不把聊天正文、文件内容、录音或输入草稿放进布局桥接。

### 7.3 坐标与安全区的单一归属

1. 原生 region 先转换到 WebView 本地坐标，并与其 bounds 求交；不得把 screen 坐标直接发给网页。
2. 原生 point 与 CSS px 的换算按实际 WebView/布局 viewport 映射核对，不能再除一次 devicePixelRatio。键盘缩小 visualViewport 不应被误当成页面缩放。
3. 网页保留自己的 visualViewport offset 与滚动坐标处理；不能把其偏移重复叠加到原生 frame。
4. WebView 若已经被原生父容器限制在安全内容区，网页不能再减父容器已经去掉的那一段。反之，WebView 铺满时，网页必须处理其剩余安全区。
5. 每个前景容器只应用一份有效安全区：CSS env 与经核对的原生布局值二选一作为来源，不把两者相加。
6. region.frame 已包含 margins，不重复扩张同一份区域。
7. 背景可铺满；聊天、固定遮罩、原生工具栏分别明确边界所有者，不能依赖 body padding 自动约束所有 fixed 元素。

现有 `.never` 用来避免 WKWebView 自动 inset 与网页高度叠加造成底部空白，第一阶段保留。后续加入原生导航容器时，要以实际 WebView bounds、安全区与页面 env 值验证整条链路，不简单切回 `.automatic`。

### 7.4 更新时机与性能

- 仅在已确认 Duo 的页面初次就绪时提供最新专项布局快照；非 Duo 不订阅本专项的区域/铰链观察，不进行其布局测量和JS回调。零尺寸不是有效的布局依据，保持现有避免首次零宽度导致输入框异常的处理目的。
- 响应容器尺寸、safe area、trait、系统栏及活动保留区域变化；仅监听 resize 不足以覆盖所有内部区域变化。
- 保留区域在参与布局的视图中查询，并通过当前 SDK 支持的观察/布局生命周期更新。若需铰链变化通知，只用它触发重新查询，不以角度推算区域。[Apple DTS：区域变化观察](https://developer.apple.com/forums/thread/847876)
- 原生合并同一布局周期内的更新；网页在同一绘制帧内应用一次。没有变化不重发，不增加常驻计时轮询。
- 布局更新不进入 Agent 命令队列，不调用 CDP，不重新读取历史、目录或额度。
- 对来自网页的操作沿用现有主 frame 和受信来源检查，仅允许声明过的动作；不增加任意 JS/原生命令执行接口。

## 8. 仅限 Duo 的网页各页面修改要求

本节所有要求仅在 Duo 专用根标记及脚本分支内生效。即使调整代码位于共用文件，也不得改动非 Duo 的默认选择器、断点、DOM 排列、文案及交互。连接页重叠等问题在本方案中同样只为 Duo 修复，不扩展为全设备通用改造。

### 8.1 连接页

- `#conn` 四边前景边距分别处理安全区；标题和“切换电脑”不能进入系统状态区。
- 增加连接内容包装层，限制展开时的内容宽度并在安全内容区居中；外层背景继续铺满。
- 标题使用简短状态摘要，详细错误保留在对应 Agent 行；保留查看原因、启动和部分可用时进入等行为。
- 窄屏减少过大的区块留白，错误文字正常换行，操作不被挤出点击范围。
- 两主按钮容许并排；实际空间不足或大字体时纵排。偏好项宽度充足时并排，不足时纵排。
- 版本号进入正常文档流，位于偏好项之后，彻底消除与开关重叠的定位条件。
- 连接页作为一个整体滚动，最后一项可到达；不增加没有必要的卡片内嵌滚动。

### 8.2 聊天标题、会话条与额度

- 以聊天列的实际宽度计算标题和额度是否放得下，不能仅用 menuBtn.right ≤ window.innerWidth 判断。
- 保留已有紧凑环形额度与详情入口；不改变“上下文已用”和“账号剩余”的统计口径。
- 会话条仅在当前主列内横向滚动，长标题省略；关闭按钮和当前会话状态可操作。
- 原生操作接管后去掉对应网页控件的布局占位，不能留下空白按钮区。

### 8.3 输入框、键盘与状态栏

- 复用 composeCompact 与原有草稿/附件逻辑；以实际可用阅读高度修订收起条件，避免整窗高宽比误判。
- 正在编辑、有正文/附件、录音、Question 回答、失败待重试等状态不因折叠强制收起。
- 宽度收紧以输入框容器为准；工具行先滚动或收纳，发送及当前必要的停止/麦克风保持可达。
- 附件缩略图、上传状态、引用列表和输入历史不重置；不通过清空草稿换取矮输入框。
- 保留 fitViewport 对 iOS 焦点滚动的修正，区分窗口重排、键盘遮挡和页面缩放。折叠引起 resize 不等于键盘弹出。
- 键盘期间排队栏临时隐藏、收起恢复的既定行为保持；不清空排队数据。
- 输入框 max-height 根据当前可用区域及键盘可见范围计算；底部安全区、键盘高度和原生栏不能重复扣除。
- 浮动/拆分键盘、硬件键盘及中文候选栏加入验证，不能仅靠“viewport 高度减少超过阈值”宣称全部支持。

### 8.4 菜单、预览与其他页面

| 页面/元素 | 修改要求 |
| --- | --- |
| 网页配对 gate、扫码 scanner | 四边安全区、外屏短高度、按钮与输入可到达 |
| 壳内 setup.html | 仅由已确认 Duo 的原生信号启用专项样式/逻辑；非 Duo iOS 和 Android 的共用默认页面完全保持 |
| 设置 sheet、模型/项目列表 | 面板受安全可用区域约束；长列表独立滚动，返回和当前项可见 |
| Question / 执行审批 | 输入、所有选项和提交可达；折叠不触发选项、不自动提交 |
| 文件预览与 Editor | 长路径、代码横向滚动、返回与编辑工具正常；不强行断开路径语义 |
| 文件传输 | 上一级/路径吸顶、列表滚动和底部主操作保持；不改变两个独立目录 |
| 图片编辑 | 当前裁剪/标注/缩放状态保持，工具条避让，文字输入正常 |
| 视频、画面页 | 视觉内容可以延展；播放/缩放/返回等交互避让；关闭仍停止加载 |
| 原生扫码、系统文件选择器及弹窗 | 优先让系统 presentation 适配，不额外叠加同样的安全区 |

不是所有自定义网页面板都要迁成原生 sheet。本次优先修好既有实现的定位、尺寸和滚动；不能把 Apple 原生面板的自动适配效果直接当成 HTML 已获得的能力。

### 8.5 终端

终端输出、输入及操作栏同属于当前终端主列。折叠和旋转保持选区及滚动意图，内容重排不执行或补发命令。保留复制/全选、Ctrl+C、Tab、新建/列表、历史和换行入口。

模式入口迁入原生后仍通过原 setMode 调用既有保存/恢复草稿和服务端 mode 流程。不能同时模拟按钮点击并额外调用 setMode，造成重复切换。

## 11. 验证计划与验收标准

### 11.1 记录格式与测试隔离

产物统一放 `_shots/iphone-duo/`，不提交截图、配对数据或令牌。按日期/阶段记录网页版本、iOS壳版本/构建号、SDK、模拟器runtime、姿态、语言、主题、键盘状态、bounds、size class、安全区和活动区域。

先做只读及独立配对浏览器验证，再在 Duo 模拟器实际操作。需要发送、切会话、改模型、执行终端命令或跑 Fusion 时，使用独立测试项目/会话并取得相应授权，不拿工作中的真实会话做测试。临时配对按精确新增设备ID清理，保留原设备与凭据。

### 11.2 Duo专项验收与非Duo不变性矩阵

Duo行是新增适配目标；非Duo行仅用来证明现有正常表现不变，不是新增适配或界面调整目标。

| 场景 | 必测内容 |
| --- | --- |
| Duo 外屏竖向、横向 | 连接、聊天、工具栏、输入、菜单；左右边界均核对 |
| Duo 内屏宽窗口、窄高窗口 | 主列/侧栏和原生工具栏变化，不依赖 orientation 判断 |
| Duo 纵向半折、横向半折 | 输入、弹出菜单、Question/审批、文件预览避让 |
| Duo 左右分屏及连续调整宽度 | 不同侧的系统栏、安全区和紧凑布局 |

### 11.5 明确的通过条件

1. 正文前景和交互目标不与活动系统遮挡区相交；连接页标题、“切换电脑”及所有偏好项可读可点。

3. 完全展开聊天没有“左消息/右输入”的非预期分离；正文与输入同属主列，宽度变化不产生两份聊天。
4. 所有必需操作均可直接访问或从系统溢出访问；没有依赖网页JS的唯一原生刷新入口。
5. 一次原生点击只产生一次既有业务动作；布局变化产生0次发送/停止/模式切换/attach请求。
6. 折叠后当前电脑、应用、项目、会话、mode、草稿、引用、附件、Question回答和展开状态保持。
7. 自动跟随状态保持；阅读历史时以相同消息内锚点衡量连续性，不因正常换行高度变化错误地要求绝对scrollTop不变。异常跳动需单独记录修复。
8. 键盘期间输入、发送及当前必要控件可达；收起后无遗留空白、transform或错误kb标记。
9. 普通iPhone、iPad、Android、其他折叠设备及非Duo浏览器不进入专项分支，原有布局、按钮位置、字号/间距、气泡、输入和交互与实施前基线一致，不增加专项区域观察及测量。仅证明“入口未消失”不足以通过；任何现有正常表现或性能改变都视为本专项未通过。
10. 所有声明通过的姿态均有实际操作记录。模拟器通过不等于实体手机通过；真机缺失时明确列为未验证。
11. Duo原生识别在外屏、完全展开、半折、分屏和WebView重建后均正确；普通iPhone横屏、iPad宽窗口、Android折叠屏和宽浏览器窗口均不得被误判。资格不成立或未知时必须保持原路径。
12. 新旧原生/网页混用时安全区不重复扣除，能力不足的入口不隐藏；只有Duo资格与对应操作接管都确认后才启用专项入口变化。
