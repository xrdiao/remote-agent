# 07 Fusion：主 Agent 与任务编排

[功能基准索引](README.md) · 新版契约：2026-11-01。实现与验收证据见 [Fusion 方案及进度](../fusion-multi-agent-plan-20261101.md)。本文件描述应有行为，不表示所有原生或手机场景已经通过。

## 入口与归属

主页底部统一为“概览｜项目｜收藏｜Fusion”，横竖屏顺序与入口一致。顶部及横屏软件列表提供 Cursor、Devin、Codex；RA Fusion 保留内部虚拟目标身份与历史 run attach 路由。Devin 原生 Fusion 模型模式独立保留。

Fusion 工作区复用主页电脑范围。单电脑只操作该电脑的 run；全部电脑分组展示，新建前明确执行电脑。点击导航只切换视图和读取状态，不创建原生会话或发送任务。进入 run 后返回 Fusion 页，恢复原电脑范围。切换其他导航或会话保留草稿及后台任务。

Fusion 新建 run 复用已有打开项目、浏览目录、新建项目和原生信任确认流程。主 Agent 可以选择同项目的普通原生会话，也可以显式新建主会话；读取模型使用已选主会话，不要求创建 Fusion 专用主窗口。主会话继续显示在普通概览、项目和收藏中；子 Agent 的专用窗口与 Binding 会话仅在 Fusion 展示，原生历史和收藏记录保留。

主对话顶栏分两行：返回、Fusion 标题、项目／电脑和通用导航在上行，主 Agent／模型、配置和任务入口在下行。窄屏仅截断过长模型名称，完整名称可在配置中查看；横竖屏保留相同入口。

用户配置项目、主软件、主模型及思考强度、成本偏好。均衡为默认，省钱／均衡／性能只表达成本、时间、质量取舍，不限制模型或强度，不替换用户所选主模型。

## 编排与授权

用户始终与主 Agent 对话。主 Agent 自行执行，或分批派出 B1…Bn；独立子任务各用原生会话。没有固定子任务数量或评审轮数，允许零子 Agent。结果由主 Agent 验收、补做、继续派工或交付。

沿用用户授权及项目 AGENTS.md。需要确认的方案先展示具体范围、步骤、完成标准并等待确认，确认绑定具体计划；范围内常规分工不重复请示。原生信任、问题、权限审批保持原义，并绑定实际 Task／Attempt／Binding。

主 Agent 通过本次已完成原生回复中的一个 `fusion-control` JSON 块控制编排。动作包括 `plan`、`dispatch`、`continue_task`、`review`、`self_execute`、`wait`、`ask_user`、`cancel_task`、`finish`。Runner 生成 decisionId，记录 runId、实际会话与原生轮次；历史、思考、子任务控制文本及重复回执不产生派工。解析与字段错误显示具体原因，不猜测动作或自动重试。

用户消息、子任务结果、配置、原生操作和错误按事件归属保存。主 Agent 一次处理一个决策轮次，集中消费已到事件；无事件不调用模型。

## 原生资源与任务事实

| 对象 | 行为约定 |
|---|---|
| Run | 保存电脑／入口归属、主配置、授权、完成标准、事件、任务与历史 |
| Task | 保存目标、依赖、输入、允许范围、读写属性和验收条件 |
| Attempt | 配置变化或重新执行新增记录，保留提交、原生接受、生成结束、结果及验收事实 |
| Binding | 对应明确软件、host、项目、窗口和原生会话；主会话归普通流程，子会话归专用窗口 |
| 软件槽位 | relay 内每软件一个，跨项目排队；不同软件可并行；主决策结束后释放再调度同软件子任务 |
| 专用窗口 | 仅用于子 Agent，按电脑、软件、host、真实目录登记；同键并发创建合并，与普通主会话窗口分开 |
| 项目写占用 | 同项目一次一个写任务；独立只读可并行，依赖写结果的读取／验证等待依赖验收 |

用户明确选为主 Agent 的普通会话承接 Fusion 决策与主 Agent 执行，使用用户配置的模型和强度；选择、新建及信任确认复用既有项目流程。其他普通窗口及会话的项目、模型、草稿和运行任务保持原状。为新主会话选择窗口时保留普通草稿，不能借用子 Agent 专用窗口。`owned=true` 或项目相同不足以认定子窗口归属。主窗口被手动切换项目、切到无关会话或留下草稿时记录变化并阻塞，不清空或强行切回。

使用用户选定工作区，不自动创建 worktree 或合并。执行前记录已有 Git 改动及指定文件状态，验收区分旧改动与本轮成果。子任务需要进一步分工时向主 Agent 提议，不递归创建 RA 子 Agent，也不主动启动原生多 Agent 扇出。

## 成本与结果

派工依据本次原生可用候选，保存自己执行与委派的总成本比较，计入规划、评审、上下文传递和返工，并保存来源、单位、读取时间与选择理由。金额未知保留未知；Free、倍率、套餐额度保留原单位，Cursor Auto 保留原名，不用 API 单价推算桌面订阅费用。

执行后记录可读用量、耗时、返工与来源。账号用量属于账号，不能算作单任务精确费用。只有用户明确设置的预算构成预算边界；无法用原生资料核对时说明限制并请求决定。

原生结束后收集结果、释放本次观察与租约，结果交主 Agent 评审。已验收且不再继续的子会话仅使用真实原生归档；无归档能力如实保留会话，窗口可以独立回收。

决策、归档和执行退场，以及确认停止后，主动通知现有扫描器检查子 Agent 专用窗口。占用按实际 Binding、整窗及全部 run 判断：子任务排队／运行／结果未知、待评审或归档尚未结束时保留复用；同软件同项目的普通主会话不会占住空闲子窗口。主会话不自动归档，不属于 Fusion 子窗口回收范围；运行中的主会话仍持有实际窗口占用。已停止 run 的已知结果不继续占子窗口。事件触发与定时检查都使用同一软件槽位，不增加第二个回收定时器。

真正空闲的 Fusion 窗口立即检查回收，不等待普通窗口的空闲时长，也不因它是最后一个可用窗口而永久保留。普通窗口原有回收规则及设置不变。原生前台使用、真实草稿／未保存内容、后台命令、用户保留／归属变化及同软件同项目收藏仍阻止关闭，归档收藏同样有效。关闭须确认 target 消失；如果调试端口随最后一个窗口退出，则核对原生进程已退出，不能仅凭断线报告关闭。

回收后再次执行已确认的新 Attempt，可重开同项目专用窗口、关联原生会话并建立新 Binding，保留旧 Binding 事实。只有 Fusion 冷启动使用现有项目打开器的调试端口参数，普通调用不变。新建 Cursor 窗口等待原生模型控件就绪；未知原生执行仍走原 Binding 核对，不通过重建窗口自动重发。

## 停止、恢复与交付

停止由 relay 直接处理：停止新派工、取消未提交队列，仅停止本 run 的实际目标。未确认原生停止时保持 stopping。手机切页、退出和断线不停止 Runner。

relay 启动后对未结束执行进入 recovering，核对原生会话与轮次；仍运行则观察，已结束则收集，仅确认未提交的执行可提交，未知则 blocked，不自动重发。

finish 必须逐项关联完成标准与证据，且没有未验收的必需任务、未处理的新事件或结果未知的原生执行。超时、失联、额度不足和用户停止不等于完成。新版历史保留 Task／Attempt／Binding 及真实结果，继续 run 不覆盖旧事实。

旧 Fusion 元数据在切换初始化时备份并一次性删除；不迁移旧历史，不保留旧引擎或协议。其他 relay 状态、原生历史、收藏、项目映射和普通窗口不属于清理范围。
