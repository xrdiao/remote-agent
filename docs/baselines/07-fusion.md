# 07 Fusion 协作

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

Fusion 是独立的双 Agent 协作入口：A 生成方案与评审，用户确认后由 B 执行，再由 A 检查完成标准，必要时小修或退回 B。它与 Devin 自带的 Fusion 模型模式不是同一功能。

## 配置与正常流程

1. 选择实际项目目录，处理原生工作区信任；项目身份包括真实目录和主机信息。
2. 选择 A 和 B 的 Agent、窗口、会话与各自模型／强度；只把项目已经确认的会话作为直接候选。
3. A/B 可以来自同一软件或同一会话，但原生操作仍按阶段顺序执行；不同时占用同一输入框互相覆盖。
4. 需要续接其他项目背景时，按既有入口创建当前项目的新会话并携带历史摘录，原会话保留，执行目录仍为所选项目。
5. 用户提交任务，A 生成含范围、步骤、约束和可核对完成标准的方案，展示后等待用户确认。
6. 用户确认执行方案，B 实际执行并反馈变更、验证及未完成事项；展示本轮进度和相关差异。
7. A 按方案、结果及执行前后差异评审，完成、小修或退回；不能把执行前已有改动算成本轮成果。
8. 完成、用户停止、错误或轮次上限后明确结束当前阶段，保留历史与实际结果。

## 运行行为

| 场景 | 行为约定 |
|---|---|
| 开始条件 | 项目、双方会话和模型已选且一致；原生登录、信任、账号及审批仍有效 |
| 输入归属 | 不覆盖原生已有草稿，不把执行指令发到其他项目／会话 |
| 作业归属 | 同一个 Fusion 会话一次只有一个实际作业；多入口／标签页不能重复开始同一轮 |
| 原生回复 | 识别本次发送对应的回复与完成状态，不拿上轮回复或 DOM 当前可见范围代替完整原生记录 |
| 方案确认 | A 规划后等待确认，确认前不自行进入 B 的修改执行 |
| 检查决定 | 完成／小修／退回按当前检查阶段执行；阶段已变的旧按钮不改新作业 |
| 小修与退回 | 保留原任务范围、完成标准和已完成成果；错误要结束本次等待并反馈可操作状态 |
| 轮次上限 | 保留当前最多 4 轮执行的既有上限及停止反馈 |
| 进度 | 展示对应阶段、A/B 来源及任务结果；展示更新不等于新阶段或再次提交 |
| 差异 | 属于当前项目及本轮，能区分已有改动和新改动 |
| 额度／模型 | 分别按双方原生账号、模型和会话读取；不能把接近用量上限等同于明确耗尽 |

## 停止、断线和历史

- 用户停止后不再进入后续阶段，按当前正在执行的 Fusion 目标停止原生调用，不停止无关 Agent／终端任务。
- 手机切换页面、关闭或断线与“停止 Fusion”不同；独立 Runner 继续按已有运行机制管理，重连能读取所属会话进度。
- 异常、取消和结束都需要当前作业的最终状态；旧作业结束回调不能清掉新作业。
- 流式展示和保存的历史均归属该 Fusion 会话。保存记录可恢复查看，但中继重启后的记录不表示原生任务已经自动恢复或可以重复发送。
- 历史选择、创建新 Fusion 会话和当前运行状态分开处理；未知原生执行结果须核对，不自动重做文件修改。

## 回归场景

| 操作 | 观察结果 |
|---|---|
| 选项目、双方软件／会话／模型，含同一软件和同一会话 | 项目与目标明确，原生能力正确，阶段顺序执行 |
| 新目录信任、登录未完成、原生有草稿 | 如实等待用户处理，不覆盖或误发 |
| 提交任务，查看 A 方案，再确认 B 执行 | 确认前不执行，B 有实际结果，A 评审对应本轮 |
| 完成、小修、退回，达到上限或原生失败 | 阶段、反馈及恢复入口明确，不永久停在无作业的进行中 |
| 桌面滚动到旧内容、目标回复未挂载 | 仍读取本轮完整原生回复，不能只等当前 DOM |
| 两个标签页同时开始／停止，旧回调晚到 | 不重复实际作业，旧结果不改新作业 |
| 执行中切页面／断线再返回，查看历史 | 运行语义保持，所属进度可见，不自动重复发指令 |
| 执行中用户停止，随后观察原生与下一阶段 | 当前任务按语义停止，不继续下一阶段，无关任务保留 |
| 查看执行前后差异和双方额度 | 来源及阶段正确，不把旧改动或另一账号数据算进来 |
