# 07 Fusion：持续主 Agent 与后台子 Agent

[基准索引](README.md) · 2026-11-05 新契约，替代旧 run 与专用子窗口流程。实施、切换和验证边界见 [Super Agent 方案](../fusion-super-agent-20261105.md)。本文件描述应有行为，不表示真机验收已通过。

## 入口与主会话

底部“概览｜项目｜收藏｜Fusion”横竖屏一致，共用电脑范围；全部电脑不静默挑选执行电脑。点击导航仅读取状态，进入后返回 Fusion 并恢复电脑范围。切页、普通会话切换与手机断线保留草稿及后台 Runner。

工作台长期管理多个工作项。项目选择／新建／信任复用现有流程；主项目有窗口则复用，没有则按普通项目流程打开。当前单会话工具主控为 Codex；Cursor、Devin 的主控接入未经同等隔离验证，不宣称可用。

主 Agent 使用完整普通原生会话功能，模型及思考强度由用户选择。Fusion 在主对话旁提供设置及任务关系。工作台文字收件箱可交办新需求、补充具体工作／任务、回答问题；登记回执不等于原生接受。只读查看任务板不切换桌面会话。

主对话是主控提问、回答及方案确认的统一入口：卡片显示工具登记的原文，关联实际主轮次与questionId／planId。控制台只提供待处理状态和定位，不再显示另一份问题表单；原生审批和原生问卷保留原目标。主控使用ask_user登记完整问题，普通回复不另写一份不同提问。紧接唯一提问轮次的实际原生用户回复可按已接受轮次关联；多个候选、其他会话或事件唤醒不推测回答目标。回复已收到不等于方案已确认，方案按钮保留独立语义；草稿、选择和焦点在状态刷新时保留。

启用Fusion即按工作台约定授权主Agent自主组织需求：决定自做或派工、子Agent软件／模型／强度、依赖、验收补做及交付，无需用户点名子Agent或逐项批准分工。零子任务仍允许，用户本轮的明确限制、项目AGENTS.md要求及原生权限审批继续适用。授权事实随该主Binding的原生turn/start及turn/steer请求进入additionalContext，保留用户正文、附件、草稿、消息身份和原生设置；同客户端其他会话及子会话保持原请求。启用、查看和安装绑定本身不发送业务任务，已有主会话下一次正常请求沿用该规则。

## 打开、详情与证据读取

已启用的工作台点击后直接走普通会话的既有导航链路，按实际主绑定确认 Codex 窗口、原生 thread 和工作台身份，不先等待完整工作台数据。未启用的工作台只读取配置。异步配置、任务和审计回复只属于发起它的视图，切走后不能重新弹出或抢占后来选择。

历史主会话在当前项目窗口中确认新鲜首屏后，同步当前 Fusion 主绑定的窗口位置；核对软件、原生 thread、真实目录及 host，缓存、未就绪或已切走的读取不登记。历史子会话正文沿已有项目窗口定位能力，读取其原生 thread，不依赖旧桌面窗口仍存在。位置更新和历史查看不改变原有 Attempt、待处理事件或停止状态，也不继续派工；执行与停止仍核对实际原生轮次。

工作台列表及主对话头部使用摘要；主绑定确认的 attached 携带必要关联，原生主聊天不附带整份工作台。配置、工作／任务列表、选中任务、输入问题分别按用途读取，不把全部事件、历史正文、大差异和每次 Attempt 重复的实时正文放入默认状态。

选中任务的正文与历史沿用 fusionContent 分页；真实审批／问卷从未结束的最新执行投影到主对话，按原Binding／Attempt／原生请求身份处理；子详情不展示原生操作，复制／Fork不作为审批。展开具体执行记录、评审或交付证据才读取完整数据，结果、基线、差异及证据不截断、不删除。主对话中的Fusion原生请求使用自己的目标标记，操作只发送给所属执行绑定，不自动批准或转成另一份主控问题。

详细状态只订阅正在查看的视图，关闭或切换后释放，保留摘要；连接恢复时仅恢复仍在查看的视图。更新详情时保留输入、选择、焦点、光标、审计展开项及滚动位置。Runner、派工、成本、模型、停止／恢复与持久化格式保持原语义。

## 界面与按需展示

Fusion 主页按所选电脑范围分组，复用概览卡片、状态色与底部导航；统计和待处理事项汇总所选范围，待处理胶囊标明电脑。离线电脑默认折叠，仍可展开查看缓存摘要。正在执行的工作台使用宽卡，需要处理的工作台标出橙色边框；任务验收数与分段进度来自真实摘要，不以原生接受或生成结束代替验收。

主对话标题显示工作台名称，副标题显示主会话模型、强度和成本档位，模型显示值已包含强度时不再追加。上下文和额度放在标题右侧，复用 Cursor 的圆环与数字，保留原有口径、辅助说明和点击详情。工作台设置统一位于“…”菜单，关联当前电脑与工作台；输入区原生模型选择功能保留。手机竖屏显示可横向滚动的任务条，按真实最近活动倒序排列，首次进入显示最左侧最近任务，状态刷新保留手动横向浏览位置；打开关系面板时对话变暗。电脑仅在现有 `body.split` 布局中沿用左侧栏，并增加可收起的关系右栏，任务详情也在右栏展示；中间聊天保留原节点、输入和滚动。手机横屏不采用电脑右栏。

任务条的滚动标识与真实computer／run归属分开，点击仅读取实际所属工作台。关系中的每个子Agent按最近负责任务的目标显示名称，软件／模型为次行；节点默认折叠，展开查看全部任务和依赖，明确定位某任务时展开其所属节点。刷新使用Worker身份保留展开状态，不因职责标题变化重置。子原生审批／问卷仍在主对话处理，交互详情默认折叠，待处理标识保持可见；展开不额外读取子会话正文，刷新保留选项、草稿和焦点。

主对话不常驻显示“等待新事件”等普通状态。实际阻塞、停止或停止待确认时使用紧凑提示卡，原因可展开，动作沿既有工作台归属提交；当前读取失败继续提供错误与重试入口。恢复按既有核对流程成功从recovering转waiting时清理已解除的blockedReason，历史Attempt的中断、失败及证据保留，未确认执行不重发。

关系树按真实 Worker 展示分工、状态和依赖，保留历史主控执行记录。主控的新自做工作直接使用其原生轮次，不创建自派Task。聊天里的派工卡按已登记命令与原生工具／用户轮次身份关联，不从回复文字猜测派工，也不把未知历史轮次插到其他消息下。Fusion 图标统一为一个实心主节点向下分出三个空心子节点，使用现有软件 logo 表示各 Agent。

主页、任务条、关系树和任务详情首屏只使用展示摘要，不读取子会话正文。详情首屏包含进展、更新时间、可用文件变化数、耗时和接受回执；真正待处理的原生交互统一在主对话展示，来自已有fusionLive，不读取子会话正文。没有可靠记录时标明未提供。目录快照缺少逐文件哈希时不猜文件数，执行前已有改动不计为本轮成果。

“派工 → 执行 → 验收 → 交付”是已有事实的展示，不增加执行阶段或结束规则。“子 Agent 对话”展开后才使用 `fusionContent`，保留加载更早内容；任务输入通过 `fusionRead.inputs` 显式读取，评审与执行记录沿用审计读取。关闭、切换与旋转复用同一视图归属和释放规则，刷新保留表单、焦点、光标、展开项及滚动位置。

## 主控与持久任务

原生单会话 `ra_fusion` 工具是唯一管理入口；真实主 thread／turn／request ID 与 Runner decisionId 关联。请求 ID `0` 正常处理，重复命令不重复派工。子回复、历史、思考和文本 `fusion-control` 不执行。

Controller、WorkItem、Task、Worker、Assignment、Attempt、Binding、输入／事件／效果分别保存。一个主控管理多项工作；简单问题零子任务，复杂工作按依赖分批派工，无固定数量和轮数。项目 AGENTS.md 要求确认时展示具体范围和标准，确认后才派工；已授权范围内分工不逐个请示。

主控验收真实结果，补做新增 Attempt 并保留原执行归属：子任务续接原子会话，主控自做直接关联当前主轮次与工作项，plan.input登记mainScope和成本选择；每个真实主轮次保留其范围基线、观测差异和证据，不创建自派Task或子Worker。交付逐项关联完成标准与证据；必需任务、未处理新输入和未知执行均须核对，主控实际轮次完成后才确认工作项交付。完成工作项不关闭主工作台。

plan登记范围、完成标准和主控自做范围／成本，dispatch才登记及派发子任务；各动作必填字段通过read_workspace统一提供。review的顶层attemptId就是本次逐项证据的实际来源，无需在每一项重复；finish仍逐项关联来源Attempt，本轮主控交付证据才使用main-turn引用。历史读取使用所选Attempt的Binding，不随Worker后续配置改变来源。

主控管理变更复用原生会话订阅的轻量通知，读取原生轮次与工具请求，不等待80条正文；普通会话仍沿用原快照订阅。主控唤醒通知只携带数量和本次输入标识，正文通过 `read_workspace` 完整读取；以原生工具回复成功确认事件已读，生成结束不代替确认。未读完本次事件时保留原文并阻塞等待核对，不反复调用模型。工作台返回任务与能力摘要，具体任务及证据用 `read_task`，完整原生候选、价格和额度用 `list_models`；读取不改变保存的事实。

子请求只携带当前目标、项目、授权范围、读写属性、验收、本次派工说明、新补充及最近的补做要求。依赖只带任务身份和状态，主 Agent 在派工说明中提供必需的上游结论与文件路径；子 Agent 不被要求调用主控工具。历史评审、整份方案及依赖完整报告不反复附送，完整用户原文与执行证据继续保留。新格式适用于后续请求，已有原生会话历史及已提交 Attempt 的提示不重写。

## 后台执行与普通会话隔离

同软件 Worker 使用主窗口中的独立原生会话；跨软件复用该软件已打开的窗口，不创建子窗口。通过明确 app／host／目录／thread 的原生管理器读写和订阅，不借当前可见对话的 DOM 代替后台事实。普通项目、草稿、模型、权限、队列、会话和监听均保持原功能。

普通窗口由用户切到其他会话时，普通发送仍按原规则拒绝；Runner 不强行切回。后台任务只操作自己的绑定与实际原生轮次。主 Agent 按输入产出、文件、命令和共享资源判断依赖与冲突，用 `dependsOn` 或分批派工决定串并行；relay 不按软件、项目或读写类型强制互斥。同软件、同项目的独立写任务可并行，不同软件有依赖也必须顺序执行。截图验收后再修改依赖截图的 README；两个互不冲突的功能可以并行实现，后续集成和验证依赖对应任务验收。主控自己执行同样遵守其登记依赖。

同一工作台的主控决策保持顺序，同一任务未结束或原生结果未知时不能重复提交；未知执行只保留在其任务与 Attempt，不占用全软件或全项目。当前策略通过 `read_workspace` 告知历史主会话。记录执行前已有改动和本任务的负责范围，原有及其他并行任务的改动不算本次成果，不创建 worktree 或自动合并。

Worker是可复用的原生子会话，不与单一Task绑定。新任务派工时，主控通过dispatch.input逐项明确选择已有Worker或新建及理由，比较已有上下文、自做和新建的总开销；主模型不作为子模型的默认继承规则。复用核对软件、host及实际项目，任务、Assignment和Attempt分别保留。一个Worker同一时刻执行一个原生轮次，多项任务依次排队；不同Worker仍按主控依赖并行，未知结果阻塞该Worker的新提交。

子 Agent 和原生会话持续保留，不自动归档、删除、隐藏或关闭。每次原生生成结束释放该次监听和连接，不影响同窗口其他任务；后续相同任务可重新调用原子会话。共享窗口继续使用原有普通空闲扫描与收藏关联规则，没有专用 Fusion 回收流程。

## 成本、停止与恢复

均衡默认，三档只表达取舍，不限制模型或强度。自做成本记录于方案，显式预算累计计入已确认主控方案和子任务Assignment。成本与候选保留原生来源、时间、Free／倍率／套餐原单位；未知金额不猜账单，账号整体变化不归为子任务精确费用。派工保存自做／委派总开销比较。只有用户显式设置并可用原生单位核对的预算形成边界。

停止由 relay 直接处理，范围可为任务、工作项或整个工作台；先取消未提交队列，只停止实际绑定的本次原生轮次。未确认保持 stopping。原生权限保持原义，后台无法安全处理的交互说明原因并等待，不自动批准或切换普通会话。

relay 恢复进入 recovering，核对已接受与已结束事实；仅确定未提交才发送，未知执行 blocked，不自动重发。失联、额度不足、错误和中断均不表示完成。

Fusion执行终态取对应原生轮次的状态；正文或工具历史仍在分页不等于原生还在运行。原生中断／失败如实结束对应执行，不作为业务完成。

旧元数据备份并清理明确属于旧 Fusion 的字段，不迁移或保留旧引擎；其他 relay 状态、原生会话、收藏、项目映射和普通窗口保留。Devin 原生 Fusion 模型模式独立保留。

## 验收

受控状态机覆盖零／多任务、DAG、补做、三档、去重、事件合并、停止／恢复、预算，以及同软件／同项目独立写任务并行、跨软件依赖串行、多个未知轮次恢复与连接释放。真实原生核对各任务回执、执行时间是否重叠、后台并发、原会话隔离和重复调用；配对浏览器核对任务及原生内容归属、草稿和普通导航。用户手机按实际范围另行验收；缺少条件或未执行的项目保持待验，受控通过不等于真实并行验收通过。
