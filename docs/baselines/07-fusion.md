# 07 Fusion：持续主 Agent 与后台子 Agent

[基准索引](README.md) · 2026-11-05 新契约，替代旧 run 与专用子窗口流程。实施、切换和验证边界见 [Super Agent 方案](../fusion-super-agent-20261105.md)。本文件描述应有行为，不表示真机验收已通过。

## 入口与主会话

底部“概览｜项目｜收藏｜Fusion”横竖屏一致，共用电脑范围；全部电脑不静默挑选执行电脑。点击导航仅读取状态，进入后返回 Fusion 并恢复电脑范围。切页、普通会话切换与手机断线保留草稿及后台 Runner。

工作台长期管理多个工作项。项目选择／新建／信任复用现有流程；主项目有窗口则复用，没有则按普通项目流程打开。主软件从该电脑登记的软件能力选择，Cursor、Devin、Codex 共用软件级 NativeAgentProvider；连接状态与模型目录来自当前原生窗口。模型及思考强度是配置数据，新增模型不创建新的会话管理实现。具体软件的真实成功场景与受阻项仍按当次验证记录区分。

主 Agent 使用完整普通原生会话功能，模型及思考强度由用户选择。Fusion 在主对话旁提供设置及任务关系。交办新需求回到普通主输入框，保留既有草稿；具体工作／任务补充及问题回答沿用工作台收件箱，登记回执不等于原生接受。只读查看任务板不切换桌面会话。

主对话是主控提问、回答及方案确认的统一入口：卡片显示工具登记的原文，关联实际主轮次与questionId／planId。控制台只提供待处理状态和定位，不再显示另一份问题表单；原生审批和原生问卷保留原目标。主控使用ask_user登记完整问题，普通回复不另写一份不同提问。紧接唯一提问轮次的实际原生用户回复可按已接受轮次关联；多个候选、其他会话或事件唤醒不推测回答目标。必要方案提供确认执行、要求修改及拒绝：修改意见和拒绝均不授权派工，新方案仍须重新确认；拒绝方案不等于停止工作台。回复已收到不等于方案已确认，草稿、选择和焦点在状态刷新时保留。

启用Fusion即按工作台约定授权主Agent自主组织需求：决定自做或派工、子Agent软件／模型／强度、依赖、验收补做及交付，无需用户点名子Agent或逐项批准分工。零子任务仍允许，用户本轮的明确限制、项目AGENTS.md要求及原生权限审批继续适用。授权及主控说明只进入实际绑定的主会话：Codex 沿原生 additionalContext／开发者指令，Cursor 沿该 composer 的原生请求上下文与工具快照，Devin 沿该 ACP 会话的 MCP 工具配置。用户正文、附件、草稿、消息身份和原生设置保留；同客户端其他会话及子会话保持原请求。启用、查看和安装绑定本身不发送业务任务，已有主会话下一次正常请求沿用该规则。

Codex 使用单会话动态工具；Cursor 按原生 composerId 提供／执行工具，不注册全窗口 MCP Provider；Devin 仅使用连接器实际提供的会话级 HTTP MCP，管理服务只监听本机。Devin 新主会话在 session/new 时携带工具配置，Fusion 后台会话使用原生 skipPreferenceSeeding，不消耗普通界面的待选配置；显式模型与该会话的待提交配置保持一致。MCP 只承载同一个 ra_fusion 管理协议，不新增模型执行通道。原生工具请求关联真实 thread、turn／generation 和 call ID，普通聊天、子回复或历史文本不作为管理请求。

## 打开、详情与证据读取

已启用的工作台点击后直接走普通会话的既有导航链路，按实际主绑定确认所属软件窗口、原生 thread 和工作台身份，不先等待完整工作台数据。未启用的工作台只读取配置。异步配置、任务和审计回复只属于发起它的视图，切走后不能重新弹出或抢占后来选择。

历史主会话在当前项目窗口中确认新鲜首屏后，同步当前 Fusion 主绑定的窗口位置；核对软件、原生 thread、真实目录及 host，缓存、未就绪或已切走的读取不登记。历史子会话正文沿已有项目窗口定位能力，读取其原生 thread，不依赖旧桌面窗口仍存在。位置更新和历史查看不改变原有 Attempt、待处理事件或停止状态，也不继续派工；执行与停止仍核对实际原生轮次。

工作台列表及主对话头部使用摘要；主绑定确认的 attached 携带必要关联，原生主聊天不附带整份工作台。配置、工作／任务列表、选中任务、输入问题分别按用途读取，不把全部事件、历史正文、大差异和每次 Attempt 重复的实时正文放入默认状态。

选中任务的正文与历史沿用 fusionContent 分页；真实审批／问卷从未结束的最新执行投影到主对话，按原Binding／Attempt／原生请求身份处理；子详情不展示原生操作，复制／Fork不作为审批。展开具体执行记录、评审或交付证据才读取完整数据，结果、基线、差异及证据不截断、不删除。主对话中的Fusion原生请求使用自己的目标标记，操作只发送给所属执行绑定，不自动批准或转成另一份主控问题。

详细状态只订阅正在查看的视图，关闭或切换后释放，保留摘要；连接恢复时仅恢复仍在查看的视图。更新详情时保留输入、选择、焦点、光标、审计展开项及滚动位置。Runner、派工、成本、模型、停止／恢复与持久化格式保持原语义。

## 界面与按需展示

Fusion 主页按所选电脑范围分组，复用概览卡片、状态色与底部导航；统计和待处理事项汇总所选范围，待处理胶囊标明电脑。离线电脑默认折叠，仍可展开查看缓存摘要。正在执行的工作台使用宽卡，需要处理的工作台标出橙色边框；任务验收数与分段进度来自真实摘要，不以原生接受或生成结束代替验收。

工作台卡片沿用普通会话卡片的紧凑结构：Fusion图标在左，标题及其下方状态标签在右，中部为电脑／项目，底部保留任务完成数和分段进度条。卡片固定使用现有Fusion图标，不以参与软件的Logo替代；关系和任务中的各Agent仍使用所属软件Logo。标题与状态字号、状态配色和背景层复用普通卡片，底部任务完成数为16px，总数及“任务”为12px；主页和收藏共用同一渲染。工作台不展开普通会话预览，不提供底部重复状态或打开按钮；点击直接进入原主对话，长按菜单和打开中／失败反馈保持原语义；打开进度和失败原因复用普通会话卡片下沿提示，不额外显示加粗的“正在打开”或“重试打开”，再次点击卡片沿原路径重试。从收藏打开工作台保留收藏来源、电脑范围及返回位置，不先切到Fusion主页。需要用户操作的状态统一显示“待处理”（Pending），审批和问卷的实际目标及处理方式不变。

工作台卡片长按复用普通会话菜单，提供打开主对话、查看任务、设置、已读、收藏／取消收藏、重命名、停止及删除。长按本身只打开菜单，不发送任务或切换原生目标；已读沿用本入口稳定 resultKey，不清除必要问题、运行或未知状态。名称与收藏保存到所属 relay 的工作台数据，其他配对入口同步；收藏页保留原电脑与工作台身份，使用同一 Fusion 卡片。重命名通过已有软件级接口，在后台更新当前main.bindingId对应的原生主会话，确认成功后保存并广播工作台名称；原生规范化名称时以实际确认名称保持两者一致，失败或结果未知不冒充成功。没有主绑定时先保存工作台名，首次启用也确认原生主会话同名；读取列表本身不改名。子Agent、其他普通会话、模型、草稿及执行事实保持独立归属，收藏不改原生名称。

用户明确删除工作台时，先按既有规则停止并核对全部未结束或结果未知的执行，再逐个清理该工作台明确绑定的主／子 Agent 原生会话；按原生实际能力删除或归档，记录真实动作及确认结果。全部确认后才从可用列表及后台恢复中移除工作台，执行记录保留；部分失败则保留工作台和各项结果，不冒充全部删除。无关原生会话及共享桌面窗口不属于清理目标。

整体状态核对主／子Agent尚未结束的实际Attempt及未处置结果，不以子任务运行数或Controller的waiting字段代替主控原生轮次。主控独自执行、排队或准备同样纳入当前推进；已返回而待主控验收的结果保持待处理展示。旧停止／取消任务、已处置及已结束工作项中的历史失败保留在任务计数和详情，不单独造成整体阻塞。实际必要用户决定、明确整体阻塞／停止、恢复及未知执行继续各按真实事实展示，未知不提供可清除结果标识。当前进展关联本轮工作或原请求，不回退到无关旧停止任务；没有当前执行或待办时为空闲，全工作项真正交付后按已完成处理，不修改Runner和历史数据。

主页的已结束结果提示与真实执行状态分别处理。成功进入对应Fusion主对话，目标和新鲜首屏已就绪且页面可见后，本入口将本次完成／已停止阻塞结果标为已查看；卡片及统计恢复中性空闲，任务进度、原状态、阻塞原因及历史仍在主对话和详情保留。仅浏览列表、配置或任务关系、打开失败／取消、缓存预览和其他目标不清除。运行、必要问题／方案确认／原生授权、结果未知和停止未确认继续显示。已查看记录按电脑、工作台及稳定resultKey保存，同一结果刷新／重连不重新提示，新执行或交付结果重新提示；正在观看对应主对话时沿用同一规则。resultKey只取原执行／交付及终态事实，不使用会因连接或管理读取变化的updated／revision，也不改变Runner状态。

主对话标题显示工作台名称，副标题显示主会话模型、强度和成本档位，模型显示值已包含强度时不再追加。上下文和额度放在标题右侧，复用 Cursor 的圆环与数字，保留原有口径、辅助说明和点击详情。工作台设置统一位于“…”菜单，关联当前电脑与工作台；输入区原生模型选择功能保留。手机竖屏显示可横向滚动的任务条，按真实最近活动倒序排列，首次进入显示最左侧最近任务，状态刷新保留手动横向浏览位置；打开关系面板时对话变暗。电脑仅在现有 `body.split` 布局中沿用左侧栏，并增加可收起的关系右栏，任务详情也在右栏展示；中间聊天保留原节点、输入和滚动。手机横屏不采用电脑右栏。

任务条的滚动标识与真实computer／run归属分开，点击仅读取实际所属工作台。关系中的每个子Agent显示主控提供的职责短名Worker.label，软件／模型为次行；新建和复用时通过dispatch.input.label更新，不为历史改名额外派工，闲置历史Worker在复用前保留旧名。节点默认折叠，展开后任务按updated最近活动倒序，同时间保持原顺序，完整目标及依赖保留；明确定位某任务时展开其所属节点。刷新使用Worker身份保留展开状态。子原生审批／问卷仍在主对话处理，交互详情默认折叠，待处理标识保持可见；展开不额外读取子会话正文，刷新保留选项、草稿和焦点。

主对话不常驻显示“等待新事件”等普通状态。实际阻塞、停止或停止待确认时使用紧凑提示卡，原因可展开，动作沿既有工作台归属提交；当前读取失败继续提供错误与重试入口。恢复按既有核对流程成功从recovering转waiting时清理已解除的blockedReason，历史Attempt的中断、失败及证据保留，未确认执行不重发。

关系树按真实 Worker 展示分工、状态和依赖，保留历史主控执行记录。主控的新自做工作直接使用其原生轮次，不创建自派Task。主对话不再追加内部事件提醒、派工卡及自动确认的内部方案卡，具体工作从顶部任务条与详情查看；必要用户确认、问题及原生审批继续显示。历史内部输入仅按已登记的origin=events主Attempt和原生消息身份从Fusion展示过滤，不删除原生历史，不按正文关键词隐藏用户消息；普通会话不应用此过滤。Fusion 图标统一为一个实心主节点向下分出三个空心子节点，使用现有软件 logo 表示各 Agent。

主页、任务条、关系树和任务详情首屏只使用展示摘要，不读取子会话正文。详情首屏包含进展、更新时间、可用文件变化数、耗时和接受回执；真正待处理的原生交互统一在主对话展示，来自已有fusionLive，不读取子会话正文。没有可靠记录时标明未提供。目录快照缺少逐文件哈希时不猜文件数，执行前已有改动不计为本轮成果。

“派工 → 执行 → 验收 → 交付”是已有事实的展示，不增加执行阶段或结束规则。“子 Agent 对话”展开后才使用 `fusionContent`，保留加载更早内容；长文本、JSON及路径在Fusion正文范围内折行，代码和表格在自身容器内滚动，全文保留。任务输入通过 `fusionRead.inputs` 显式读取，评审与执行记录沿用审计读取。关闭、切换与旋转复用同一视图归属和释放规则，刷新保留表单、焦点、光标、展开项及滚动位置。

## 主控与持久任务

原生单会话 `ra_fusion` 工具是唯一管理入口；真实主 thread／turn／request ID 与 Runner decisionId 关联。请求 ID `0` 正常处理，重复命令不重复派工。子回复、历史、思考和文本 `fusion-control` 不执行。

旧主会话保留原生thread及工具schema。Fusion显式绑定在该线程空闲时更新开发者指令，忙时等原轮次结束再更新；保留用户模型、强度、权限和草稿，不新建会话或自动发送。当前原生协议不支持resume更新工具schema，Worker短名通过已有dispatch.input传递，不增加改名动作；普通会话不进入此配置分支。

Controller、WorkItem、Task、Worker、Assignment、Attempt、Binding、输入／事件／效果分别保存。一个主控管理多项工作；简单问题零子任务，复杂工作按依赖分批派工，无固定数量和轮数。项目 AGENTS.md 要求确认时展示具体范围和标准，确认后才派工；已授权范围内分工不逐个请示。

主控自己执行按普通原生会话及项目AGENTS.md完成，不以create_work、plan、mainScope、成本登记或finish为前置，不创建Task／Worker／Assignment。历史自派任务、范围基线及成本事实保留。委派时主控验收真实结果，补做新增Attempt并续接原子会话；主控管理轮次保留其工作项关联。工作项交付逐项关联完成标准与证据；必需任务、未处理新输入和未知执行均须核对，主控实际轮次完成后才确认工作项交付。完成工作项不关闭主工作台。

plan登记委派范围与完成标准，dispatch才登记及派发子任务；各动作必填字段通过read_workspace统一提供。正常review必须同时提交简短summary，归纳结论、验证和未完成项，作为后续工作记忆；完整reason和evidence保留，不另开模型轮次生成摘要。review的顶层attemptId就是本次逐项证据的实际来源，无需在每一项重复；finish仍逐项关联来源Attempt，本轮主控交付证据才使用main-turn引用。历史读取使用所选Attempt的Binding，不随Worker后续配置改变来源。

工具契约在contract.mjs集中定义动作字段、查询视图、分页边界及证据含义，schema、运行时校验和说明共用；保留单个ra_fusion及既有字段类型。工作详情直接用read_workspace顶层workId，input只承载section及分页，旧input.view=work/id明确反馈新入口，不猜测或改写参数。默认agents就是子代理索引，单个Worker详情复制其read并携带真实id，不增加workers／agents视图别名。模型分页默认最多8张，沿read读取，静态参数校验先于原生目录或公网读取；非法大limit不截断或改写。scope仍须非空项目相对路径，'.'表示明确选择项目根目录，系统不替主控扩大范围。

选中待验收Attempt的read_task返回review填写模板，预填真实taskId／attemptId和任务criterion ID，主控填写verdict、理由、工作记忆及实际证据；工作详情返回当前已确认方案的finish模板和已结束来源索引，来源先列4项、完整索引沿sources读取及分页。criterion是标准ID，detail是实际核对结论，reference是证据位置；finish逐项选择attemptId，系统不猜来源或结论。review成功回执给出对应工作详情read。默认摘要不常驻完整模板，模板不代表已获授权或满足完成条件。字段错误回给原生调用message／field／expected及相关read，原reason、动作和轮次归属保留；不自动修参数、重试、接受模糊ID或降低验收条件，其他原生错误保留原路径。旧线程沿既有字段和回执取得新说明及模板，不重建或伪造热更schema。

finish只登记交付候选，仍等待本轮原生成功结束并核对方案、必需任务及未知执行。候选之后的事件中，仅同一主thread／turn已实际收到回执的只读工具结构化参数错误不撤销候选；错误记录完整保留。未送达、其他轮次／线程、旧记录缺少动作归属、修改动作错误及原生错误不按该类处理；新需求、子结果、权限、停止和未知执行仍阻止交付。

主控管理变更复用原生会话订阅的轻量通知，读取原生轮次与工具请求；普通会话沿用原快照订阅。内部事件在原生管理工具回执成功后确认送达，批次记录只表示实际送达／占用，不表示验收。主控有wait或管理工具请求时接收结果，普通生成期间保留事件，本轮结束后空闲时沿原主thread接续；不插入另一条普通用户消息或新增Steer路径。历史后台轮次的eventIds不能永久遮蔽尚未处置的结果。部分处置后继续剩余批次，有实际进展就继续，无固定审核轮数；审核轮次没有处置进展且无新事实或真实外部等待时，明确保留审核阻塞，不反复空调用。新事实、实际用户输入或用户明确继续可再推进；原生失败／失联不自动重试。内部输入沿origin=events及原生消息身份过滤，手机切页／断线不停止Runner，停止或未知执行先核对。

结果待办按原Attempt独立保留，默认至多4个引用及总数，完整队列沿read_workspace的reviews分页。成功结果明确review，失败保留原生失败并关联补做、取消或必要问题，未知执行不重发；通知已读、主轮次结束和Task较新执行已验收均不能抹掉旧待审事实。问题按taskId／attemptId关联，仅暂停相应结果；实际回答或方案确认后接续。wait不能跳过可处理结果，finish不能跳过必需处置，continue_task须先处理原任务上次成功结果。较旧Attempt的review不覆盖较新Task状态或最新成果记忆。读取证据不修改结果事实；工具回执的实际送达单独记录。

read_workspace默认返回当前工作记忆、未结束任务及轻量Worker索引；仍完整保留当前方案、授权范围、完成标准、待处理问题／事件、停止和未知原生执行事实。选定工作使用顶层workId；worker、history或protocol通过input JSON读取，均复制返回read。已结束过程不反复塞入默认回执。read_task首屏保留必要任务条件及所选Attempt证据目录，完整输入、评审、分配和执行历史显式分页，沿nextOffset读完；默认摘要不代替原文或用户授权。

子请求在实际Binding确定后构造。该原生thread首次发送完整规则、目标、项目、授权范围、读写属性、验收、本次说明及新补充；原Task续接只发送变化字段，新Task复用Worker时发送完整新任务条件而不重复规则。差量基准必须是同Binding、同原生thread已经接受且结束的Attempt，依据和最终提示在提交前持久保存；旧记录没有基准时下一次正常提交先发完整输入，恢复只核对原请求，不重新生成或重发。依赖只带任务身份、目标和状态，主控在派工说明中提供必需的上游结论与文件路径。原文和既有原生历史不改写；这减少RA后续输入，不等于压缩原生会话已经积累的历史。

## 后台执行与普通会话隔离

同软件 Worker 使用主窗口中的独立原生会话；跨软件复用该软件已打开的窗口，不创建子窗口。通过明确 app／host／目录／thread 的原生管理器读写和订阅，不借当前可见对话的 DOM 代替后台事实。普通项目、草稿、模型、权限、队列、会话和监听均保持原功能。

普通窗口由用户切到其他会话时，普通发送仍按原规则拒绝；Runner 不强行切回。后台任务只操作自己的绑定与实际原生轮次。主 Agent 按输入产出、文件、命令和共享资源判断依赖与冲突，用 `dependsOn` 或分批派工决定串并行；relay 不按软件、项目或读写类型强制互斥。同软件、同项目的独立写任务可并行，不同软件有依赖也必须顺序执行。截图验收后再修改依赖截图的 README；两个互不冲突的功能可以并行实现，后续集成和验证依赖对应任务验收。主控自己执行也需判断结果依赖和共享资源冲突，不额外登记自派任务。

同一工作台的主控决策保持顺序，同一任务未结束或原生结果未知时不能重复提交；未知执行只保留在其任务与 Attempt，不占用全软件或全项目。当前策略通过 `read_workspace` 告知历史主会话。记录执行前已有改动和本任务的负责范围，原有及其他并行任务的改动不算本次成果，不创建 worktree 或自动合并。

Worker是可复用的原生子会话，不与单一Task绑定。主控从agents索引查看职责、软件／项目、当前及排队任务、最后活动和最近已验收memory的120字符预览；预览标总字符数，全文沿read取得。指定Worker详情保留近期目标、结果与用量，不默认读取原生历史。原生工具回执真正成功后记录本主thread已经收到的Worker身份、摘要指纹、时间和轮次；未变化资料不要求每轮重复读取。用量保留原读取时间，未知不据任务数推算当前上下文或账单。

原Task补做用continue_task，相关新Task可通过dispatch.input选择已有workerId。Task的输入、Attempt、评审和证据独立保留，复用Worker只续接原生上下文；另立任务／保留记录不要求新Worker，独立复核应与被复核执行分开。新建时若存在同软件、host及实际项目的候选，compared不能空且须比较真实返回过的候选；选择保存读取依据和取舍，缺资料给出具体read，不自动改选或猜理由。独立职责、软件／项目差异或并行需要仍可新建，相关性由主控判断，不以文字相似度强行复用。label概括长期职责，单行最多32字符，文件名／TaskId留在Task.goal；旧长名仍在正常派工／复用时更新，保留Worker、Binding和原线程，不为改名调用模型。

主模型不作为子模型的默认继承规则。复用核对软件、host及实际项目，任务、Assignment和Attempt分别保留。一个Worker同一时刻执行一个原生轮次，多项任务依次排队；不同Worker仍按主控依赖并行，未知结果阻塞该Worker的新提交。

子 Agent 和原生会话持续保留，不自动归档、删除、隐藏或关闭；用户明确删除整个工作台时按上文清理绑定会话。每次原生生成结束释放该次监听和连接，不影响同窗口其他任务；后续相同任务可重新调用原子会话。共享窗口继续使用原有普通空闲扫描与收藏关联规则，没有专用 Fusion 回收流程。

## 成本、停止与恢复

均衡默认，三档只表达取舍，不限制模型或强度。主控直接执行不新增方案成本预留；已有已确认主控方案的成本事实仍与子任务Assignment纳入原预算累计。成本与候选保留原生来源、时间、Free／倍率／套餐原单位；未知金额不猜账单，账号整体变化不归为子任务精确费用。派工保存自做／委派总开销比较。只有用户显式设置并可用原生单位核对的预算形成边界。

选型使用同一个list_models接口：app=all收集本次已连接软件，JSON needs可说明任务类型、视觉／工具／推理与上下文需求；默认至多8张交错软件的候选资料卡，沿返回的read选择器分页或读完整profile。原生窗口决定可执行型号和思考强度，公开资料不增加原生不可用型号。主控按任务需求比较模型特质、软件工具、已有Worker上下文、自做和委派总开销，在cost.reason及sources保存取舍和原生快照ID；不为多样性强迫换模。continue_task也明确本次execution，不再隐式沿用上次配置；同型号合适时可继续选用，原Worker／线程复用不变。

Fusion共用联网资料缓存，首次／过期24小时或出现未映射原生型号时读取models.dev、OpenRouter及登记的软件官方计费文档；手机配置和普通会话不等待公网。只有配置FUSION_AA_API_KEY时才读取Artificial Analysis，缺少独立评测保留未知。按确切ID或公开canonical关系匹配，Pro／batch等变体分开；Cursor Auto内部型号未知。来源URL、声明／评测类型、可读更新日期、读取时间、错误和陈旧标记保留；资料缺失或冲突不猜结论。API参考价、桌面套餐／额度和本机原生价格分别保存，原单位不转换成订阅账单或显式预算报价。官网文档原文及完整评测按需读取，实际模型配置与评测配置不等同；本机验收、补做、原生错误和总耗时只是历史观察，具体用量沿原Attempt读取，不当成精确模型能力或单任务费用。

停止由 relay 直接处理，范围可为任务、工作项或整个工作台；先取消未提交队列，只停止实际绑定的本次原生轮次。未确认保持 stopping。原生权限保持原义，后台无法安全处理的交互说明原因并等待，不自动批准或切换普通会话。

relay 恢复进入 recovering，核对已接受与已结束事实；仅确定未提交才发送，未知执行 blocked，不自动重发。失联、额度不足、错误和中断均不表示完成。

Fusion执行终态取对应原生轮次的状态；正文或工具历史仍在分页不等于原生还在运行。原生中断／失败如实结束对应执行，不作为业务完成。

旧元数据备份并清理明确属于旧 Fusion 的字段，不迁移或保留旧引擎；其他 relay 状态、原生会话、收藏、项目映射和普通窗口保留。Devin 原生 Fusion 模型模式独立保留。
