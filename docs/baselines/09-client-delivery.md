# 09 客户端、外观、缓存与发布启动

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

提供手机网页／PWA、Android WebView 与 iOS WKWebView 客户端，维护公共界面、主题、语言和布局，交付缓存更新、网页／原生版本与本机安装、Agent 启动及隧道服务。业务功能仍遵守各自基准，不在壳或公共弹窗里复制一套。

## 客户端与公共界面

| 场景 | 行为约定 |
|---|---|
| 深浅主题 | 深色、浅色和跟随系统按用户选择展示，不改变原生业务设置 |
| 中英文 | 翻译应用文案；聊天正文、代码、文件、路径和用户名称保持原内容 |
| 竖屏／横屏／宽屏 | 功能入口可达，弹窗和列表可操作，布局变化不创造聊天到底意图 |
| 输入框 | 未编辑时保持紧凑，编辑时适应内容；键盘收起、旋转和切模式不清空草稿 |
| 弹窗 | 打开、返回、切换和关闭时只结束属于该功能的读取／临时资源；关闭或替换确认须结束为取消，明确确认保持成功，不误关其他原生页面 |
| 原生能力 | 按实际安装构建提供扫码、通知、密钥、存储、下载和麦克风等能力；网页更新不创造壳里不存在的接口 |
| 刷新／崩溃恢复 | 保留持久配对、草稿和历史的既有语义；重建 WebView 不应重复使用一次性授权或通知目标 |
| 外链与导航 | 外部地址按既有原生／浏览器方式打开；受信入口按完整来源边界处理，不把不同端口默认当同源 |

原生系统权限与网页站点权限分别按实际平台管理，不能承诺所有入口都能永久保留权限。PWA、Safari 普通页面和原生 App 的后台能力分别验证。

从 iOS 主屏幕打开的 PWA 不再声明 apple-mobile-web-app-status-bar-style；原有 theme-color 主题脚本和安全区 CSS 保持。v405 将 viewport-fit 从 cover 改为 auto，作为浏览器自动处理安全区的单变量对照，页面可用区域和 env 计算值可能变化，实际手机结果待验。html 使用 100vh，主屏幕 body 在键盘开合时均使用 relative／100% 高度；普通浏览器标签继续原固定根布局。v403 按用户要求在所有入口取消整页几何补偿：fitViewport 不再写入 body 的 height／transform，主屏幕不再随 .kb 切换 fixed；原键盘判定、工具栏状态、输入框／Question 高度计算、编辑收尾及事件调用保持。这是取消补偿的对照实验，尚不作为 iOS 模糊修复通过。v393 采样元素、v395／v396 启动隐藏恢复、v398 布局记录及 v399 失焦后维持补偿在 v400 已撤回。主屏幕新旧入口、底部是否超屏、键盘跳动和顶部模糊分别由手机验证，不以桌面模拟结果认定 iOS 原生效果通过。

v403 已发布后的真机反馈：取消补偿没有消除顶部模糊，故模糊修复验收失败；用户明确要求保持补偿取消，不恢复。其他未分别反馈的手机项目保持待验。进入页面时出现的黑屏与顶部渐变截图不单独作为“系统唯一根因、RA 完全无关”的证据。

v404 将主页与对话页顶栏独立固定，保留当前可见布局，不增加顶部空白。原对话顶栏仍为 body 的直接子节点，新增 aria-hidden 的空元素承接原有 flex／grid 位置；ResizeObserver 只同步顶栏实际 left／width 和该空元素的 margin-bottom，其高度为0，不复制顶栏或写死多行高度。主页用伪元素保留原有一份顶栏高度；横屏消息列仍从原位置开始，侧栏列宽保持。整页高度／平移补偿继续取消，viewport-fit、状态栏、主题、安全区、导航过渡和底栏保持。顶栏是否随真键盘上移与顶部模糊是否改变分别由手机验收，未验不记通过。

v404 已按单独授权更新四项网页静态文件，Pages构建及公网五项哈希核对通过，共享url.json保持；这是资源交付结果，手机仍须沿用原图标确认版本后验收，不将其计为模糊或键盘问题已解决。

v404 发布后的真机顶栏验收失败：用户确认主页卡片和对话页在键盘打开时都会上移，关闭后回来。随后提供的主页卡片记录确认计算样式为 fixed，但键盘打开时根和顶栏 top 均从0变为-161，关闭后恢复0；可视视口从874缩至477，offsetTop 变为161，body 内联 height／transform 始终为空，顶部安全区保持62。记录不包含独立对话页操作，不能将同时测量的未激活 chatHeader 算作第二次验收，也不能直接测量系统模糊。普通桌面文档滚动的检查结果不足以代表此场景。

v405 按用户确认的五文件方案仅改变 viewport-fit 配置并同步 core 版本与缓存引用；CSS 继续使用v404，独立顶栏、原占位、尺寸观察器和整页补偿取消状态保持。该配置对照的手机结果按用户实际反馈分项记录，不以桌面布局检查代替真机验收。

v405 本地 npm run check 583/583通过，既有配对浏览器完成三个功能分组，四组横竖屏布局矩形与本次修改前v404一致，原配对页与存储保持。新旧版本同场景均报告 ResizeObserver 通知未送达，脚本整体“无错误”断言未通过；未为此扩大产品修改。

用户于2026-11-05随后授权发布。gh-pages提交 `2db00b637201a3687d6b4afb57bd5e9351fa1545` 只更新index.html、js/core.js、sw.js，共享url.json与其他资产保持，发布时master为 `e923d3b2e0f7c36d67ca096f388a74d6953dea2e`。首轮[部署工作流](https://github.com/xrdiao/remote-agent/actions/runs/41864434629)遇到排队，[GitHub官方](https://www.githubstatus.com/incidents/xr3myzj7ms51)公告Actions／Pages性能异常，当时公网仍为v404。后续核对当前Pages已built（提交 `657d9d1a65b4bb06672a33c56265e262883fb790`），公网根入口、index、core、sw及未改CSS五项哈希全部匹配v405静态包，发布生效已确认。

v405 真机反馈：用户确认顶部不再模糊、底部正常、重新共享没有问题，手机显示v405；上述反馈范围记为通过。未明确反馈的键盘期间顶栏位置及全部横竖屏场景不外推为通过。用户另报Codex从卡片内“打开会话”后偶发留在主页、打开慢，补充时已恢复；该间歇问题独立保留排查记录，未据此修改v405产品代码。

v401 仅按 [WebKit 317153 中 Apple 工程师的建议](https://bugs.webkit.org/show_bug.cgi?id=317153#c2)删除旧状态栏 meta，不替换成 default，也不增加页面层补偿。状态栏颜色、顶部模糊和可用区域由 iPhone 真机验证；入口实际更新至 v401 后，必须删除旧主屏幕图标，从 Safari 重新添加，再逐项核对冷启动／刷新、深浅主题、主页／会话／终端的上下沿、会话返回、键盘及横竖屏。桌面资源检查不能代替这项验收。若出现底部超屏或异常顶部留白，先记录 innerHeight、screen.height、visualViewport.height 及安全区上下计算值，再单独提出方案；模糊仍存在则记录失败，不在本轮叠加其他候选。

v401 真机结果已判定失败：用户确认网页 v401 并删除旧图标重新添加后，顶部仍模糊，主页底部栏目被屏幕下沿截断。删除该 meta 不作为已通过的解决方案；现有代码状态与验收结论分别记录。本轮候选到此停止，未验证项目保持待验；后续布局处理需先获得手机实际视口、安全区与容器几何值，再单独确认方案。

v402 在“…”→通用→应用设置与帮助中恢复临时“页面布局记录”，默认关闭。手动记录或主动设置一次性“记录下次启动”后，才采集视口、安全区、容器几何、顶部覆盖元素及应用资源摘要；一次性开关在下一文档消费，记录保留在当前文档内存，不自动刷新、不上传，不读取正文或配对凭据。每次最多 400 条，停止时释放监听和不可见测量节点；刷新清除当前记录。主页采用真实顶栏与底部栏目作测量对象，按事件及合并的下一帧记录，保留原键盘和布局行为。资源摘要区分已执行 core、已加载 CSS 的 CSSOM 指纹、DOM 引用及缓存条目哈希；缓存条目不能单独证明当前页面使用的字节。用户保留当前底部正常的图标，在入口确认 v402 后记录刷新首屏、主页卡片键盘和会话返回；网页发布、本地及桌面检查不能当作手机已开录或模糊已解决。

主页共用顶栏和底部栏目导航保持在各自视口边缘及卡片前方，卡片展开／收起、自动定位、电脑分组折叠和栏目切换的动画期间也不被移动的卡片遮挡。导航恢复原常驻过渡名称，在视图过渡中独立保持静止；顶栏的同一过渡快照同时覆盖顶部安全区，工具按钮仍位于安全区下方，原位置不变。卡片继续原有动画，滚动区、横竖屏和左右／底部安全区规则保持。普通菜单和弹窗仍显示在导航之上。

主菜单标题右侧依次放置文件传输、语音输入、切换电脑的图标入口，图标沿用各自原有动作。主菜单“模型”分类不重复展示更换模型、Editor 和打开项目；输入区、侧栏及项目列表中的其他入口保持原用途。传输与语音移到标题栏后不再保留原列表重复项。

主页电脑行右侧在连接认证完成后显示该电脑的文件传输图标，替换原 ⓘ 连接详情；尚未连接、断线或失败场景保留原连接详情及重连入口。文件传输复用原面板并独立登记浏览器历史，返回时恢复打开前的会话或主页栏目、卡片和滚动位置，不改变聊天目标。

主对话输入框横竖屏共用折叠后的模型／项目工具行外观。横屏保留原有空输入、无附件且空闲时自动折叠及点击展开的交互；主输入框编辑期间不自动折叠，提问卡片输入聚焦时主输入框立即折叠。手动收起、展开或旋转不清空草稿。

当前会话有未隐藏的改动文件提示时，耗时和状态位于输入框左上沿，文件图标与数量位于右上沿，点击可打开原变更列表。提示不带叉号，统一通过“…”菜单的“显示改动／隐藏改动提示”操作；隐藏状态继续按电脑与会话区分。两侧分配各自宽度，长状态截断显示，上沿预留高度避免与排队栏重叠；完整文件说明保留在按钮辅助名称中。重试按钮显示“重试”，辅助名称与动作仍为重试当前会话。折叠箭头保持原工具行位置；没有文件提示时沿用原状态布局，排队、子 Agent 和真实改动数据保持原语义。

## PWA、缓存与更新

1. PWA 缓存应用壳，实时中继地址和业务数据按各自请求语义读取；离线预览不冒充实时连接。
2. 网页显示版本、Service Worker 缓存名、HTML 资源参数与预缓存资源组成一致的一次交付。
3. 更新及激活只清理本应用、对应 scope 的旧资源；同源其他应用缓存、配对密钥、IndexedDB 历史和草稿不被顺带删除。
4. 从中继和 GitHub Pages 两种入口提供当前功能所需资源，包括按需加载的扫码、PDF、字体和媒体组件。
5. 网页发布后核对部署状态及公网实际版本；本地文件改变、推送提交成功、网页已生效是不同事实。
6. 刷新行为按浏览器及壳实现验证，不能只看本地版本号就认定手机已拿到新资源。Service Worker 注册使用当前应用版本并绕过 HTTP 缓存检查更新，安装应用壳时重新读取资源；不通过清空配对、草稿或历史数据升级。

应用壳包含本地 KaTeX 脚本、样式及其引用的现有 WOFF2 字体。首次成功安装后，即使此前没有展示公式，断网重新打开也可渲染已缓存内容中的公式；资源检查同时核对 HTML 引用、字体引用和预缓存清单。离线渲染不表示已经连接 Agent 或可执行新请求。

## 网页发布与地址记录

已有用户约定：代码修改完成并通过必要检查后，更新前端缓存版本，同步当前 `app/` 到 gh-pages，重启中继并核对公网资源生效。`master`／`debug` 的提交和推送仍在用户明确要求时执行。

本规则不用于纯文档任务。发布保持其他电脑的地址记录，不把一次手机网页升级当作 Android／iOS 原生二进制升级，也不通过清空配对解决更新问题。当前用户明确指令可调整本次发布范围。

## 原生版本交付

- Android 独立维护 `versionCode`、`versionName`，使用用户自己的签名发布。现有更新入口依赖 `v` 加版本名的 tag，以及名为 `AgentRemote.apk` 的发布资产。
- iOS 使用对应构建号和签名，通过现有构建／TestFlight 入口交付；本地签名、`Local.xcconfig` 和私钥不提交。
- 原生通知、后台服务、权限、桥接、历史存储和深链属于壳功能。没有 SDK、签名、Xcode 或真机时，标明未构建／未验证，不能把网页浏览器检查写成原生验收。
- 共享 setup 页面与两种壳入口保持既有链接、语言和扫码规则，避免单独更改一份后另一壳加载失效。

## 安装、启动与隧道

1. 安装／配置入口发现依赖，按用户同意安装或下载，不悄悄修改系统驱动或全部配置。
2. Windows／Ubuntu／手动脚本按可执行路径或 PATH 发现目标；`.cmd`、`.exe`、平台进程和路径差异保留。
3. 启动 Agent 明确报告复用、启动、未安装、已有进程但端口不可用、超时或失败；可用调试端口不能冒充项目／会话完整就绪。
   Windows 启动器与中继的端口优先级一致：对应 `CDP_URL`／`DEVIN_CDP_URL`／`CODEX_CDP_URL`，再对应 `CDP_PORT`／`DEVIN_CDP_PORT`／`CODEX_CDP_PORT`，最后默认 9222／9223／9224；Ubuntu 启动入口保持原有配置规则。
4. 只启动所选软件，保留其他 Agent、原窗口和真实任务；普通脚本维护不擅自改变用户启动偏好。
5. 中继、后台服务、隧道进程和地址发布有清楚生命周期；健康隧道按既有语义复用，网络恢复后更新可用地址，不因重复入口创建无关多份服务。
6. 重启中继不等于退出电脑 Agent；不能为恢复一个入口关闭用户已有健康隧道或原生任务。
7. 路径包含空格、中文和合法特殊字符时，命令参数、配置格式、日志及服务安装仍正确。
