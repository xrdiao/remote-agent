# 09 客户端、外观、缓存与发布启动

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

提供手机网页／PWA、Android WebView 与 iOS WKWebView 客户端，维护公共界面、主题、语言和布局，交付缓存更新、网页／原生版本与本机安装、Agent 启动及隧道服务。业务功能仍遵守各自基准，不在壳或公共弹窗里复制一套。

## 客户端与公共界面

| 场景 | 行为约定 |
|---|---|
| 深浅主题 | 深色、浅色和跟随系统按用户选择展示，不改变原生业务设置 |
| 中英文 | 翻译应用文案；聊天正文、代码、文件、路径和用户名称保持原内容 |
| 竖屏／横屏／宽屏 | 功能入口可达，弹窗和列表可操作，布局变化不创造聊天到底意图 |
| 输入框 | 未编辑时保持紧凑，编辑时适应内容；键盘收起、旋转和切模式不清空草稿 |
| 弹窗 | 打开、返回、切换和关闭时只结束属于该功能的读取／临时资源；关闭或替换确认须结束为取消，明确确认保持成功，不误关其他原生页面 |
| 原生能力 | 按实际安装构建提供扫码、通知、密钥、存储、下载和麦克风等能力；网页更新不创造壳里不存在的接口 |
| 刷新／崩溃恢复 | 保留持久配对、草稿和历史的既有语义；重建 WebView 不应重复使用一次性授权或通知目标 |
| 外链与导航 | 外部地址按既有原生／浏览器方式打开；受信入口按完整来源边界处理，不把不同端口默认当同源 |

原生系统权限与网页站点权限分别按实际平台管理，不能承诺所有入口都能永久保留权限。PWA、Safari 普通页面和原生 App 的后台能力分别验证。

主菜单标题右侧依次放置文件传输、语音输入、切换电脑的图标入口，图标沿用各自原有动作。主菜单“模型”分类不重复展示更换模型、Editor 和打开项目；输入区、侧栏及项目列表中的其他入口保持原用途。传输与语音移到标题栏后不再保留原列表重复项。概览层（见 [10](10-overview.md)）打开主菜单时不显示“模型”分组；对话标题栏最左侧的返回按钮回到概览。

## PWA、缓存与更新

1. PWA 缓存应用壳，实时中继地址和业务数据按各自请求语义读取；离线预览不冒充实时连接。
2. 网页显示版本、Service Worker 缓存名、HTML 资源参数与预缓存资源组成一致的一次交付。
3. 更新及激活只清理本应用、对应 scope 的旧资源；同源其他应用缓存、配对密钥、IndexedDB 历史和草稿不被顺带删除。
4. 从中继和 GitHub Pages 两种入口提供当前功能所需资源，包括按需加载的扫码、PDF、字体和媒体组件。
5. 网页发布后核对部署状态及公网实际版本；本地文件改变、推送提交成功、网页已生效是不同事实。
6. 刷新行为按浏览器及壳实现验证，不能只看本地版本号就认定手机已拿到新资源。Service Worker 注册使用当前应用版本并绕过 HTTP 缓存检查更新，安装应用壳时重新读取资源；不通过清空配对、草稿或历史数据升级。

## 网页发布与地址记录

已有用户约定：代码修改完成并通过必要检查后，更新前端缓存版本，同步当前 `app/` 到 gh-pages，重启中继并核对公网资源生效。`master`／`debug` 的提交和推送仍在用户明确要求时执行。

本规则不用于纯文档任务。发布保持其他电脑的地址记录，不把一次手机网页升级当作 Android／iOS 原生二进制升级，也不通过清空配对解决更新问题。当前用户明确指令可调整本次发布范围。

## 原生版本交付

- Android 独立维护 `versionCode`、`versionName`，使用用户自己的签名发布。现有更新入口依赖 `v` 加版本名的 tag，以及名为 `AgentRemote.apk` 的发布资产。
- iOS 使用对应构建号和签名，通过现有构建／TestFlight 入口交付；本地签名、`Local.xcconfig` 和私钥不提交。
- 原生通知、后台服务、权限、桥接、历史存储和深链属于壳功能。没有 SDK、签名、Xcode 或真机时，标明未构建／未验证，不能把网页浏览器检查写成原生验收。
- 共享 setup 页面与两种壳入口保持既有链接、语言和扫码规则，避免单独更改一份后另一壳加载失效。

## 安装、启动与隧道

1. 安装／配置入口发现依赖，按用户同意安装或下载，不悄悄修改系统驱动或全部配置。
2. Windows／Ubuntu／手动脚本按可执行路径或 PATH 发现目标；`.cmd`、`.exe`、平台进程和路径差异保留。
3. 启动 Agent 明确报告复用、启动、未安装、已有进程但端口不可用、超时或失败；可用调试端口不能冒充项目／会话完整就绪。
   Windows 启动器与中继的端口优先级一致：对应 `CDP_URL`／`DEVIN_CDP_URL`／`CODEX_CDP_URL`，再对应 `CDP_PORT`／`DEVIN_CDP_PORT`／`CODEX_CDP_PORT`，最后默认 9222／9223／9224；Ubuntu 启动入口保持原有配置规则。
4. 只启动所选软件，保留其他 Agent、原窗口和真实任务；普通脚本维护不擅自改变用户启动偏好。
5. 中继、后台服务、隧道进程和地址发布有清楚生命周期；健康隧道按既有语义复用，网络恢复后更新可用地址，不因重复入口创建无关多份服务。
6. 重启中继不等于退出电脑 Agent；不能为恢复一个入口关闭用户已有健康隧道或原生任务。
7. 路径包含空格、中文和合法特殊字符时，命令参数、配置格式、日志及服务安装仍正确。

## 回归场景

| 操作 | 观察结果 |
|---|---|
| 切主题、语言，打开含用户文字的各类弹窗 | 应用文案正确，用户数据不翻译，业务状态保留 |
| 竖横屏、软键盘、输入框空闲／编辑、模式切换 | 入口和内容可用，草稿、光标及聊天滚动符合相应基准 |
| 模型、文件、设备、语音弹窗相互切换和返回 | 自身请求与资源结束，不影响无关功能 |
| PWA 旧版更新、离线再开、与同源其他项目共存 | 版本资源一致，原授权／历史和其他应用缓存保留 |
| 从中继／Pages 首次加载扫码、PDF、字体等资源 | 所需资源存在且可读取，无仅发布入口正常的假通过 |
| 网页交付及中继重启后手机刷新 | 实际公网版本生效，连接恢复，电脑任务保持 |
| Android／iOS 扫码、权限、通知、刷新与进程恢复 | 按实际构建能力验证，已处理跳转不重放 |
| Android 更新检查／下载、iOS 构建／交付 | 独立版本和签名正确；缺环境则如实记录未执行 |
| 平台安装、PATH、自定义目录和已有进程／隧道 | 目标和返回状态准确，合法路径正确，健康服务不被误终止 |

## 关联检查与维护

用户功能按索引选择对应基准，尤其读取 [02](02-chat-display-history.md) 的布局／滚动约定、[05](05-notifications-background.md) 的原生后台约定、[06](06-desktop-tools-media.md) 的媒体权限及 [08](08-connection-pairing.md) 的来源和恢复语义。

本次为文档建档，没有升级缓存、发布、重启、安装依赖或构建原生 App。具体命令仍以根目录 AGENTS.md、现有指南和当前用户授权为准。

导航及入口 HTML 明确重新验证 HTTP 缓存；新 Service Worker 激活后广播自身资源版本。当前页面尚无用户操作时可自动切换到更新版本；用户已经操作后保留当前页面，在下次刷新使用新版本，不打断编辑或写操作。离线仍使用本应用当前完整应用壳，不清理配对或业务数据。
