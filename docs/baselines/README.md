# 功能基准与检查导航

这些文档描述功能本身：用途、入口、正常交互、必须保持的行为、边界和验收场景。它们不是问题清单、修复计划或某次测试报告。

首次建档：2026-10-26；核对起点：`24e4cd7` / 网页 `v250`。功能约定是检查标准，不表示该版本全部场景已经通过。具体缺陷、简化建议和修复证据继续在各自审查／验证记录中维护。

## 使用规则

1. **每次检查或修改功能前，先读本索引和对应功能基准。** 代码修改前还须遵守根目录 [AGENTS.md](../../AGENTS.md) 的修改规则。
2. 根据用户操作选择主功能；涉及其他功能的行为、数据或生命周期时，继续读取相关基准。不要只按文件名判断范围：`sheets.js`、`net.js`、`session.mjs`、`routes.mjs` 等同时服务多类功能。
3. 状态描述表达用户可观察的语义，不要求新增同名变量、框架或另一套状态管理。技术入口用于定位，检查时再核对当前源码；索引不代替 CodeGraph 的仓库导航规则。
4. 必须区分“应有行为”“当前实现”“本次已验证结果”。发现不符合基准，记录实际差异；不要把错误行为改写成基准，或把待实现事项标成已完成。
5. 功能变更获得用户授权后，同步更新受影响基准。常规修复只在必要处澄清约定；没有改变功能契约时，不为每次补丁重写文档。用户当前明确要求优先，发现文档冲突先核对来源。
6. 按修改范围选择回归，覆盖被修改及受影响的功能。保留根目录 AGENTS.md 的必要检查；不为纯文档更改运行产品测试或发布流程。
7. 验证结果写进本次测试／修复记录，记录版本、平台、场景、实际结果和证据路径。未执行、受环境限制与失败分别标明，不能仅勾选“通过”。

## 共享验收规则

- 三个 Agent 的原生数据、能力和权限存在差异，以当前适配器及实际原生界面为依据；不把一个 Agent 的按钮、模型或队列能力写成三者必有。
- 同名项目、同名会话、同文本消息要按真实身份区分。切电脑、Agent、窗口、会话或关闭功能后，旧结果不得改变新目标。
- 发起、等待、成功、失败、取消、断线、刷新恢复是不同场景；写操作结果未知不等于未执行，不应据此自动重复发送、保存、删除或批准。
- 原生页面可能虚拟化，当前 DOM 不等于完整历史；缓存预览不等于实时已连接。
- 电脑端已在运行的 Agent、终端和后台任务，应按功能既定语义保留。不能为检查或提速擅自终止真实任务。
- 真机／模拟器截图及临时证据放 `_shots/`。纯源码、隔离执行、配对浏览器和真机结果分开记录。
