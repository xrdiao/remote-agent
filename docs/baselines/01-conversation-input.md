# 01 对话输入、发送与同步

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

手机在当前电脑、Agent、窗口和会话中编辑草稿，发送给原生 Agent，并显示接收与执行状态。支持电脑端消息同步、生成中的原生排队／追加、停止、输入历史、指令和文件引用。终端命令属于独立输入目标，见 [06](06-desktop-tools-media.md)。

## 用户入口与正常流程

1. 连接并选中可用会话；输入框未就绪时不能把消息发送到其他窗口。
2. 点击输入框编辑；空闲时输入框节省空间，编辑时按内容展开，草稿不因收起而清空。
3. 输入正文，可加入附件、语音文字或原生支持的 @ 文件引用、/ 指令。
4. 点击发送，或按回车发送；Shift+回车换行。屏幕上的输入历史 ↑↓ 和键盘 Alt/Option+↑↓ 调用输入历史，普通键盘方向键保留光标／输入法行为。
5. 原生接受消息后显示相应结果；生成中根据原生能力进入队列或立即追加。消息的位置及刷新恢复按 [02](02-chat-display-history.md) 核对。
6. 停止按钮操作当前目标任务；停止、排队、追加和普通发送是不同操作。

## 行为约定

| 场景 | 应保持的行为 |
|---|---|
| 草稿 | 归属于所选电脑、会话及输入目标；切换后恢复对应草稿，不能带到别的目标发送 |
| 手机编辑 | 保持当前编辑与选择范围，旧电脑快照不能覆盖更新的文字、删除结果或光标 |
| 输入框伸缩 | 测量和提交输入框高度不造成聊天区短暂收缩／扩张；原本已到底时保持跟随，自由阅读时不因此进入跟随 |
| 输入法 | 组合输入未结束不能误发送，单独方向键不抢占正常编辑 |
| 接收确认 | 区分发送中、已接受、已入队、待确认、明确失败；输入框清空不是唯一接受证据，原生临时（optimistic）气泡也不能作为接受证据 |
| 网络中断 | 明确未发出时提示未发送并保留草稿；电脑结果未知时提示待确认，不能自动重复发送 |
| 迟到回执 | 更新原请求，不覆盖用户后来编辑的新草稿，不把已确认接受倒退为失败 |
| 同文本多次发送 | 按请求和原生消息身份区分，不能仅凭正文相同合并 |
| 排队与追加 | 遵守原生顺序、编辑／移除／立即发送能力；立即追加的消息仍是需要同步的用户消息 |
| 文档与图片 | 正文、引用和附件跟随同一个发送目标；接受或入队后再结束相应待发送归属 |
| @ 与 / | 使用当前 Agent 支持的检索及选择语义；过期查询不能恢复旧草稿、旧建议或挪动新光标 |
| Question | 当前问题的文本回答按 [04](04-native-controls.md) 提交，不能同时作为新聊天消息发送 |
| 语音插入 | 插入当前草稿的预期位置，转录结束不自动发送；录音交互见 06 |
| 发送回底 | 停止当前惯性并回到新消息处，实际到底后继续跟随；不得与自由阅读状态互相覆盖 |

“已接受”表示原生接收，不表示 Agent 已经完成任务；“已入队”表示原生队列接受，不表示已经执行。

Codex 的单次“排队／立即追加”意图交由原生提交入口处理，沿用全局默认设置；不能先人为入队，再按正文找回并转换来代替原生追加。已有队列项的立即发送须等待原生异步处理及对应用户消息回执，调用 UI 包装回调本身不等于成功。

Codex 原生输入组件的可提交状态与提交回调是提交依据，发送按钮暂时未显示不能直接判为不可提交。普通发送、排队和追加均遵守原生禁止提交及交互状态，接受结果仍由原生消息或队列回执确认。

## 同步与归属

当前选择、发送请求、草稿修订及原生消息应能相互对应。正文归一化、历史与发送回执应识别同一条原生用户消息；刷新后以原生可读取历史及已保存历史恢复，不只依赖临时气泡。后台同步不应擅自发送消息或切换用户正在操作的原生会话。

## 回归场景

| 操作 | 观察结果 |
|---|---|
| 三 Agent 各发送短消息，再从电脑端主动发消息 | 两端正文、顺序和接受状态对应 |
| 生成中排队／追加，再检查队列并刷新 | 能力符合原生；消息不丢失、不重复、不移到错误轮次 |
| 连发相同正文，接收前后继续编辑新草稿 | 请求分别确认，新草稿及光标保留 |
| 发送前断网、发送后回执前断网、恢复连接 | 提示符合已知结果，不自动重发，不永久发送中 |
| 编辑、删除、中文输入、切换会话与电脑再返回 | 没有旧值回写、重复文字或草稿串入其他目标 |
| 引用文件、附图／文档、语音插入后发送 | 目标及内容一致，附件可见且不会提前消失 |
| @、/ 快速改查询，再关闭或切换 | 建议与当前查询对应，正文及光标保持 |
| 停止任务、回答 Question、切终端输入 | 各入口只操作自己的功能与目标 |
