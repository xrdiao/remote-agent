# 04 模型、设置与原生交互

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

在手机操作当前 Agent 的原生模型、推理强度、权限和设置，查看上下文、账号额度及原生提供的价格，回答 Question、执行审批及操作原生 capacity／Retry 和其他会话动作。不同 Agent 的能力按实际原生菜单和适配器提供。

## 模型、参数与设置

1. 在当前会话打开模型／参数菜单，先展示所属选择的数据，再读取或刷新原生选项。
2. 选择模型，原生要求进一步选择强度或参数时继续对应步骤；不能把点选动作等同于切换完成。
3. 确认原生实际选择后更新手机显示；快速重开、连续切换或切会话时，旧读取不覆盖新结果。
4. 权限模式与原生审批一致；读取菜单、额度或聊天不能擅自更改权限。
5. 原生设置按文本、下拉、开关等原有控件操作，禁用项和不支持能力保持真实反馈。写入未生效不能提示成功。
6. 需要打开原生菜单／设置页才能读取时，按本次操作管理打开和退出，避免关闭电脑用户自己打开的界面。

## 上下文、额度与价格

| 信息 | 行为约定 |
|---|---|
| 上下文 | 对应当前会话，明确已用／剩余含义，缺失不显示为 0 或完整可用 |
| 账号额度 | 对应当前 Agent 账号，常规展示剩余含义；缓存、更新时间及读取失败按实际来源反馈 |
| 刷新 | 同一请求结果更新所属目标，旧会话的额度／上下文不串入新选择 |
| 可用性 | 账号用量与模型容量不足是不同原因；不能仅因“接近上限”伪造原生拒绝 |
| 价格 | 仅展示原生提供的信息，不自行估算或编造单次任务费用 |
| Fusion | 双方额度、上下文和模型按各自原生来源展示，不用普通当前会话缓存冒充双方 |

## Question 与执行审批

- 每个实际请求有独立身份；选项、自定义回答、Skip、Next／Send 遵守原生可用状态。
- 同一问题不要重复出现一栏没有独立意义的“Codex 请求”；多个真实问题则要分别保留。
- 主输入框用于回答当前问题时，提交目标、按钮文字和草稿与普通聊天区分；不会同时新发一条聊天消息。
- 原生问题被电脑回答、取消或替换后，旧手机按钮失效并更新，不把答案提交到另一个问题。
- Question 文本提交、预设选项和终端命令批准／拒绝是不同操作；任何一种不能替代另一种。
- 审批提交应有结束反馈；断线结果未知先核对原生状态，不自动重复批准。

## Capacity 与 Retry

1. 手机展示当前原生模型容量不足提示，保留与原生会话及轮次的对应；生成中和刷新恢复均应能正确展示现存提示。原生历史轮次的容量错误保留正文，不因已有后续轮次而丢弃；Retry 只来自该轮当前真实可用的按钮。
2. 原生是否有 Retry、是否在倒计时、是否可点击，以原生当前状态为准；不能凭一段错误文字造一个没有绑定的 Retry。
3. 手机手动 Retry 操作对应原生按钮；按钮失效或请求已变时更新提示，不能按旧序号改点另一个动作。
4. 自动 Retry 默认关闭，用户在子列表设置是否开启及每条提示最多 1–5 次。
5. 次数表示本错误实例实际执行的点击；关闭、切换或尚未执行的取消不算点击，新错误实例独立计数。
6. 原生自动重试和倒计时照常运行；读取、渲染和折叠内容不能中断电脑自身的重试。

自动 Retry 由电脑端按用户配置执行；手机只提交开关／上限并展示实际点击结果。计数属于原生窗口及错误实例，手机断线或刷新不重置；多个入口观察同一错误不会各自重复触发。保持原生按钮可用性及用户原有次数限制，切换目标取消该入口在旧目标尚未执行的自动操作。

## 其他原生动作

Fork、查看子 Agent、应用／撤销变更等只在原生支持且有实际处理时提供。新版 Devin 改动直接写入文件，改动栏只有 Dismiss（IDE）／Mark as seen（Agents），没有逐文件接受／拒绝：手机隐藏逐文件按钮，“全部接受”入口按电脑端实际按钮名执行该清除动作。动作名称、目标和执行结果对应，不把无响应入口留作可用功能。复制、文件查看和变更列表分别沿用 02、06 的语义。

Codex 完成回复的 Fork 即使收在原生“更多”菜单中或该轮未挂载到 DOM，也应对应到该轮真实可用的分支操作；只读提取不为搜寻按钮而反复打开／关闭菜单。Fork 后的新会话保留原生分支内容及项目归属，可以切走再切回。完成回复的动作缓存与 capacity 的 Retry 当前状态分别处理，不能用缓存恢复已失效的 Retry。

## 回归场景

| 操作 | 观察结果 |
|---|---|
| 三 Agent 打开模型／参数，连续选择并快速重开 | 选项、当前值、完成反馈与原生一致，无永久等待 |
| 切会话／窗口／电脑时菜单读取尚未返回 | 旧结果不显示到新目标，不操作旧目标的新控件 |
| 改开关、文本和下拉项，原生控件变化或不可用 | 真正生效才确认，不支持有明确结果 |
| 刷新上下文、额度与价格，读取失败再恢复 | 缓存及来源明确，不把缺失显示为实际用量 |
| Question 选项、自定义回答、主框回答、多步骤与 Skip | 目标正确，同一请求不重复，原生变化可结束旧卡片 |
| 执行审批允许／拒绝，电脑先处理或断线 | 不误提交聊天、不重复批准、不留下永久禁用卡片 |
| 原生 capacity、倒计时、手动 Retry、自动开关与次数 | 提示绑定正确，实际点击计数，电脑原生重试不受干扰 |
| 原生动作更新、文件变更或子 Agent 入口 | 点击实际有效；旧按钮不变成其他动作 |

本次建档未执行原生菜单、审批或 Retry，不改变任何账号和原生设置。

Codex 普通会话的思考强度包括当前模型原生能力中支持的 Max；不为不支持的模型伪造选项。原生模型已列出 Max 时直接选择；支持但隐藏时才通过原生 Configuration 的 Available reasoning efforts 启用，再调用原生模型／强度选择并读回实际值。该开关属于电脑端 Codex 设置，会同时影响其原生菜单；保留其他强度，包括 Ultra。设置页初始化沿用同一次等待预算，响应请求取消，失败后结束等待并返回原生标签页。

模型、强度和 Fast 菜单从原生参数读取选项、当前值及可用性，参数读取不依赖完整聊天解析。未命中所属选择的菜单缓存时立即展示加载态；Fast 切换期间显示等待，原生状态读回后才改变开关，失败恢复可操作状态。菜单回包仍遵守原请求及项目／会话归属。

Codex 强度的选项、选择动作与成功回读使用同一原生控件来源；不能通过已存在的一种控件完成选择后，只向另一种控件查询确认。读取未确认与原生明确拒绝分开反馈，不自动重复选择。

Devin 本地会话的模型家族与变体沿用原生模型配置；Cloud 首页使用其原生已启用 capability 集合与选择回调，不把本地配置缺失当作 Cloud 没有模型。只提供原生实际支持的选项，不混用 RA Fusion 的编排状态。原生服务拒绝初始化时如实显示不可用与错误，不能制造模型选择成功。
