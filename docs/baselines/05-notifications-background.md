# 05 通知与后台

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

手机在没有观看对应会话时接收任务完成、等待确认等提醒，点击进入正确电脑、窗口和会话。支持当前部署提供的网页提醒、Web Push、Android 后台事件连接、iOS APNs 与实时活动；能力依赖系统权限、安装方式和服务配置。

## 用户流程

1. 从菜单开启通知，按当前入口申请原生／浏览器权限并登记相应通道。
2. 查看当前通知权限、连接或服务状态；不支持时明确说明，不伪装已启用。
3. 任务运行、待确认和完成按电脑原生会话状态产生对应事件。
4. 手机前台、后台、关闭、断线及恢复时，按可用通道接收；提醒能力不依赖手机页面持续轮询。
5. 点击提醒才执行定位；普通接收提醒不得擅自切换用户正在阅读的会话。
6. 关闭通知或撤销入口后结束相应授权和订阅效果，保留其他入口独立设置。

## 事件与内容

| 场景 | 行为约定 |
|---|---|
| 工作中 | 对应实际任务和开始时间；只读快照或切窗口不冒充新任务 |
| 等待确认 | 对应当前真实问题／审批，正文来自该请求；问题已处理就不继续发旧提醒 |
| 完成 | 来自相应轮次的真实结果，不能拿旧回复、其他项目或其他会话正文代替 |
| 同轮重复快照 | 应用层不因重复读取或通道重复登记制造两次同一提醒 |
| 同文本新轮次 | 仍是新事件，不因正文相同被错误去重 |
| 旧轮晚到 | 不得倒退新轮状态、复活旧问题或重新产生旧完成提醒 |
| 当前正在观看 | 按既有前台会话规则避免不必要提醒；后台／已关闭不误判为仍在观看 |
| 断线恢复 | 核对仍运行状态及可补发事件，不复活已结束计时；不声称外部系统必能送达所有消息 |
| 任务停止／窗口消失 | 正确结束工作展示；普通停止、待确认和完成保持不同语义 |

事件应携带可解析的来源身份及轮次／请求归属。投递渠道负责投递及自身生命周期，不能各自通过“最新一段文字”重新猜目标。

通知状态观察复用中继的原生窗口数据源；事件去重、正文归属和投递仍独立按本基准处理。后台预加载和其他手机的数据订阅不代表当前入口正在观看，不能因此压制通知。网页显示概览层（[10](10-overview.md)）时同样视为未观看对话。

## 点击与通知内操作

- 目标包括电脑、Agent、窗口和会话；当前手机连接其他电脑时仍要定位到通知来源的已配对电脑。
- 未就绪时保存本次待定位目标，准备完成后处理；成功处理只消费一次，重连不再次跳旧目标。
- 来源入口已撤销、窗口已关闭或会话不存在时显示真实结果，不随机打开相似名称会话。
- 原生支持的通知回复、选项或接受变更绑定原始请求；过期动作不能提交给当前新问题。
- 通知载荷不应成为跨入口搬运长期配对凭据的方式；配对规则见 [08](08-connection-pairing.md)。

## 平台约定

| 平台能力 | 验收边界 |
|---|---|
| 网页／Web Push | 分清页面内提示、系统通知权限及后台推送；按浏览器和安装方式实际验证 |
| Android | 后台服务独立处理事件、重连、通知和动作；页面恢复不能重复触发已处理通知目标 |
| iOS APNs | 注册、权限、推送服务与安装构建有效；网页发布不等于原生推送扩展已经升级 |
| iOS 实时活动 | 工作、等待、进度和终止按真实状态更新；窗口消失也能结束，转为等待不误结束 |
| 多入口 | 每个入口授权、订阅和撤销独立；设备分组不共享凭据或虚构额外用户 |

## 回归场景

| 操作 | 观察结果 |
|---|---|
| 三 Agent 完成／待确认，重复读取同轮状态 | 正文与来源正确，同一事件不因本软件重复判断而重复提醒 |
| 连续两轮输出相同正文，旧轮快照晚到 | 两轮分别识别，旧轮不覆盖新轮 |
| 前台看本会话、看别的会话、后台、关闭页面 | 提醒符合观看状态及平台能力 |
| 断线后结束任务，再恢复后台连接 | 已结束不继续工作计时，不回放错误旧状态 |
| 电脑 A 提醒到达时手机在电脑 B | 点击回到 A 对应窗口／会话；未配对或失效有真实反馈 |
| Android 热／冷启动点通知，之后切会话再重连 | 待定位只消费一次，不再次跳旧会话 |
| 原生通知回复／选项，电脑已先处理 | 目标有效才执行，失败不假成功 |
| iOS 工作转等待、完成、停止或窗口消失 | 实时活动阶段及终止正确 |
| 关闭通知、撤销入口或拒绝权限 | 状态与后续行为一致，其他入口独立 |
