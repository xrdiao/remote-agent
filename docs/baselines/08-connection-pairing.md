# 08 连接、加载、配对与设备

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

让手机找到当前电脑中继，完成独立入口配对和认证，发现／启动 Agent，绑定实际窗口及会话，处理加载、重连、电脑切换、设备管理和两步验证。本类也记录各功能共用的请求归属语义。

## 地址发现与正常进入

1. 固定入口或当前页面读取电脑地址记录，已有配对优先复用仍有效的地址并更新目录；隧道恢复由 09 的启动服务负责。
2. 用当前入口自己的令牌和密钥证明连接中继；缓存预览可以先展示，但认证和目标未就绪前不允许误发。
3. 加载页固定展示 Cursor、Devin、Codex 三项及实际连接状态；安装检测与启动偏好不把加载项擅自变成另一套列表。Android 从概览卡片或通知打开指定会话（`directOpen`）时跳过加载页直接进入，直到该会话首屏就绪、读取失败或离线（`directDone`）；离线仍显示连接失败页，读取失败显示会话内重试。
4. 分别判断连接认证、窗口发现、当前选择绑定和首屏可读；端口打开或“有窗口”不等于聊天输入和项目会话可用。
5. 恢复上次电脑、Agent、窗口和会话，目标在电脑端不是最前窗口时也按身份绑定；新启动目标完成必要初始化后读取项目／会话。
6. 达到当前选择的进入条件即进入，动画和隐藏详情补全不反向阻塞；部分失败按用户的“先进入／部分失败直接进入”偏好处理。
7. 无窗口、读取失败、登录／信任未完成等给出当前阶段和可用重试入口；不能永久卡在无结束状态的加载页。

## 启动与重连

| 场景 | 行为约定 |
|---|---|
| 手动启动 Agent | 操作明确软件，展示启动结果；不关闭已运行 Agent，不把进程存在当作完整初始化完成 |
| 自动启动偏好 | 仅启动用户选择且当前支持的目标；不因取消偏好终止已运行任务 |
| 启动后绑定 | 确认实际原生界面和会话能力，避免绑定错误窗口／错误 iframe |
| 断线 | 显示连接状态，结束本连接的等待语义；不声称电脑已经没接收写操作 |
| 重连 | 重新发现、认证和绑定当前选择，确认首屏；不复用旧连接的“已就绪”结论 |
| 电脑切换 | 草稿、窗口、会话、元数据、权限及迟到结果按电脑隔离 |
| 部分可用 | 进入可用功能后保持正常操作，失败 Agent 可单独重试 |
| 超时 | 使用该操作的等待预算并反馈所处阶段；重复内部读取不能形成无限等待 |

## 配对、扫码与授权

- `npm run pair` 提供当前支持的二维码、链接、手动码和电脑审批窗口。打印链接不等于批准成功；仅终端使用不能假装具备不存在的审批能力。
- 电脑配对会话当前 3 分钟有效，核对入口地址与六位验证码后允许／拒绝；关闭、取消、过期仅结束本次待批准申请，已有授权保留。
- 已配对入口的“添加入口”提供二维码和链接；新入口申请、旧入口核对批准后获得独立凭据。邀请有独立有效期，不等于永久公开配对。
- 浏览器相机、相册识别和手动输入最终走同一配对规则；扫码失败可以退出或使用已有替代入口，不把识别成功当成认证成功。
- HTTPS／安全上下文是网页密钥能力的前提；普通手机 HTTP 局域网页面不得被描述为已经可完成密钥配对。电脑 localhost 审批页按其实际环境处理。
- 浏览器、不同来源和原生壳使用各自已有的凭据／签名能力；复制令牌、同名手机或设备分组不替代授权。详见 [连接与安全](../security.md)。

## 设备、电脑及 2FA

设备列表按明确归属分组，每个入口的名称、配对时间和最近连接等信息保持真实含义。分组、重命名、移动和移除不合并凭据；移除入口断开相应连接，不停止电脑 Agent／终端任务。

电脑列表的分组与已配对入口分组是不同列表。跨来源切电脑只携带允许公开的电脑书签和入口地址，目标来源使用自己的授权；原来源授权保留。

两步验证遵守当前配置：新配对核验，以及配置要求的周期性重新验证。失败、取消、恢复、撤销均有明确状态，不用清空全部配对作为普通重连办法。

## 共享请求与切换语义

请求属于发起时的电脑、Agent、窗口、会话及本次选择。读取可以因切换而取消，旧结果不更新新目标；写操作的真实原生结果仍须按原请求处理，不能因页面切走就假装没执行。

成功、失败、取消、超时、断线、未发出各有结束结果。超时和断线可能只意味着结果未知，不自动重发消息、保存、删除或审批。已完成某功能的状态不能被无关目录刷新或旧回包改回等待。Agent、窗口、项目和会话切换的提示按本次操作对应，不因共用项目绑定流程而把切换会话报告为切换 Agent 或打开项目。

## 回归场景

| 操作 | 观察结果 |
|---|---|
| 新配对、二维码／相册／手动码、邀请批准和拒绝 | 验证码及目标对应，状态结束明确，凭据独立 |
| 申请取消、过期、查询临时失败后恢复 | 未批准不生效，已有授权保留，仍可操作当前流程 |
| 三 Agent 均可用、部分失败、均不可用与新启动 | 固定三项真实状态，单项重试和先进入符合选择 |
| 上次目标在电脑后台、窗口多、原生加载较慢 | 恢复正确目标，成功／失败有出口，不绑错窗口 |
| 网络断开、旧地址失效、新地址发布、重新认证 | 连接恢复可解释，原选择与配对不丢失 |
| 反复切 Agent／项目／电脑时旧读取未完成 | 旧任务及时结束其影响，新目标功能正常 |
| 设备归组、改名、移除、电脑分组及跨来源切换 | 公开书签与凭据边界正确，其他入口／任务保留 |
| 开启／周期 2FA、错误码、取消和重新验证 | 符合当前规则，不绕过校验或假连接 |
| 加载时并行收到聊天、菜单、历史或写操作回执 | 按所属请求处理，不能因无关结果进入错误就绪状态 |
