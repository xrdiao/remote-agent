# 02 对话展示、滚动与历史

[功能基准索引](README.md) · 首次建档：2026-10-26 · 核对起点：`24e4cd7` / `v250`

## 功能与范围

展示当前会话的用户消息、Agent 回复、工作说明、思考、执行工具、任务及子 Agent 信息，提供复制、历史分页、本地历史搜索、上下轮定位与底部跟随。数据接收、可见内容更新和用户滚动分别遵守当前选择与交互。

## 展示行为

- 保持原生消息的角色、正文和顺序。生成中消息可以更新，完成后的用户／回复内容不因虚拟列表移除而凭空丢失。
- Markdown、代码块、数学内容、文件引用与图片保持相应展示和入口；用户正文、文件及名称不被界面翻译替换。
- 缓存预览、加载、登录和真实子 Agent 的身份分别展示；暂时只读不等于子 Agent，返回主对话入口只用于真实子 Agent 场景。
- Devin 用户消息的小箭头和“回到这里”在气泡右侧纵向排列，时间与复制保留在气泡下方。
- 思考、工具详情和长输出按原生能力展开；加载详情不能把任务状态改成已完成或吞掉审批、错误、capacity 提示。
- “显示执行指令”按 Agent 记住选择；关闭后按既有完成态规则隐藏执行／读取记录，保留思考、工作说明、结果、失败和待审批，不删除历史。
- `Copy message` 只出现在已完成回复的适当位置，复制该回复正文；原生轮次未挂载到 DOM 不影响该入口及正文复制。用户消息自身的复制与代码块复制保持各自语义。
- 文件变更入口要有实际动作；没有可用功能的动作不得显示为可操作成功。Question、审批和 Retry 的操作约定见 [04](04-native-controls.md)。

## 滚动与定位

| 场景 | 应保持的行为 |
|---|---|
| 首次进入或切换会话 | 默认展示所选会话最新内容，到达底部后才跟随；不能默认停在最早消息 |
| 自由阅读 | 用户离开底部后，新正文、工具加载、布局和按钮文字变化不得自动拉回底部 |
| 手动滑到底部 | 真实到达底部后识别为到底，清除最新／有新消息提示，并随新增内容保持底部 |
| 向上离底 | 退出底部跟随，尊重触摸、滚轮、滑块及惯性产生的位置 |
| 点击最新／有新消息 | 在任意时机立即停止惯性，回到最新内容；实际到达底部后开启跟随 |
| 发送消息 | 按 01 的发送回底要求执行，后续跟随不被旧自由阅读状态覆盖 |
| 点击上下轮 | 立即停止惯性，找上一轮或下一轮，快速定位一次；不持续锚定该轮 |
| 上下轮导航外观 | 上下箭头共用最外层胶囊背景和阴影；内部按钮不分别加边框，不加分隔线；点击、拖动与显隐行为保持 |
| 拖动滑块 | 按用户控制展示位置，不被后台详情读取或旧定位任务拉走 |
| 流式增长 | 已跟随时保持底部；自由阅读时不创建“用户到底”的意图 |
| 输入框／可视区域变化 | 已跟随时根据最终可视高度保持底部，不能因高度测量的中间布局丢失位置；自由阅读不自动进入跟随 |
| 惯性结束 | 停在滑动结束位置，不执行旧阅读锚点或旧补偿 |
| 程序定位 | 不能被重新识别为用户触摸／惯性，再触发另一套定位 |

不引入持续阅读锚定。历史插入允许一次性调整，见下一节；它与跟随底部、一次性上下轮定位是不同目的。

显示尾窗只限制初次绘制，不在自由阅读时随新快照裁掉已展示的头部。当前阅读区域及其上方的正文补全、缩短和新插入明细先保存在数据缓存，按显式展开、历史加载或回到底部提交；不在惯性结束后补拉旧位置。状态及操作按钮单独更新，不为这些变化重建正文。回到底部后继续显示最新内容并回收额外保留的行。

## 历史读取与本地记录

1. 在顶部继续向更早内容滑动或点击加载更早消息，触发当前会话的历史读取；不能要求用户先结束 Agent 生成。首次从已加载消息的最早顺序向前读取，后续沿服务端分页游标续读；不能以补当前范围的明细代替向前分页。
2. 顶部手势与滑块操作保持区别，避免只因接近顶部就反复发起分页。
3. 同一次分页只发起一个有效请求；未发出、失败、取消、断线和完成都有可见结束结果。
4. 历史合并按原生身份及顺序去重，不以正文相同删除合法重复消息。当前 DOM 未挂载不代表原生历史不存在。
5. 插入前后只做一次必要的位置调整，使用户继续看到插入前阅读的内容；不把窗口留在新的最顶端，不延迟到惯性结束后拉回。
6. 新消息与较早历史分别接收，不能以加载历史为理由长期停止最新消息同步。
7. 本地缓存、搜索、删除本地历史使用电脑和会话归属；缓存预览不能冒充新电脑的实时内容，清理本地缓存不删除电脑原生会话。

Codex 历史分页使用同一份原生会话快照确定轮次、内容及结束状态。向前加载轮次与补齐轮内明细分别完成，不以概要或延迟更新的界面派生数据代表完整历史；等待原生已有分页结束后再发起本次分页。历史插入仍复用一次性保位，不增加阅读锚定。

## 回归场景

| 操作 | 观察结果 |
|---|---|
| 竖屏／横屏，触摸／滚轮／滑块浏览 | 各方向可滑动，惯性不被无关更新中断，不闪回旧位置 |
| 生成正文、工具读取、图片加载时向上阅读 | 不误回底，不持续抖动，停下后位置稳定 |
| 手动到底与主动离底，连续等待新内容 | 跟随只按真实用户行为切换，最新提示正确 |
| 惯性中点击最新或上下轮 | 最新立即回底；上下轮仅定位一次；没有旧任务拉回 |
| 生成中到顶继续拉动及点击更早消息 | 两个入口可加载，原阅读内容保持，实时内容继续同步 |
| 分页失败／断网，再恢复、重试或切换 | 无永久加载占位，旧分页不插入新会话 |
| 折叠思考／工具、切执行记录显示、复制回复 | 内容与动作对应，隐藏记录不丢失必要信息 |
| 刷新、搜索本地历史、查看未挂载轮次 | 消息顺序、会话归属与记录恢复正确 |

## 关联检查与维护

发送读 [01](01-conversation-input.md)，切换读 [03](03-projects-sessions-windows.md)、[08](08-connection-pairing.md)，原生动作读 [04](04-native-controls.md)，文件／图片读 [06](06-desktop-tools-media.md)。不以删除历史保存、取消惯性或恢复阅读锚定来达成局部检查。

本次建档未执行上述功能回归；不能把本文当成真机滑动通过记录。

Codex 助手正文按当前会话的 Agent 身份选择渲染器，不要求消息或旧缓存具有 src 字段。读取端用明确的正文格式区分原生富文本 HTML 与 Markdown 原文；旧缓存没有格式标识时从完整原文渲染，不按包裹标签猜测格式。回复显示保留已确认的原生富文本；原生正文未挂载时从完整 Markdown 原文渲染标题、列表、表格、代码及数学公式。工作过程与思考正文使用同一 Markdown 渲染器，保留折叠及生成状态，正文未变化不重建其节点。工具命令与日志仍按字面展示。未挂载读取不得用相同原文的纯文本回退覆盖已确认的富文本。复制仍使用原文，文件引用仍进入原文件预览，Copy／Fork／Retry 保持各自动作及目标。

首屏内容与补充信息的等待必须响应导航取消和窗口解绑；首屏复用后台读取时同样适用。旧读取结束不得清除新读取的归属，取消后的旧读取不能继续补发或重试。

耗时按所属会话的实际运行状态计时。原生已空闲但没有提供结束时间时固定本次观察到的结束时刻，后续相同轮次更新不能让计时继续增长；点停止本身不能冒充已经空闲。

普通 Codex 会话的首屏、实时更新及向前分页共用原生顺序与同一范围读取器。先选择本页原生记录，再读取／规范化正文和补充已挂载的富文本及动作；默认页预算为 80 条可见记录，完成后隐藏的执行记录不占该预算。单条用户消息与回复保持完整。页首可以附带所属用户提问，但分页游标只表示实际覆盖范围，不用附带提问的顺序代替游标。历史是否结束以同一份原生规范历史的完成状态为准，容量错误的空轮次也须保留。

切换只清除在途读取、当前草稿／控件和运行状态，不清空其他会话的已完成正文缓存。中继沿用有界会话缓存，正文可复用，当前运行态、排队、Question、审批及 Retry 必须来自当前原生快照。实时尾页不删掉手机已展开的历史与正在阅读的内容；历史插入继续只做一次必要的保位。

Devin 新版 transcript 的会话身份从所属原生上下文读取，不能以空的输入焦点或显示标题替代。折叠工作记录中的思考、命令及工具调用属于正文数据，读取不要求在电脑上展开。Devin 原生错误横幅保留当前会话归属并展示其原文；发送接受、成功生成和原生失败分别记录，不把接受确认当作生成成功。
