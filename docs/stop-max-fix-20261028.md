# 停止发送与 Codex Max 修复记录

版本：网页 v291；日期：2026-10-28；系统：Ubuntu。保留开始本轮前已有的本地修改，仅处理本轮停止行为、相关耗时和 Codex Max，不修改或测试 Fusion。

## 最终行为

- 普通 Agent 确认停止后，清理当前手机待确认的发送记录，保留可恢复草稿和电脑端真实聊天。
- 中继取消本连接中属于当前选择的发送等待及后续步骤，包括尚未执行的排队发送；停止请求直接执行，不排在发送后面。
- 通过既有窗口处理入口检查归属和占用，然后检查当前原生停止按钮。按钮存在且可用就点击一次，没有则不操作，不改用快捷键、不重复点击。
- “已点击停止”只表示执行了点击。原生仍在生成时继续显示运行状态和耗时；收到原生空闲后固定耗时。
- Codex 思考强度列表增加当前模型原生支持的 Max。选择时启用电脑端原生隐藏选项，使用原生选择回调设置，并读回实际强度。

取消等待不能撤回已经交给原生执行的提交；已接收消息以原生结果为准。按用户要求，没有可用原生停止按钮时不额外补发停止，也不把手机强制显示成空闲。

## 根因与修改

| 功能 | 根因 | 修改位置与处理 |
|---|---|---|
| 停止晚于发送 | 普通停止请求与发送串行；发送读取、提交或等待未结束时，停止没有执行机会 | `server/routes.mjs` 将普通停止接到即时入口，复用 `Session.handle` 的窗口处理但不等待焦点锁；Fusion 原入口保留 |
| 停止后旧发送继续 | 本连接没有当前选择的发送取消生命周期，手机待发送记录仍存在 | `server/ws.mjs` 按请求登记取消信号，停止时取消所属请求；原队列清理取消项，CDP 等待及后续命令响应取消。`composer.js` 清理当前待发送项；`net.js` 区分主动取消回执，避免错误提示覆盖停止状态 |
| 按钮不在时使用其他停止方式 | 原停止实现还包括快捷键和等待流程，不符合本轮明确要求 | `server/agent/chat.mjs` 新入口只检查并点击按钮。`server/page/devin.js` 复用既有定位逻辑执行一次原生点击，禁用按钮不点击；Codex 首轮按钮识别不再依赖消息轮次已挂载 |
| 电脑已停但手机耗时继续 | 原生空闲时仍可能提供开始时间而没有结束时间；手机每次归并都用该空结束时间覆盖时钟 | `app/js/chat.js` 收到空闲后固定结束时间，同一轮后续更新保留该时间；原生仍忙时不伪造停止 |
| Max 缺失 | 原生可见菜单过滤了隐藏强度，不能代表模型完整能力 | `server/page/menus.js` 保留现有可见选项，从当前主机、当前模型原始能力补充 Max；不支持就不提供 |
| Max 仅展示却不能生效 | 原生隐藏偏好与聊天菜单缓存可能不同步 | `server/apps/codex.mjs` 复用原生 Configuration → Available reasoning efforts 启用 Max 并退出临时界面；`server/agent/menus.mjs` 选择后读回实际值。保留模型身份与其他强度，包括 Ultra |
