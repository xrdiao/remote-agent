# RA v518 产品界面

底部导航为「概览」「工作」「设备」。概览沿用 v517 的电脑选择器、双列卡片、电脑分组、状态排序和快速回复。项目与收藏进入概览筛选条。搜索按会话标题、项目、Agent 或电脑名称筛选，并保留空闲与不常用分组的展开状态。选择项目后按返回键，可恢复项目筛选和搜索词。批量管理支持跨电脑选择和收藏。搜索收窄范围时，工具栏清除范围之外的选择并显示提示。删除或归档确认列出每个会话的标题、电脑名称和 ID、Agent 及线程 ID。确认后重新核对范围，逐项处理仍在所选范围中的目标。

工作页有「关联操作」和「自主编排」两节。关联操作按发起电脑和原生会话读取 RA Core 持久日志。工作台沿用 Fusion 的创建、配置、会话绑定、任务及原生交互。前端仍以 `fusion` 标识该导航和协议，`projects`、`favorites` 继续作为 `ovS.level` 的值供概览、历史和旧版 localStorage 使用。普通 Agent 会话继续直接从概览打开。

设备页显示当前范围的配对连接，以及所选发起中继返回的本机能力和远端工作区登记。授权核验时间来自 B 返回的签名回执，后续请求仍由 B 核验授予。快照读取失败时清除当前激活状态。电脑互控和手机控制从设备页显示的同一台发起电脑进入。手机选择器锁定该电脑，并显示电脑和配对设备的 ID。打开选择器只向该电脑读取手机列表，使用本机或请求控制都需要另行点击。

## 原会话与远端回执

1. 在概览展开本机 Agent 会话卡片。快速回复入口确认原生线程就绪后，打开「跨设备操作」。
2. 前端固定电脑、配对、窗口、线程及导航代次，从签名快照中查找与电脑、设备、Agent 和线程唯一匹配的 OriginRef。匹配缺失、重复或会话切换会阻止提交。
3. 选择已登记的 B 电脑、工作区和「列出工作区文件」。显式点击「核验并激活」后，A 请求 B 的可验证授权回执。界面发起的激活有效期为五分钟，用量为一次。已存在的激活按实际动作、到期时间和剩余用量显示。
4. 另行点击「执行示例 · 列出文件」，只读取所选工作区的根目录列表。界面显示服务器返回的状态、原会话、目标、条目数和目录引用。首次响应的文件名只显示在当次面板。失败和不确定结果按实际回执显示，用户可到工作页核对。撤销激活走同一原会话的签名请求。
5. 读取与激活、试读、撤销都通过 `entryHeaders` 签名。签名完成后、发送前再次核对面板、电脑连接、配对设备、OriginRef 和线程。关闭面板或切换会话会中止读取与待发送的请求。已发出的请求继续接收原回执，同一原会话在等待期间只能有一笔提交。离开面板后，页面仍显示该请求的原会话、目标及状态。如果试读未收到有效回执，本页面会阻止用同一份激活再次提交，可按原操作 ID 到工作页核对。

RA Core 路径只展示和调用确定性的设备操作。普通 Agent 会话仍运行原有的提示、模型及工具。电脑互控保留既有的独立工作区流程。

关联操作使用 `GET /api/ra-core/work?originId=…` 的操作记录，其中含关联所需的原会话、远端工作区和引用。原会话选择器合并中继当前快照与此配对浏览器曾调用或读到记录的 OriginRef。浏览器仅保留最近 100 个原会话身份，按发起电脑和配对设备索引。关闭线程后，工作页仍可查询拥有已知 OriginRef 的历史。v1 接口按单个 OriginRef 查询，历史首次发现取决于已有索引或中继当前绑定。已落盘的回执以中继日志为准。

快照在打开工作或设备栏、切换电脑或绑定、恢复可见及手动刷新时请求。每次只读取一个来源中继，短期复用同连接及会话的快照。工作页可见且所选原会话有登记中或执行中的操作时，每五秒刷新一次所选会话的回执。离开栏目、切换操作记录来源或关闭跨设备面板时取消相应读取。

由协调方在后端就绪后，在既有配对 Chrome 9335 与隔离 Relay 3949 上执行。完整浏览器流程从「概览 → 全部」开始，保留现有共享测试辅助函数的初始导航约定。

- 使用 `overview.levels`、`overview.filters`、`overview.batch-search`、`overview.ra-devices`、`overview.ra-work`、`overview.ra-origin` 核对导航、筛选、批量确认、工作区状态、原会话和回执。两台电脑在线时运行 `overview.ra-phone-scope`，验证设备页来源与首个签名手机列表请求一致。
- 用实际有登记和授予的 B 验收激活、只读试跑、回执恢复和撤销。再用离线 B、已撤销的工作区授予以及 A 的会话切换验证阻塞。没有对应设备或操作记录的样本只覆盖已实际观察到的状态。
- 按受影响范围复查 Cursor、Devin、Codex 的概览卡片、会话、项目及文件入口，并在自主编排中完整执行一次工作台流程。检查 500×757 深色视图、横屏、软键盘和 v517 → v518 的 PWA 更新。真机状态以实际验收为准。

## v521 · 原会话显式文件与终端操作（2026-11-23）

在 v520 的只读「列出根目录」示例基础上，`app/js/ra-core-ui.js` 使用远端已登记工作区返回的真实 capability/actions，显示 Peer Workspace v2 的九类动作：列目录、读/建/存文件，开/读/发/中断/关终端。文件路径仍须是工作区相对路径，写入正文与终端输入经同一生产后端动作参数规则校验；读取文件正文及终端输出只显示在首次调用回执面板，不写入概览/持久操作摘要。新增输入框样式在 `app/app.css`。PWA 资源版本改为 v521，更新 `app/index.html`、`app/sw.js`、`app/js/core.js` 的同一版本号。

操作继续遵守**选定原会话 → 选定 B/工作区/动作 → 独立核验激活 → 单次提交**；UI 默认不开启动作，不给普通 Agent 增加动态工具或 Prompt。每次激活仅授权一个选定动作、最多一次、五分钟；操作 ID 仍由前端签发，后端持久化并执行签名认证、B 端授权、相对目录检查、重试去重和未知回执处理。UI 在发送前重新核对当前 OriginRef、目标、动作与输入，发送后即使弹层关闭仍保留原请求回执，不在结果不确定时自动重发。终端文本按原样发送，用户要提交命令需包含换行。

注意：以上是**用户手动显式 RA Core 操作**，并不等于普通 Codex 已具有按需动态调用 B 的原生工具。当前 Codex 的 `dynamicTools` 仅在新线程 `thread/start` 使用；普通旧会话无全局注入。此 M3 项目仍需独立设计、原生执行和生命周期验收。QA 当前第二台机器的工作区未登记/中继离线，因此本轮无法测试真实 A→B 写文件与终端回执，不能把界面与本机输入测试视为真机双机成功。
