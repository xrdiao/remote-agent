# 电脑确认、手机展示修复记录（2026-10-29）

最终交付网页与缓存 `v302`。本轮按用户授权修复电脑端业务确认的归属及生命周期，不改普通发送／排队／立即追加、停止、原生审批、批量取消的操作语义，不改其他 Agent 适配器，不测试或修改 Fusion。

用户要求先完成全部修改，再统一验收；验收发现的相关缺口继续修复。开始时已有本地文档、截图及其他未跟踪产物均保留，没有提交或推送 master/debug。

## 实现

| 功能 | 修改及保持的边界 |
| --- | --- |
| 请求与结果 | 新增 `server/operations.mjs`，按独立配对入口及请求 ID 保存电脑执行结果，身份固定在原电脑／Agent／窗口／会话。重连恢复结果，同一请求 ID 不重新执行。复用既有回执，不另写手机原生确认。 |
| 发送确认 | Codex 的原生接收观察由共享原生窗口管理，回调恢复所属电脑端操作上下文；手机 Session 销毁不再取消已提交消息的观察。普通发送、Queue、Steer 继续走原来的对应入口。 |
| 停止 | 手机仍按原要求清理待发送展示；电脑取消尚未提交的发送步骤，已提交消息继续按原生事实结束确认。停止仍只检查／点击原生停止按钮，不以点击成功伪造生成结束。自动 Retry 尚未执行时可被停止取消，不能阻塞原生停止操作；已开始的点击完成后再检查停止按钮。 |
| 自动 Retry | 移除手机的触发定时器、执行计数和在途动作集合。手机提交原有开关及 1–5 次上限，电脑按原生窗口／错误实例调度、计数，同一可用按钮状态不因重复快照或多个查看入口反复点击。保持倒计时、手动 Retry、目标切换取消及默认关闭。 |
| 模型、队列、问题、会话管理 | 原生执行与回读方法保留，结果改由电脑端记录和恢复；手机按原请求结束等待，再决定是否更新当前界面。旧模型结果不修改新页面，批量最终进度可在切换后结束原任务；归档的缓存失效事件不被当前页面过滤掉。 |
| 批量管理 | 断线仍取消尚未开始的剩余删除／归档，不擅自改成后台继续删除；已经完成的结果和最终取消进度由电脑保存，手机不丢弃原请求 ID。 |
| 文件保存 | 电脑写入完成才确认；手机保留断线时的保存等待及编辑内容，移除手机 30 秒推断失败的计时。保存尚未开始便断线时明确回传 `saved` 失败，不能只发通用错误而留下永久等待。 |
| 子 Agent 停止 | 手机先显示正在停止；电脑原生操作返回后提示已点击停止，不在发指令时提前声称子任务已经停止。 |

正在执行的写操作保留必要的电脑端上下文，手机连接关闭后完成收尾才释放。展示读取和连接订阅仍按原规则取消，未将所有只读请求改成后台业务。结果记录位于中继进程内，保留待确认请求及最近 100 个已结束请求；本次不实现跨中继进程重启的未完成请求恢复，不会据未知结果重发写操作。

主要源码：`server/operations.mjs`、`server/ws.mjs`、`server/session.mjs`、`server/native-windows.mjs`、`server/apps/codex.mjs`、`server/agent/chat.mjs`、`server/agent/session-actions.mjs`、`server/routes.mjs`；前端 `core.js`、`net.js`、`composer` 现有回执消费、`chat.js`、`history.js`、`sheets.js`、`files.js`。`composer.js` 本轮没有修改。

## 验收与修正

### 完整链路受控检查

`_shots/desktop-confirmation-fix-20261029/contracts.json` 共 16 项通过。使用实际 WebSocket 调度源码、操作记录、Session 释放及共享窗口接收逻辑，在隔离传输／原生数据下检查：

- 断线后仍能认领原生消息，重连恢复真实身份，同 ID 不重发；不同入口／电脑隔离。
- 停止保留已提交回执，取消尚未提交的步骤；排队中的自动 Retry 不阻塞停止。
- 已开始的保存断线后继续完成，未开始的保存断线后明确失败。
- 模型、队列、问题／审批、改名和子 Agent 操作结果恢复。
- 批量断线取消剩余动作，保留部分成功及最终进度。
- Retry 在没有手机执行器时工作，多入口不重复点击，遵守次数上限及关闭／切换。
- 跨页面的模型和批量回包结束原请求，归档缓存失效照常处理，旧页面提示不覆盖当前界面。

### 既有配对浏览器

复用原 Chrome，未新增配对。`browser.json` 11 项通过：公网资源与本地一致、刷新及缓存生效、独立项目绑定、真实 Codex 发送期间断线后确认且原生只收到一条消息、真实 Queue 编辑／删除、原生停止、模型原生回读、Editor 保存丢失即时回包后重连恢复、真实会话重命名、Retry 及原生页面未刷新。

Retry 使用隔离原生页面中的受控容量横幅及倒计时按钮，走实际提取、原生点击、电脑调度和手机回包：自动次数达到 2 后停止，手机断线期间仍执行，随后手动 Retry 可点击。此项不是上游自然发生的容量故障。

`paired-ui-contracts.json` 最终 v302 的 4 项受控回执检查通过：问题卡片结束等待、其他页面的模型结果清理原请求且不改变当前提示、批量取消后接收最终进度、子 Agent 停止提示等待电脑结果。没有执行真实用户审批、删除用户会话或停止真实子任务。

原生链路检查在 v301 完成；v302 仅收尾修正跨页面结果消费、模型／批量本地等待及缓存版本，针对这些改动补验受控链路、上述四项配对 UI 和最终连接恢复，没有重跑未受影响的已通过场景。

### 统一验收中发现的缺口

1. 保存未开始便断线时只有通用错误，没有 `saved` 失败回执；已在保存路由统一补齐失败收尾，并验证电脑未写入且手机结束等待。
2. 在窗口写队列中等待的自动 Retry 可能阻塞停止；已改为取消尚未执行的动作，不等待前一写操作退出，已开始的原生点击保持完整。
3. 若在通用结果入口按当前页面过滤所有回包，会遗漏跨页面请求结束及归档缓存清理；已将结果归属与展示分开，由原功能按请求身份收尾，提示按当前页面展示。

测试夹具曾在重连未就绪时点击禁用按钮、绕过文件预览的请求入口，均已更正，没有据此修改产品功能。保存失败后的测试收尾触发未保存确认，诊断受阻后仅刷新 RA 网页恢复；未刷新原生 Agent 页面。早期失败及诊断记录保留在相同证据目录，最终结果以 `contracts.json`、`browser.json`、`paired-ui-contracts.json`、`final.json` 为准。
