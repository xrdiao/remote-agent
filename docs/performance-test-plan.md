# 全功能测速方案

更新日期：2026-10-23。状态：**方案待执行，没有产生本轮测速结果。**

本文取代旧版功能耗时基线中的测速流程，作为当前唯一测速方案。功能问题、后续测速结果和修复状态继续统一记录在 [功能检查报告](functional-check-report.md)，不重新建立分散的结果报告。旧测速正文已在前轮文档整理中归档，原始数据继续保留供追溯，不能充当当前版本的测量值。

## 1. 目标与执行顺序

先回答当前最主要的问题：**请求已经到达电脑、电脑已经开始生成后，手机为什么仍然迟迟没有显示？** 区分点击反馈、请求执行、Agent 生成和手机同步，不先认定为网络问题。

按以下顺序推进：

1. 记录当前 Codex 慢场景，完成一次发送链路的分段观测；保留现场，不先刷新、重启或切换模型来消除现象。
2. 测项目／会话切换、模型与强度、队列、Question 和执行审批等核心交互。
3. 按第 5 节逐项覆盖输入、文件、终端、历史滚动、画面、语音、管理和通知。
4. 在前置功能可用时，测真实 Fusion 的配置、规划、执行、交接和结束。
5. 汇总主要瓶颈及证据，提出最小修改方案，取得用户确认后再修复。修复后的对照仍使用相同的有效计时终点。

本文只授权范围内的测量规划，不因文档完成而启动测速、修复业务、发布、重启或提交源码。

## 2. 统一计时口径

每个具体动作单独一行，至少区分三种时间：

| 指标 | 开始与结束 | 作用 |
|---|---|---|
| 操作反馈 | 用户操作触发 → 手机首次正确反馈 | 判断按钮是否立即响应；占位气泡、加载提示只算反馈。 |
| 原生生效 | 操作触发 → 对应原生状态确实成立 | 判断请求是否真正执行；不能以回执、菜单关闭或草稿清空替代。 |
| 手机完成 | 操作触发 → 正确结果在手机显示且可继续操作 | 对应用户等待体验；结果必须属于目标项目、会话和请求。 |

纯手机操作没有原生阶段，以真实界面、剪贴板、存储或下载结果为终点。原生变化到手机显示的同步等待单列，观测不到原生阶段时填“不可观测”，不得推算为零。

其他统一要求：

- 记录输入触发方式：真实触摸、Chrome 原生输入事件、程序 DOM 点击不能混为同一种样本。
- DOM 写入、`requestAnimationFrame` 回调和屏幕实际可见分开；后者需渲染轨迹或录像佐证。只有 DOM／帧回调时，标明是显示机会，不声称实体屏幕已经出帧。
- 首次工作说明／思考、首段回答正文、最终完整回复分开；原生界面首次出现内容不等于模型服务端首 token。
- 人工登录、项目信任、权限选择、配对批准的等待单独记录，不混入程序处理耗时。
- 错误结果、空列表、漏读或缺按钮先判功能失败，不包装为“慢”；超时只写“超过观察上限”。

## 3. 发送与实时生成的重点链路

同一次请求关联手机、中继（relay）和原生窗口事件：

`点击 → 手机发包 → 中继收到 → 等待执行 → 原生接受 → 原生首段内容 → 中继提取并发出 → 手机收到 → 内容可见`

### 3.1 最小观测点

| 位置 | 需要记录的事件 | 判断依据 |
|---|---|---|
| 手机 | 发送处理器进入、WebSocket 实际发出 | 分开点击响应和发包；注明软键盘、输入法、附件及当前忙碌状态。 |
| 中继 | 消息入口、串行操作开始执行 | 两点之间是排队／调度等待。仅有执行后的慢日志不足以覆盖这一段。 |
| 中继／CDP | 会话校验、草稿读写、提交调用及返回 | 记录调用耗时和次数，辨别重复读取、菜单操作或其他请求占用。CDP 返回不等于原生接受。 |
| 原生窗口 | 对应用户消息或真实队列项出现 | 这是接受依据；成功提示、输入框清空不能替代。无法观测时保留空缺。 |
| 原生窗口 | 首段工作说明／思考、首段回答、生成结束 | 分清 Agent 自身等待与中继同步；必须匹配本轮而非旧消息。 |
| 中继 | 聊天读取开始、提取完成、对应快照发出 | 区分等待读取、提取执行、后续处理和发包。记录提取在途及是否发生合并读取。 |
| 手机 | 回包进入、渲染调度、DOM 更新、显示帧 | 判断网络之后是否又被主线程、滚动／选字暂缓或渲染合并延后。 |

优先使用既有请求 ID，结合电脑、窗口、会话、原生轮次／消息 ID 关联；不能只按“出现了一条新消息”匹配。缺少关联 ID 时用测试记录建立明确对应，不为测速擅自改业务协议。

### 3.2 本轮必须分开报告的结果

- 点击反馈、电脑真正接受、首段过程、首段正文、最终完整回复的耗时。
- 原生已出现新内容到手机可见的延迟；流式更新间隔、最长停更间隔及对应原生是否仍在变化。
- 正常发送、生成中排队和立即追加分别记录。入队耗时与轮到执行后的首内容耗时分开，不把等待上一轮结束算成发送故障。
- 生成中刷新后的消息恢复单列；刷新不能用来替代原场景观测，也不能让已有请求被自动重发。

现有顶部延迟探测走快速通道，并含原生文档就绪检查，不能代表普通发送的串行排队时间，也不是纯网络往返。已有变化通知、周期读取、节流、在途合并及手机延后绘制均是待测阶段，不预先认定其中任何一项就是根因。

## 4. 测量方法、环境和次数

### 4.1 观测方式与时钟

- 先使用已有日志、浏览器网络／性能记录、CDP 事件和旧脚本的测量结构；不直接运行绑定旧端口、旧会话或旧认证的历史脚本。
- 必要时使用限目标请求／会话、结束即撤销的临时调试探针，记录现有路径的进入与返回。不要加入持续提取轮询、改变调度周期、用暂停式断点计时或保存无关聊天内容。
- 不能取得完整分段时明确写“不可分离”，不编造精确耗时；若必须修改生产代码才能补计时点，先说明具体范围并取得确认。
- 手机、中继、原生渲染进程各用本地单调时钟算内部差值。跨进程／设备的时间戳不能直接相减；需要关联往返估计偏移区间并保留误差，不假设网络上下行对称。
- 网络只报告可观测的往返和传输范围。没有内核到达时间时，中继入站事件循环等待可能混在其中，不能全归为网络波动。
- 若发现排队或事件循环占用，再对同一时间窗口做必要的短时性能记录；不用全程高频采样干扰本身要测的速度。

### 4.2 样本与状态

1. 使用一个配对测试浏览器和独立测试项目／会话；保留版本、入口、网络、设备、数据量及是否正在生成。共用组件测一次，原生驱动或数据来源才按 Agent 分别测。
2. 每项先测一次，仅失败、不稳定或前置不足时续测，总计最多三次，脚本错误也计入。不能换名或重置计数来绕过已达到上限的同一故障。
3. 明确需要首次／再次对照的启动或缓存项目，可指定一冷一热两个状态样本，两者共用三次上限；不把所有功能机械重复三轮。
4. 冷／热分别描述：前端缓存是否命中、原生菜单是否初始化、进程是否存在、模型是否驻留、连接是否复用。“第一次点开”不统一称冷启动。
5. 不清用户缓存、不关闭 Codex、不重启正式中继来制造冷样本。不清操作系统文件缓存；新进程测量不能声称为冷磁盘测试。缺少安全可用的冷样本时记未测。
6. 数据量固定并记录：短／长会话、目录条目数、文件字节数、图片尺寸、音源时长等不能混算。传输先测一个代表大小，只有异常或需区分固定开销／吞吐时再增加指定样本。
7. 一到三次样本只列各次值及范围，不据此报告可靠平均性能、P95 或普遍提速比例。不同版本、网络和缓存条件不拼成同一对照组。
8. 保持用户现有运行负载并记录，不为让结果好看而停止任务。异常时只做能解释该异常的对照，不将每项扩成所有网络、历史长度和忙碌状态的组合。

### 4.3 平台和实际操作边界

- Cursor 使用 Auto；Devin 使用免费的 SWE-2 High；Codex 使用独立低成本测试会话且不得关闭。允许开关 Cursor／Devin 的测试窗口，不替换、停止用户工作项目或运行任务。
- 配对 Chrome、模拟音源、真实原生 Agent 和 iPhone Safari 真机结果分别标记；402×874 等手机视口不等于实体 iPhone 测速。
- 经现有公网／隧道入口的测试与电脑本机环回分开；电脑上的配对浏览器不能代表手机 Wi-Fi／蜂窝链路。需要真机才能确认的项目，没有现场就标未测。
- 设备撤销、归档、Fork、设置写入、审批等有副作用动作只对独立测试对象执行，不改用户安全配置或真实历史来补覆盖。无安全测试条件时记受阻／未测。
- 配对前保留原设备记录，结束只清理本轮精确新增的入口；原始凭据不得写入文档、测速日志或截图。
- 语音复用已有预热、引擎选择和进程机制；测试引擎串行切换，不同时加载多个测试模型，不停止其他设备正在使用的引擎来制造冷启动。保留 Safari 修复、按住录音／松开收尾及草稿插入，不提前申请麦克风，不修改驱动、CUDA 或训练环境。

| N1 加载页管理行为待回退；N2 运行标识失真 | 当前行为如实记录，不能为测速先顺手修改 UI 或用标识推断原生状态。 |
| N3 引用边界；N4 电脑文件分支／删除／发送确认 | 核对正确性后才谈速度，不以空结果、文字清空或无法删除作为完成。 |
| H1 能力跨入口不一致；H2 小屏折叠；H3 上一轮仅工具历史页边界 | 记录入口及触发条件；没有真实场景证据时保留待验证，不升格为全部平台回归。 |
| 启动和惯性等旧项目曾达到三次上限 | 不以测速名义对相同受阻条件再做第四次；条件实质改变时说明并确认新的定向检查范围。 |
| 浏览器通知订阅环境拒绝；无真麦克风／真机 | 记环境受阻或未测；合成音源、服务端回执不能补成系统送达／真录音通过。 |

功能修复与测速分开。即使为了完成测量必须修复前置功能，也先提出最小修改并取得确认，不绕过失败或静默移除入口。

## 7. 结果记录模板

每个动作及每次尝试保留以下字段，先记录原始事件，再形成摘要：

| 字段 | 内容 |
|---|---|
| 测项／动作／尝试 | P 编号、独立动作、尝试 1–3、触发方式；关联已有失败项。 |
| 环境 | 时间与时区、版本及工作区标识、Agent／模型／强度、OS、浏览器／壳、视口或真机型号、入口与网络类型。 |
| 前置状态 | 项目／会话测试标识、缓存、进程／模型／连接、忙碌与历史长度、页面可见性、滚动／选字、在途菜单或静默读取。 |
| 数据量 | 文本／记录条数、目录条目、文件字节、图片尺寸、音源时长等。 |
| 事件时间 | 各进程的本地单调时钟、关联标识、观测方法、跨时钟误差范围。无法取得的节点明确标缺失。 |
| 耗时 | 操作反馈、原生生效、手机完成及可分离阶段；人工等待另列。 |
| 正确性与状态 | 完成／功能失败／环境受阻／超过观察上限／未测／不支持，附实际原生结果与手机对应状态。 |
| 补充指标 | 流式停更间隔、帧间隔／长帧／位置跳变、字节／吞吐、CDP 次数或必要的短时资源采样。 |
| 证据与清理 | 原始时间线、截图／录像／trace 路径、临时入口和窗口／进程清理或保留状态。 |

结果摘要按“测项 → 状态 → 首次／复用条件 → 总耗时 → 可分离阶段 → 瓶颈证据 → 限制 → 最小建议”整理。失败和脚本错误原样保留，不删除失败记录来提高通过率。

原始产物放 `_shots/` 下本轮独立目录，图片和日志避免包含令牌、私钥或无关用户内容；文档只引用必要证据。结果追加到功能检查报告，不覆盖既有故障记录，也不把本方案表格当成已经完成的结果。
