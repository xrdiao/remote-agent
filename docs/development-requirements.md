# 用户要求与续做记录

更新日期：2026-10-21。本文记录本项目已明确的用户要求，不代表所有要求都已实现或已完成真机验证。后续用户明确指令优先；范围或状态变化时同步更新本文。

## 每次修改前

- 先阅读根目录 `AGENTS.md` 和本文，再检查当前分支、工作区差异及有关实现。
- 默认简体中文，说明直接、具体；技术术语按需要给出中文和英文。
- 修改前先取得用户确认。当前明确的“直接改”“开始改”等授权可直接执行，不重复索要相同确认。“先排查”“先给方案”不授权修改。
- 每完成一个完整功能，更新本文对应条目，记录实际实现、验证结果及限制；不能只写计划或把未测项目标为完成。
- 本机语音引擎选择放在「… → 语音输入」子列表，仅显示本机已安装引擎，按电脑记住选择；浏览器权限机制暂不改。开启语音后，刷新页面应在认证成功后后台预热所选引擎，不等待Agent或聊天加载，不申请麦克风。列表内连续选择只记住最终选择，退出列表后延迟启动；切换时停止旧引擎，包括尚在冷启动的进程，不重复加载所有引擎。用户允许安装并实测 Qwen，但不得修改本机显卡驱动、系统 CUDA 或现有训练环境，依赖必须使用独立虚拟环境。
- 遵循最小修改、最小必要检查原则，保护所有既有功能和性能优化；不顺手重构，不重复实现已有能力，不擅自添加保护或兼容逻辑。
- 用户要求只改名字、只改一项、只验证一项时，严格保持该范围。
- 不频繁刷新 Agent 页面，不为测试中断现有任务，不随意切换真实会话或改其模型，不覆盖未提交改动。
- 检查优先只读；交互测试优先用配对测试浏览器和独立测试项目/会话。浏览器不可用或真机未验证时如实说明，不能把脚本测试说成真机验证。
- 测试配对设备：配对前保存完整 `devices.json`，测试后只删除本次配对新增的那个设备 ID，绝不按时间或名称筛选删除（曾因此误删用户 iPhone `e24b0c08`）。
- 截图和临时测试产物放 `_shots/`。现有未跟踪 `screenshots/` 不属于本次改动，不提交。

## 默认发布和重启

- 用户最新要求：以后修改并检查通过后，仅发布手机前端、重启中继，不自动提交或推送；只有用户明确要求时才提交推送。
- 本地 `scripts/local-publish-restart.sh` 同时包含提交推送、手机端发布、重启及公网核对流程；默认只运行其中发布、重启及核对部分，不运行 Git 提交推送部分。该 Bash 不提交；提交信息不得包含 AI 工具署名。
- 用户明确要求提交时，脚本只自动收集已跟踪文件；确需交付的新文件应先明确暂存。不要把截图、授权数据或其他无关内容带进提交。
- 前端变化要考虑资源版本和 Service Worker 缓存，确保手机实际拿到新内容。用户明确只改名称等极小范围时，不附带其他产品行为修改。
- `npm run check` 通过后交付；改协议或页面 helpers 必须检查。验证不应超出必要范围。
- 修改共用聊天提取器时，除目标 Agent 外，还须实际调用 Cursor、Devin、Codex 三者的 extract，验证应用专属分支不影响其他应用；语法检查和单 Agent 数据检查不能替代此项。
- 发布后确认公网资源一致、中继 HTTP 正常；失败则报告停在哪一步，不宣称发布成功。网络失败重试不重复生成无意义提交。
- 用户明确要求提交推送时，按指定分支操作；仅指定提交但未指定分支时默认 `debug`，要求 `master` 时再同步。两个分支可能有独立功能，不强推覆盖；同步具体提交、解决冲突时保留目标分支已有功能。
- 重启前注意是否有 Fusion 任务执行，避免中断任务。保留隧道、配对、操作系统用户和授权数据。
- 仅排查、仅方案、未授权修改的任务不触发自动发布。

## 应用、项目、会话导航：必须遵守

这是用户多次强调的产品规则，后续不得因多窗口适配而反复改变：

- 顶层 Agent 列表每个应用最多一行：Cursor、Devin、Codex、Fusion；多个窗口不能导致同一应用重复出现。
- 顶层只用于切换应用，不承担项目或会话选择。切回应用应优先恢复该应用上次使用的项目/会话。
- 对话输入框按钮名称为“项目/会话”；项目和会话切换、新建都从这里进入。
- Cursor、Devin 沿用 Codex 的“项目一级、会话二级”可折叠排版；同项目多窗口合并，其他已打开项目展开时只读加载并缓存，点击会话才切换。保留当前/运行中标记及每项目新建入口。Devin Editor 的完整历史仍从进入该项目后的原生选择器读取，不为后台读取弹出选择器。
- 底层仍须识别多个窗口，让不同项目和会话可访问，但不要把桌面窗口作为顶层选择项暴露给用户。
- 从项目/会话选择 Codex 会话时，终端必须绑定会话所属的编辑器项目；已有目标项目直接复用，没有时打开对应项目并继续指定会话，保留原窗口及终端，不自动向原终端发送 cd。工作区信任确认后仍继续原先选定的会话。
- Devin 同样按原生会话的工作目录定位编辑器及终端来源窗口，左上角同步实际项目名；已有项目复用，缺少时打开项目并继续原会话。切换完成后的项目/会话列表仅静默更新缓存，不重新弹出。
- 三个 Agent 都需要可靠地创建项目、打开项目、在项目中新建会话，并正确识别工作目录、处理必要的信任确认。打开、刷新重连及点击“项目/会话”（包括命中列表缓存）时发现受限项目，应复用信任确认入口；拒绝时返回最近成功显示对话的窗口，不能自动信任。为保证可返回，打开其他目录时保留已有对话的窗口。
- 创建和切换项目不强制新建窗口：优先使用已打开的目标项目；需要打开其他项目时空闲窗口可复用，运行中任务不受影响。
- 新建/打开项目不能不告知就替换正在工作的窗口。创建失败应说明真正失败环节，不能仅假报启动成功。
- Codex 新项目可能尚未打开侧边栏，需要在会话创建流程处理初始化，不能要求用户碰巧先开好侧边栏。

## 已有聊天与设置行为要保留

- 正常会话输入、发送、流式输出、历史完整性、展开/折叠状态、用户滚动位置和自动跟随不得被其他修复破坏。
- Agent 生成时，开启语音且正在使用对话输入框则显示麦克风，未使用时显示原停止按钮。复用输入框的键盘展开标记及输入事件，输入缓冲2秒，录音和收尾期间保持麦克风；不得让输入框失焦导致已显示的停止按钮在点击过程中消失。语音关闭时保留停止按钮，发送/排队/追加语义不变。
- 麦克风/停止替换仅影响输入框右侧按钮，不能通过改变 `chatBusy`、原生 follow 状态或发送参数影响“排队 / 立即发送 / 立即追加 / 改为排队”。语音模型尚未就绪时不申请麦克风、不排队录音，完成准备后由用户重新按住；不在等待完成后自动开启录音。
- 对话和终端输入框共用发送栏的“↵”换行入口，保留原来的回车发送、Shift+回车换行；终端工具栏标注“终端操作”，发送按钮标注“发送到终端”。
- 第四项反馈已纠正为“已经发送的内容没有显示在手机端”，不能据计时或占位标识判断真实发送失败。Codex 提取最新消息必须排除隐藏旧会话，并补齐当前会话尚未挂载的最近消息；不通过刷新或滚动桌面解决，不改变现有计时逻辑。发送确认和占位状态仍须一致，不自动重发。
- 终端运行 sudo 等交互程序时，输入不能沿用普通命令行的旧输入清理；普通 shell 提示符下仍保留防拼接、防重复执行行为。验证只用模拟密码，不使用真实 sudo 密码。
- 熄屏/亮屏、恢复连接不能使历史乱序。该问题曾在 Devin 报告，其他 Agent 也要注意；未完整复现验证前不得声称已解决。
- 手机隐藏 IDE 自动附加的上下文包装，只显示用户实际请求；不改变发送给 Agent 的真实上下文。
- Codex 同一条已完成、文本未变的回复，在历史快照缺少按钮时，仅保留已确认的 Copy message / Fork chat from here 及原操作目标；不保留 Undo/Apply 等操作，不继承到流式、编辑后或其他消息，不改变 Cursor/Devin 和轮询频率。
- 保留修改文件数量提示、文件列表、具体差异预览和隐藏提示能力；优先沿现有框架修复，不重复造入口。键盘展开时临时隐藏排队栏（含文件改动提示），收起后恢复；不得清空队列或破坏排队消息编辑、取回输入框及保存操作。
- 模型及选中状态必须来自对应 Agent；模型名称、思考强度、Fast 模式分清，切换后及时更新，不串用旧值。
- 账号额度的百分比统一显示“剩余”，首页、详情和 Fusion A/B 一致；保留原始额度缓存及上下文占用口径。
- 三个 Agent 的思考强度统一由低到高排列，保留原生值及选中状态；Cursor 强度页不添加“完成”选项，保留返回入口。Devin 原生 Fusion 仅保留 Lead 思考强度入口，不重复显示公共 Effort。
- 支持原生报价的 Agent 在强度选项中展示对应费用；Devin Fusion 增加当前完整配置成本。金额、原生相对成本与当前实际使用的积分倍率分开，保持原生单位，不估算单次总价。只在菜单/配置操作时读取价格，不加入聊天轮询。
- 设置打开及栏目切换尽量快，保留已有优化；栏目横向滚动位置不因点击重置。
- Codex instructions 应能在手机查看、修改并保存；其他设置内容不能显示空壳入口。
- Fork 要有实际效果并可继续发送。真实会话的测试消息仅限用户明确授权的那次目标和内容，不据此取得任意发消息权限。
- 对话输入历史上下按钮放在发送栏左侧，保留 10 条输入历史及草稿恢复。
- 终端历史不使用对话的 10 条上限；读取当前 Agent 对应终端的历史，选择历史时不同时写入桌面输入，发送时不得重复拼接或执行两次。
- 终端历史上下按钮仍在发送栏左侧；“列表、新建、Ctrl+C、Tab”位于终端输入框圆角区域内。
- 终端输入框内工具栏提供“复制”和“全选”：有选区复制选区，否则复制当前已加载输出；选字期间仅暂缓页面重绘、保留最新待显示输出，不能改变终端读取频率或命令行为。保留长按选择、原生复制菜单与正常滚动，选字不能误触滑动返回。

## 图片、视频、Editor 和主题

- 图片上传后立即显示缩略图，刷新后也不能依赖再次点输入框才显示；支持批量上传。
- 图片编辑是可选项，不要每张图片都强制弹编辑器；可选择在上传前编辑，也可编辑已附加图片。
- 批量上传中已出现的图片可立即编辑、删除；叉号应真正取消上传，且不能拖慢其余图片。
- 图片编辑支持上一张/下一张；保存表示保存全部编辑后上传，保存时自动应用当前裁剪；允许取消上传。
- 图片编辑保留双指缩放和平移、放大后拖动、复原、可拖动文字、可见性良好的裁剪框；常用工具放外面，其他工具可折叠。画笔粗细、橡皮擦、简单图案等属于用户提出的编辑能力，不能未经验证就宣称全部已具备。
- 图片编辑画布与非输入控件禁止原生长按选择、拖图和弹出菜单，开始手势时清除编辑器内残留选区；标注文字输入框仍可选择和编辑文字。
- 图片上传、打开编辑和保存的速度是重点约束，不用频繁刷新 Agent 页面解决同步问题。
- MP4 在原文件预览面板播放，保留 HTTP Range 分段读取、短期播放授权、关闭停止加载；不通过聊天 WebSocket 搬运完整视频。
- 视频预览保留双指缩放/平移、放大后单指拖动和“适应”复位，不破坏原生播放、进度及全屏功能。
- Editor 区分文件夹和文件：图标、文件夹名称字重、进入箭头和分隔线；保留原顺序、类型标签和点击行为，不波及其他列表。
- 文件传输的浏览列表、接收目录选择和上传待传列表沿用 Editor 的文件/文件夹 SVG 图标、尺寸及主题颜色，以 Editor 为准，复用同一图标生成函数。
- UI 与整体风格一致，深浅主题都可读。代码框边界、链接、辅助文字、文件增删和文件标题的对比度要保留。
- 浅色终端参考 Ubuntu 风格浅底深字和深色 ANSI 配色；主题切换不重新拉取整个终端。深色终端配色与命令逻辑保持。
- 画面页用于绘图/仿真窗口，只读；保留缩放刷新；返回按钮只保留箭头，不要圆圈。

## 文件传输

- 「… → 文件传输」是独立于聊天附件、Editor 的入口，浏览当前操作系统用户有权限访问的电脑目录，不局限于项目目录；只按需读取当前目录，不后台扫描整台电脑。
- 文件传输按“下载到手机 / 上传到电脑”双页签排版，两个目录按电脑分别保存在浏览器，上传目标通过独立目录选择器更改，不随下载浏览变化。手机先选文件加入待传列表，可移除、继续添加，再点击底部按钮统一上传；底层 HTTP 传输方式不变。
- “显示隐藏文件”默认关闭，按以 `.` 开头的名称过滤列表；开关及全选只影响列表与直接选择，不裁剪已选文件夹的归档内容。主目录、刷新、磁盘、全选等次要动作收纳，主操作固定底部，保留深浅主题。
- 支持跨目录多选、全选本页、清空选择；单个普通文件直接下载，多文件及整个文件夹以流式 ZIP 下载，保留子目录和空目录，不跟随文件夹内部符号链接。文件内容走 HTTP，不进入聊天 WebSocket，也不将完整 ZIP 或文件读入内存。
- 网页下载位置由浏览器自行决定，下载进度和取消由浏览器管理；不承诺网页可以创建、管理手机统一系统文件夹。
- 手机可多选文件或选择文件夹，上传到页面显示的指定电脑目录，自动创建有文件的子目录；浏览器不提供的空目录无法保留，文件夹选择支持取决于手机系统/浏览器。
- “↑ 上一级”按钮与当前路径同一行、固定在路径左侧，至少 44px 点击高度；导航栏在页签下方吸顶，文件列表独立滚动，长路径省略但仍可点击编辑完整路径；下载页与上传目录选择器一致，根目录禁用。批量上传最多两个文件并行，同一完整目标路径按选择顺序串行，保留逐文件状态、失败重试及取消所有活动请求，不影响聊天附件上传；不承诺突破实际链路带宽。
- 上传提供逐文件进度、取消、失败项重试，以及同名另存、跳过、覆盖。上传目标和电脑授权在选择时固定；取消请求后删除未完成临时文件，覆盖采用完成后替换，不破坏原文件。
- 传输沿用配对和二次验证；下载链接为短期、设备绑定凭据。不改变聊天附件类型/大小限制、上传编辑流程、Agent 会话、终端、轮询和滚动优化。

## 固定入口与启动器

- Ubuntu 与 Windows 都提供启动 Agent 和启动中继/隧道、输出配对信息的快捷入口；已运行服务优先复用，不随意结束应用。
- 手机固定入口属于各用户自己的配置。电脑重启、隧道地址变化后，重新启动服务可从原入口连接，无需重新配对；保留授权数据。
- 先检查本机固定入口，选择固定模式后复用已有入口，没有才询问创建；不要直接要求所有用户使用仓库维护者的入口或权限。
- 用户可选择临时入口，无需 GitHub 登录、不创建固定入口，也不删除或覆盖已有固定入口配置。
- 同一用户的新电脑可以复用固定入口，但新电脑需要初次配对；电脑地址记录不能互相覆盖。

## 2026-10-20 Qwen 两阶段加载与显存释放、手机系统识别引擎（v143）

Qwen worker 改为两阶段：spawn 只做 import+numpy/torch/vllm/qwen_asr 与后台页缓存预热（顺序读模型文件，不驻留缓冲），不触碰 CUDA，进程不出现在 nvidia-smi、占 0 VRAM，发出 `{"type":"prepared"}`；收到 `{"type":"load"}` 才构造 LLM 发出 `{"type":"ready"}`；`{"type":"sleep"}` 走 vLLM sleep level 2 发出 `{"type":"sleeping"}`；`cancel` 在未加载时安全空转。stderr 增加阶段时间标记（process start/imports done/load start/constructed/ready/sleep/wake）。构造参数新增 `dtype="bfloat16"` 与 `hf_overrides={"torch_dtype":"bfloat16"}`，消除了此前每次加载约 2 秒的 safetensors repo-id 远端重试（config.json 的 dtype 为 null，vLLM 走远端探测路径；hf_overrides 置位后解析结果同为 bfloat16）。

释放策略实测决定——sleep level 2 验收失败：睡眠只释放约 1.31 GiB（5.77→4.43 GiB），远低于 ≤1 GB 门槛（权重未走 CuMemAllocator 池，属 vLLM 该路径已知限制），虽然 wake 仅 0.45s 且唤醒后转录正确，仍不满足显存释放目标。因此采用备选方案 A：Qwen 运行时零 client 零 session 满 60 秒后 `stopWorker` 并立即 respawn 一个 phase-1（prepared、0 VRAM）worker；新 client 取消计时器，状态机为 preparing→prepared→(activating)→ready→stopped→prepared，并发加载共享同一 activation promise，engine 切换停止规则不变。vLLM sleep/wake 路径与 `enable_sleep_mode`、worker 端 `sleep` 指令已整体移除，load 在已加载时仅重复 ready。idle release 计时器除 ws close 外也在 activation 完成后再次检查，修复了最后一个 client 在模型尚在加载时断开导致就绪后永久占用显存的竞态（ws close 中 `ws.readyState !== 1` 的既有保护同时避免产生孤儿 session）。日志：`prepared in`、`ready in`、`released (respawn) in`。`preloadVoice()` 对持久化 qwen 只到 phase 1（不占显存），Sherpa 照旧完整加载。`voiceStatus().ready` 仅 ready 态为真。

手机端引擎列表新增 `system`（「手机系统识别」），始终列出即使电脑无任何引擎；无 `SpeechRecognition` 时置灰并说明改用 Safari/Chrome。选择按设备存储同其他引擎；选中后不走 /voice socket、不建 AudioContext、不触发服务端预热。按住即建 `continuous+interimResults` 识别，partial 经既有 voiceText 前缀/后缀逻辑替换插入、final 累积；松开 `recognition.stop()`，onend 给出转录完成/未识别提示并 `cancelVoice(false)`；编辑或断开即 abort 且保留文本；not-allowed/service-not-allowed 复用既有权限提示，network/no-speech 复用旧实现提示（git 找回 v133 前实现）。未恢复旧按钮入口、无原生桥接改动。
