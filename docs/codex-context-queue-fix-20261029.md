- `server/apps/codex.mjs`：仅队列编辑的两处等待改为先检查后等待，继续使用每处 4.8 秒预算和导航取消。保存前记录原生队列 ID，保存后只核对新增 ID 的完整正文与原生消息身份，不逐行查询 React fiber。原生提交方式、完整文本写入和错误反馈保持。

## 改前／改后耗时

这是同条件的**内部受控基准，不是真机或真实 Codex 服务耗时**。执行修改前快照和修改后的实际服务端函数及队列 helper；仅传输和原生接受时序使用替身。条件固定为初始 8 条队列、相同的多行修改文本、相同生成场景、每次传输 3ms、接受延迟 45ms、前序串行等待 80ms。每种草稿各 3 次，表中为中位数。

| 场景 | 编辑执行至草稿收尾：改前 → 改后 | 加入前序串行等待的总耗时：改前 → 改后 |
|---|---|---|
| 空草稿 | 286.46 → 153.71 ms | 366.65 → 233.85 ms |
| 非空两行草稿 | 285.60 → 168.27 ms | 365.71 → 248.38 ms |

空草稿恢复约 15.87ms → 0.01ms，非空草稿仍执行恢复。队列确认相关逐行 fiber 读取次数 15 → 0；新增条件未满足时仍等真实队列接受，不提前报成功。基准的串行等待仍约 80ms，未声称该部分提速。绝对耗时不外推到用户真机；真实网络、CDP 和原生异步延迟由用户验收。
