# RA MCP — 无 RA 账号的远程接入

## 架构与边界

ChatGPT / Codex / 其他 Remote MCP Harness → HTTPS 入口 → RA Relay 的 `/mcp` → 原有 RA 配对与设备撤销 → 原生 Agent / 文件 / 终端。

RA MCP 不要求单独的 RA 账号。OAuth 用于兼容远程 MCP 客户端，支持 DCR、Authorization Code、PKCE S256、令牌刷新和撤销。授权绑定现有 RA 设备；使用令牌时仍复核设备配对与二次验证状态。MCP 接入不会替代手机端原有配对、PWA 或 WebSocket 工作流。

默认不启用 MCP 入口；服务需显式配置 `RA_MCP_PUBLIC_URL`。MCP 复用原生应用和 RA 的控制能力，任务状态、操作回执和客户端协议由接入层维护。发现问题时分别核对原生应用、RA 共享功能、应用适配器和 MCP，避免用接入层补丁掩盖原生状态或共享功能错误。

## 配对与客户端连接

使用支持远程 MCP、OAuth 和 DCR 的客户端，配置实际 HTTPS MCP 地址。客户端的安装、刷新和修改连接入口以其当前界面为准；本说明不假定特定菜单名称。

1. 在目标电脑启动对应环境的 RA 配对流程。A 的本次 QA 可使用 `_shots/ra-mcp-20261124/pair-chatgpt.sh`，应先核对脚本指向 QA 环境。
2. 在 RA OAuth 页面输入该电脑生成的完整手动配对码，不将配对码发送到聊天或写入验收报告。
3. 核对 OAuth 页面与电脑授权窗口的六位确认码、客户端名称及目标环境，再批准本次配对。过期后重新生成配对请求。
4. 客户端连接完成后，实际调用 `list_devices` 和 `list_app_capabilities`，核对电脑身份、可用应用和项目范围。
5. 在已授权的测试项目中验证需要的读取与控制操作。工具发现成功、OAuth 成功、原生应用完成任务是不同的验收项。

匿名 MCP 初始化与工具发现只披露协议和工具定义，不能读取设备、会话或文件数据。执行工具必须经过配对授权与对应 scope 检查。读权限不能调用写入、发送、审批或取消操作；有副作用的工具不得伪装为只读工具以绕过客户端限制。

已有连接需要更新工具定义时，保留其配对身份，按客户端当前支持的方式刷新或更新连接，并实际检查新增工具是否已加载。服务器新增 schema 不等于客户端已经可调用。

## 任务级工作流

当前接口提供 31 个工具，保留原有会话、文件和终端操作，并提供任务级接口：

| 用途 | 工具 |
| --- | --- |
| 发现真实能力 | `list_app_capabilities` |
| 创建并立即执行任务 | `submit_task` |
| 分阶段准备和启动 | `create_task`、`start_task` |
| 查询任务与读取结果 | `get_task`、`list_tasks`、`read_task_output` |
| 原生交互与任务控制 | `approve_task`、`cancel_task` |
| 明确失败或取消后的新尝试 | `retry_task` |
| 查询操作回执 | `operation_status` |
| 原生会话设置 | `read_session_setting`、`set_session_setting` |
| 原生会话管理 | `list_session_actions`、`manage_session` |
| 原生队列 | `read_session_queue`、`queue_action` |

推荐流程：

1. 调用 `list_app_capabilities`，根据实际原生服务、会话和动作能力选择应用。安装了应用、发现窗口、可执行动作与已经验收通过不能互相替代。
2. 对已授权的完整开发任务，优先调用 `submit_task(app, project_path, prompt, operation_id, ...)`。在 prompt 中明确目标、项目边界、限制和验收标准。
3. 需要复用会话时，提供发现结果中的精确 `window_id` 与 `thread_id`；需要创建会话时，先确认该应用当前 `create_session` 可用。不能概括为“只有 OpenCode 可以创建”，也不能假定所有运行中的原生窗口都支持创建。
4. 调用 `get_task` 查询原生进展，以 `read_task_output` 读取结果。返回 `ACKNOWLEDGED` 或 `RUNNING` 只表示已提交；完成后仍需核对真实文件、diff、任务输出及必要测试。
5. 原生等待权限或问题时，读取当前结构化 pending request，仅对已授权的确切任务与 request ID 使用 `approve_task`。动作结果和原生状态需要一致。
6. 仅在需要诊断、验证或直接操作文件时使用低层文件与终端接口，避免把原生 Agent 已能完成的完整任务拆回大量上层命令。

Codex、Cursor、Devin 的 `read_session` 返回所选会话的结构化 `messages`，按原生顺序从旧到新排列，每条含 `id`、`role`（`user`、`assistant` 或 `status`）和 `text`。单页最多 30 条，可传 `limit` 缩小页面。将 `next_before` 原样传给同一会话的 `before` 读取更早一页。游标所指消息离开近期窗口时，重新读取第一页。

`next_before: null` 表示当前近期窗口读完。`native_earlier: true` 表示原生端仍可能有更早内容。空会话返回 `history_status: available` 和空列表，原生历史暂不可读时返回 `history_status: unavailable`。历史读取沿用现有配对会话授权。OpenCode 保留原有最近消息接口。

`send_message` 和任务提交支持显式 `when`：`idle` 仅空闲发送，`queue` 请求原生排队，`now` 请求原生立即追加。Codex 使用原生 Steer；Devin 的立即发送遵循原生中断语义；Cursor 不支持 Steer，OpenCode 不支持 Queue/Steer/Fast，直接返回不支持。不会用 Stop 加重发模拟 Steer。

Cursor/Devin 的原生队列没有提供可持久关联晋升后消息的回执，因此任务接口只接受 `idle`；生成中通过 `send_message` 调用同一手机原生队列能力，返回实际队列回执，不冒充任务完成。Codex 任务支持原生消息 ID 绑定的 Queue/Steer。

Model/Effort/Fast 从手机同一菜单读取真实候选，选择后再次读取确认。设置回执只保证后续提交采用该会话设置，不能改变已经执行中的轮次，也不修改全局默认配置。会话管理仅提供手机原生概览返回的动作。

排队项操作以原生队列回读的最新 ID 为准；部分 Codex 桌面版本编辑时会生成新 ID，并由原生保留顺序和草稿。任务 prompt 保持不可变，编辑原生队列不等于修改原任务。`cancel_task` 只中断可证明归属的当前已接纳轮次；尚未晋升的原生排队项用 `queue_action` 的 `remove` 删除，不能通过 Stop 队头代替。

### 幂等、超时与结果未知

每个不同操作使用唯一 `operation_id`；同一操作的网络重传沿用原 ID。使用 `operation_status` 查询持久回执。

`UNKNOWN` 表示副作用尚不能确认，不表示没有执行。不能换新 ID 重发或另建同等任务。先对照任务和原生状态；只有匹配原任务、会话、消息及原生 turn 的证据才能收敛状态。没有足够证据时保留未知，不伪造成功或失败。

发送处理开始之前的项目、绑定、授权或就绪检查明确失败时，任务为 FAILED；一旦开始原生发送，无法确认实际结果就保留 UNKNOWN。操作已执行但最终回执存储失败时，也必须保持未知语义与去重边界。已返回的 task ID 或原生回执可用于查询，不能据此重复派工。

`retry_task` 只接受已明确 `FAILED` 或 `CANCELLED` 的任务，并产生一次新的尝试；应先确认失败原因及实际副作用。超时处理同样先核对状态，必要时对原任务执行确切取消，不能无限等待或自动重复发送。

## 应用能力与原生请求

能力以当前 `list_app_capabilities` 的动作结果为准。下表说明接入边界，不代表每个运行环境或每种原生版本都已验收：

| 应用 | 任务与会话控制 | MCP 原生交互边界 |
| --- | --- | --- |
| Codex | 已接入原生会话创建、发送、读取及精确取消 | 已接入真实问题回答；答案须有原生消费回执。桌面和后台审批复用手机原生执行器，命令决策须由精确原生请求和执行／拒绝回执确认 |
| Cursor | 已接入原生会话创建、发送、读取及精确取消 | 支持原生多题、多选和自定义答案；权限适配仅处理能核对原生决策回执的当前请求，实际可用性以能力发现为准 |
| Devin | 已接入原生会话创建、发送、读取及 ACP 精确取消 | 权限和结构化问题均调用手机原生执行器；真实问题事件的验收状态另见增量记录 |
| OpenCode | 通过实际原生 HTTP 服务提供会话与任务控制 | 权限和问题适配以真实当前请求及安全校验为前提；服务、模型和请求必须实际可用 |

权限审批只允许受支持请求的单次批准或拒绝，不提供持久 `always`、会话全局放行或 bypass。授权用户可单次答复手机端能够处理的当前原生请求；MCP 不再额外维护命令／路径白名单。设备、授权工作区、任务／消息／轮次和原生选项校验仍保留。请求归属、原生消息、项目路径、参数和可选动作变化时，应拒绝旧请求；不能根据界面文字猜测另一个请求或放宽权限。

能力缺失、未适配、登录失效、模型配额耗尽、网络错误和产品缺陷分别记录。原生模型没有生成问题或权限请求时，不能将普通回复当作交互闭环通过；原生确认取消后，也不能把该轮记为自然完成。
