# 新版 Devin 的 Ubuntu 适配检查与修复方案

日期：2026-10-29。当前 RA：v300，源码 HEAD `9e3d672` 加已有本地修改。Ubuntu 功能对照基准：`0a80c53`（v277）。本轮只排查与提出方案，不修改产品代码，不回退本地修改，不升级应用、不重新配对、不发布或重启中继。

用户本轮明确要求检查新版 Devin，覆盖此前“Devin 暂不测试”的阶段性限制；范围仅限 Devin 接口与功能，不修改 Cursor、Codex 或 RA Fusion 的功能和逻辑。

## 实际环境与检查边界

- 运行中的 Devin 应用版本为 **3.11.228**，编辑器基座为 **1.126.0**。二者不能混称为 Devin 的同一个版本。
- 现有 Devin 同时具有 IDE 项目窗口与独立 Agents 窗口。旧版 `button.switch-segment` 控件不存在；原生窗口配置和界面可区分两种窗口，当前 `devinSurface()` 的欢迎页判据却将两者都识别为 `agent`。
- 复用原有已配对 Chrome，检查 RA 的实际绑定、项目／会话列表、打开会话和模型菜单；另外通过 CDP 只读核对原生结构和元数据。未刷新原生 Agent 页面，未发送新聊天、修改模型／权限、删除／归档／改名会话或执行终端命令。
- 原会话、电脑、窗口、草稿已恢复，网页仍为 v300，九个配对入口保持。打开旧隔离测试会话时，现有 RA 项目流程生成的一个额外测试 IDE 窗口已按正常关闭入口清理，其他窗口保留。
- 新版生成中队列／追加、问题审批、历史连续分页、附件、终端执行和推送投递尚未做正向验收，不能标为通过或全部失效。

证据目录：`_shots/devin-ubuntu-audit-20261029/`，只在本地保留。报告不列用户会话 ID、正文、路径、账号或配对凭据。

## 已证实的断点

| 功能 | 实际证据 | 根因位置与含义 |
|---|---|---|
| 窗口及就绪 | IDE 原本没有可见聊天输入区，RA 却可报告绑定就绪；`surface` 误为 `agent` | `server/page/devin.js` 的 `devinSurface()`、Devin 启动就绪读取与窗口选择不适配新版 IDE／Agents 布局 |
| 项目／会话打开 | RA 实际项目列表有条目，点击已有隔离会话后报“该 Agent 已经不在列表里”，绑定离开原 Agents 窗口 | 当前公共项目流程根据目录进入项目窗口，Devin 适配器仍用旧 Editor 搜索／Agent 列表入口；目标窗口、会话入口与原生身份未贯通。修复应由 Devin 适配层履行现有导航契约 |
| 正文读取 | 原生同一测试会话有 3 条可见用户消息；当前 v300 `extract()` 为 0 条。基准脚本同页可提取 3 条，但缺新版会话身份 | 当前选中会话元数据与 transcript React 属性中的 `sessionId` 不相等，现有去前缀方式也不能解释该差异，`devinLog()` 因而找不到可见 transcript。应核对原生身份关系，不能再猜前缀或按标题匹配 |
| 消息数据 | 选中会话的 `perSession` 中有 `messages`、`events`、`status`、`activity`、`currentTurnId`、`turnStats` 等；本次 `messages` 为 3 条 `user_message` | 真实消息存在。`focusedSessionId` 本次为空，不能把输入焦点当作唯一会话身份，也不能把 DOM 未找到当作空会话 |
| 参数菜单 | 原生 Agents 首页模型按钮可见，但 RA 正常菜单入口返回“模型列表尚未载入”；旧测试会话内当前提取又能读出 33 项模型 | 模型不是全部消失，而是首页／Provider／会话上下文不同，旧 `visibleModelConfigs` 路径不覆盖所有新版入口 |
| 原生配置 | `devin-cli` 会话存在原生 `configOptions`，含 `mode`、`model` 等；实际 model 选项有 67 项 | 可直接依据原生配置及当前值做 Devin 参数映射，不必套用 Codex 设置页或模型规则。33 项家族展示与 67 项原始配置并非同一计数，不据此断言丢失 34 个模型 |
| 会话操作 | 当前有效会话的 `nativeSessionInfo('devin', id).actions` 为空 | `menuSlot.props.actionGroups` 等旧结构需重新对应新版原生动作。尚未执行破坏性操作，不声称原生已删除这些能力 |

补充：新版实际 Provider 包括 `devin-cli`、`devin-cloud`；旧 `cascade` 的判据与过滤需要逐项核对。Cloud 首页与本地旧会话不能用同一种 UI 控件假定。Windows 已有的 ID／字段识别修改存在于公共源码中，但当时主要是 Windows 的少量只读验证；原文档也注明 Ubuntu 未验收，不能当作完整 Ubuntu 功能适配。

## 与基准和当前 RA 的关系

以基准保留 Devin 原有用户功能与原生语义，依据当前 RA 的功能基准 01–06、08、09 补齐契约，不整体回退提取代码。

- 同项目在原窗口换会话，跨项目才匹配／打开窗口；失败回所选 Devin 的初始页，不能随机改用另一 Agent。
- 真实项目／会话身份、消息顺序、Markdown、完整正文、分页游标、运行态、耗时及操作回执一致；未知不假装空闲或已发送。
- 接入现有中继共享窗口连接与快照，保持每个入口选择／草稿／请求独立，不建立 Devin 的另一套连接池或重复轮询。
- 星标、常用、名称、批量管理继续复用电脑端共享元数据和当前项目列表 UI。
- 保留现有滚动、历史一次性保位及实际到底后跟随规则；不新增阅读锚点。
- Codex 的 Max、Steer／Queue 实现和特有 Retry 不是 Devin 必有能力。Devin 原生的立即发送／中断、模型配置及错误重试应遵守自己的实际入口；原生没有的能力不虚构。

## 分组修复方案

### 1. 窗口、启动就绪及项目／会话身份

先修正 Devin IDE／Agents／聊天面板识别，区分调试端口可用、原生目录可读、聊天可交互及首屏就绪。读取会话目录与原生 ID／项目目录／Provider 的真实关联，统一用于列表、打开、当前标记、恢复、文件与终端归属。

新布局不再依赖已经消失的双段按钮、旧标签高度类名和旧 Search agents 文案。列表与切换使用同一真实 ID；已有目标打开后核对原生结果，未成功则结束等待并使用现有失败出口。保留同项目不新开窗口与当前取消／归属规则，不用自动换 Agent、额外重试或固定延时补洞。

涉及：`server/apps/devin.mjs`、`server/page/devin.js`、`server/page/agents.js` 的 Devin 分支；确有需要时，窗口发现／项目绑定入口只增加或修改 Devin 对应分支，不改其他 Agent 的窗口规则。

### 2. 正文、历史和实时状态

先统一选中会话元数据与 transcript 原生身份，使当前已有正文能读取；再以新版 `perSession.messages/events` 和原生历史加载器的实际语义，按消息种类与稳定 ID 产出当前 RA 的 `thread/items/busy/earlier` 等格式。不能用未挂载 DOM、输入焦点或显示索引代替完整会话身份。

首屏有界读取，历史沿真实原生边界向前；生成中的新消息与历史分开消费。保留完整用户消息、回复、思考、工具／命令、文件变更、错误及原生实际支持的结尾动作。原生状态单独更新，不靠正文是否显示推断是否已完成。旧的 acp 显示索引、无重叠就清历史等推断，只有确认被新数据来源替代后才移除。

在现有共享数据源中补齐 Devin 的原生变更通知／新 transcript 监听，不新增独立刷新计时器；后台窗口与旧请求按当前归属规则处理。通知模块继续消费同一份正确的任务 ID、开始时间、结果与待确认状态，不重写投递／去重。

涉及：`server/apps/devin.mjs` 的历史合并／详情、`server/page/devin.js`、`server/page/chat-extract.js`、`server/page/agents.js`、必要的 `server/agent/updates.mjs` Devin 接入。

### 3. 输入、发送、队列、立即发送与停止

在正确 Devin 会话中识别新版原生编辑器及对应动作，先完成草稿写入／读回、引用／附件归属，再接回普通提交。原生接收由同会话真实消息／队列记录确认，不等待整段聊天或上下文读取，也不用输入清空假装接受。

按 Devin 原生支持保留排队、完整队列原文编辑／删除、立即发送及停止语义。不能直接照搬 Codex Steer；如果 Devin 的立即发送会中断任务，保持其现有明确确认。停止清理本入口未确认发送，并只点击当前原生可用停止动作；未知结果不自动重发，迟到回执不擦掉新草稿。

这组当前主要是受前两组阻断且有旧入口依赖，需在实现时分别实际验收，不能现在就说所有操作都坏了。

涉及：`server/apps/devin.mjs`、`server/page/devin.js` 及 `server/page/composer.js` 中 Devin 相关函数。复用当前公共回执格式，不修改 Codex／Cursor 发送流程。

### 4. 模型、强度、加速、模式与额度

分清本地 `devin-cli` 和首页／Cloud 的参数来源；从实际原生 `configOptions` 或仍有效的模型配置读取 ID、选项、当前值与可用性。模型家族、变体、思考强度、加速及权限各自按原生能力显示；选择后核对实际写回，不用点击动作当作切换成功。

保留会话和窗口归属以及当前菜单加载反馈。已有本地会话仍有效的模型配置路径继续使用，只替换失效的 Devin 入口，不整段照搬其他 Agent 的模型实现。额度、价格、上下文按新版真实来源读取；尚未读到不显示为 0 或完整可用，也不以接近限额阻断普通使用。

涉及：`server/apps/devin.mjs`、`server/page/menus.js`、`server/page/composer.js`、`server/page/settings.js` 的 Devin 分支。

### 5. 项目列表操作与共享记录

当前 RA 的筛选、小滑块、星号和更多菜单继续复用；修复 Devin 会话操作枚举与原生重命名／删除／归档入口。菜单只提供原生实际支持的动作，执行后核对实际结果，再更新现有电脑端共享记录、标题与列表。

批量管理复用同一个已修复的单条动作；不另写一套删除路径，不用本地隐藏冒充删除。常用判断继续读取实际消息时间和共享使用记录，原生 updatedAt 的含义需核对，不能把打开／刷新时间直接当成发送时间。

涉及：`server/page/session-actions.js` 的 Devin 分支及 Devin 适配器，必要时调整其原生列表元数据。不改已有公共项目 UI、其他 Agent 的操作或共享库规则。

### 6. Question／审批、附件、文件／变更与终端

在前三组贯通后核对新版 pending 请求、问题选择、文字回答、执行允许／拒绝与原生错误操作。每个动作绑定实际请求，不能变成普通聊天或误提交给其他会话。复用当前卡片格式，不重复造问题卡片。

附件／@／指令使用 Devin 当前原生入口；本地文件与变更读取正确项目，Agent 窗口和 IDE 资源窗口准确关联。新版 Agents 右侧工具面板与原来的 VS Code 终端不同，终端必须路由到真实所属会话／项目的入口，不能因 `surface` 误判直接找旧 Editor 切换按钮。通用 PDF、语音、文件传输、图片编辑器等不重写，只检查 Devin 的交接。

涉及：`server/page/devin.js`、Devin `mentionQuery/withFiles/newTerminal` 等适配方法，以及工具／审批入口中的 Devin 分支。当前没有有效待审批请求、生成中任务或终端操作的完整正向证据，实施后按真实场景补验。

## 影响范围与实施顺序

预期恢复 Devin 的进入、项目／会话切换、刷新后的聊天与运行态、消息发送、模型设置、会话管理及相关工具操作。通过修复数据归属和原生接口，让现有 RA v300 的共享连接、缓存、菜单、常用、历史、通知等继续工作，不在公共层叠加另一套状态和等待。

顺序：窗口／身份 → 正文／历史／实时状态 → 发送／队列 → 参数与会话管理 → 问题审批与工具交接。每组适当使用原配对浏览器验证修改及受影响功能，已通过且未被后续改变的场景不重跑；最后做一次 Devin 限定的往返／恢复综合检查。

若代码位于公共文件，只允许改 Devin 专用函数或明确 Devin 分支；不重写共用滚动、连接池、项目排序、认证、通知投递、PDF、语音、Cursor、Codex 或 RA Fusion。保留现有 Windows 实现，Ubuntu 检查不冒充 Windows 真机通过。不新增猜测式旧版本回退或自动重试，不用回退整个基准覆盖当前本地修改。

实现获用户确认后才修改产品代码；完成必要检查后再按原交付约定更新缓存、同步 gh-pages、重启中继。当前只形成方案，没有执行发布流程。
