# 会话切换与范围读取重构

2026-10-28，网页 v297。用户以“按方案修改”授权本轮。保留开始前 v295 的本地修改，不提交或推送 master/debug。先阅读开发要求和功能基准；按会话、切换、原生控件与连接的边界实施，未修改 Fusion 专用代码，不运行 Devin 或 Fusion 测试。

## 实现与功能边界

- 同项目仍在当前窗口切换会话，跨项目才匹配真实路径／主机并复用或打开窗口。窗口是操作载体，原生会话身份才是选择及列表当前标记的依据；来源窗口不再决定同项目会话的“打开成功”记录。任务、目录和其他窗口不为导航被停止或修改。
- 普通导航将最终绑定身份、项目结果及真实首屏合为一次最终 `attached` 回包，前端复用同一个正文接收函数。中间未就绪的绑定仅作为进度；取消、失败、窗口关闭与回初始页沿现有流程处理。导航失败不自动换 Agent 或创建替代会话。没有真实首屏时不发聊天就绪成功。
- Codex 的首屏、实时尾页与较早历史使用同一个范围读取器。先选择原生记录 ID，再规范化所选正文和补充范围内的富文本、完成态动作。默认预算 80 条可见记录；按原规则隐藏的已完成工具不占预算，所以原始条数可能超过 80。单条消息不截断，页首可补所属用户提问。
- 覆盖游标与附加的用户提问分开：不能用附带提问的最小顺序跳过长轮次的中间内容。前端保留服务端游标，历史请求同时携带已缓存记录身份，合并去重而不靠正文相同判断重复。实时尾页不替换已展开历史，历史插入继续使用既有一次保位，不引入阅读锚定。
- 缓存复用已完成正文及确认过的富文本；切换仍清理在途状态及当前控件，不丢弃所有已完成会话数据。中继缓存最多 12 个会话、每个最多 400 条已完成记录；手机现有缓存保持原用途。busy、排队、Question、审批和 Retry 由当前原生快照提供，历史页不携带可重放的 capacity 操作。
- 首屏不再等待上下文读取和原生监听安装；这些补充任务继续受连接及导航取消约束。已有目标窗口已经显示所选会话时，不再查询与本次绑定无关的终端；真正要改变会话时保留原占用规则。复用本次绑定读到的信任状态，保留最终项目及信任核对。
- 同窗口切会话不再强制做版本适配检查，也不在每次会话选择后扫描所有窗口列表。新连接绑定的诊断、手动重检、创建／管理动作及显式列表刷新保留；列表展开后的会话聚焦保留。

主要源码：`server/page/chat-extract.js`、`server/agent/chat.mjs`、`server/apps/codex.mjs`、`server/agent/context.mjs`、`server/agent/projects.mjs`、`server/session.mjs`、`server/ws.mjs`、`app/js/net.js`、`app/js/history.js`、`app/js/sheets.js`。Cursor 首屏确认涉及 `server/apps/cursor.mjs`、`server/page/agents.js` 与相应 helper 导出。其余前端改动为版本／缓存引用，功能基准 02／03／08 已同步。

## 回归发现并修正的相关问题

1. 原生规范历史已完成，但旧 `turnsPagination.hasLoadedOldest` 仍为 false，导致末尾空加载。统一读取改用同一份规范历史的 `isComplete`，不加延时或重复尝试。
2. 只有 capacity 错误、没有普通消息的轮次不能因原始消息 ID 数为零而被跳过；这类提示纳入范围读取。原生历史覆盖检查曾发现六条此类遗漏，修正后为零。
3. Cursor 会先更新活动会话 ID，再挂载正文。现有切换确认同时核对原生 `hasLoaded` 和非空会话正文；真正的空会话保留正常进入，沿用原有等待预算。
4. 同项目的会话可能列在其他来源窗口下。当前标记及打开记录复用真实 thread 身份，不再要求来源窗口等于操作窗口。
5. Codex 不走 Devin 的逐行 `SC` 存储。最后的统一检查改用真实聊天条目计数，并在既有历史合并处保留连续尾页之间已显示的正文；自由阅读不随页头前移删除内容，回到底部再回收额外行，不添加第二套缓存或阅读锚点。
6. 分页和缓存只提供正文，Retry 由当前容量栏补充，防止翻回旧记录或恢复缓存时复活旧操作。
