| 项目 | 核心修改 | 影响范围及保留行为 |

| 入口仍使用旧缓存 | 导航与 index.html 明确重新验证 HTTP 缓存；新 worker 激活广播自身版本；页面尚无用户操作时自动刷新一次 | 仅网页资源更新；已操作页面留到下次刷新更新，不清空配对、草稿或历史；通知推送与点击处理保留 |

| 图片占用控制连接 | 复用已认证二进制 HTTP 上传；控制连接只提交上传记录，再调用既有原生图片附加流程；取消、错误、目标变化及附加完成清理对应临时资源 | 三 Agent 图片附加、编辑替换、取消和重试；原来的图片尺寸与质量参数不变，文档仍走原流程，旧的直接图片输入入口保留 |

## 最后统一检查

在公开发布的 v275 上重新执行上述 11 组导航、三种刷新恢复、Markdown／公式／复制／文件预览、图片附加与清理，并检查完成回复 Copy／Fork 保留及两组 Retry 流程，全部通过。

最终三种刷新恢复样本分别约 5.28、7.68、2.54 秒；这些是包含浏览器与公网启动过程的样本，不表示每次固定耗时。源码隔离验证说明取消不再拖到旧查找自身超时。

图片原大图样本经过原处理后仍为 714,185 字节；控制消息从约 952,471 字节降到约 215 字节。此次控制探测回执为 380–689 毫秒，大图总过程样本约 6.49 秒；小图样本约 10.74 秒，其中 HTTP 等待约 9.81 秒。公网耗时存在波动，不能将跨次样本当作严格 A/B，或承诺所有图片都在固定时间内完成；本次确定解决的是 Base64 放大和图片占用主控制通道。
