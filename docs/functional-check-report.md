## 证据使用与脚本误差纠正

主要证据位于 `../_shots/final-audit-v250-20261026/`（已忽略，不随发布分发）。真实浏览器结果在 `results.json`；具体 JSON 见下表。运行过程中出现的表达式语法、缺失 mock 字段、未等语言刷新、隐藏标签页和旧 `_rows` 等是测试脚本问题，**不计入产品缺陷**。纠正时只补对应阶段；重复断言不计新的功能或新的漏洞。

特别纠正：

1. 项目点击后不能只等已有的 ready=true；本轮最终等待对应路径 projectReady，再读原生 editorRoots。早先只看 ready 的“通过”被降为脚本前置不足，以最终记录为准。
2. 模型菜单首击可能先展开紧凑输入框；不据此报原生模型菜单失效。语言切换会重载；深色默认存 null 也不是错误。
3. 改名刚提交和 @ 查询尚未返回就读缓存不能算已完成；最终 Codex 列表／共享名和对应 seq 的查询均再次确认。B08 指的是另有证据的版本竞争，不从短延时单独推断。
4. 本地 `origin/gh-pages` 跟踪引用是旧 v240；`git ls-remote` 显示实际远端较新，Pages index 及其余样本与本地 v250 一致。不更新或推送 Git 引用来掩盖差异。
5. 模型快速坐标重开曾发生等待；正常 DOM 控件触发后，三个 Agent 均完成异值切换／原生确认／恢复。这证明处理链可用，不把全部坐标点击时序包装成通过，也未在未定位前增加漏洞编号。
6. 当前原生没有测试会话 capacity／真实审批，受控验证只证明当前适配函数和手机路由，不能证明所有上游界面变体。
