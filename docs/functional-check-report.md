## 1. 环境与检查方法

- 使用一个已配对的 Chrome 浏览器上下文、一个临时授权入口，连接当前正式本机中继；视口为 402×874，另检查 874×402 横屏。测试页中途无响应，关闭了该测试标签页，并在**同一上下文、同一授权**中重新打开，首轮没有换第二个配对浏览器。首轮上下文清理后，用户追加翻页检查，补测另用一个临时配对上下文，未并行使用多个测试浏览器。
- 桌面端是真实 Cursor、Devin 和 Codex，分别使用独立测试目录和会话。Cursor 使用 Auto；Devin 使用免费的 SWE-2 High；Codex 生成任务使用 GPT 6 Luna。翻页补测只读取既有 GPT 6 Astra · High 历史，没有调用模型或更改该历史的模型。Codex 的 Xhigh 无法从手机降低，原因见 F1，没有改用昂贵模型。
- 每项先检查一次，只对失败、不稳定或前置条件不足的项目重试。含翻页补测共 75 个具名检查项、99 条尝试记录，单项最多 3 次；不是把每项都重复三次。次数包含测试脚本自身的失败，详见第 6 节。
- 基本判据为“手机入口操作 → 桌面原生状态或实际文件/命令结果 → 手机重新读取”，不以出现成功提示作为唯一通过条件。多数按钮由 DOM 点击触发；部分滚动、录音和桌面问题操作使用 Chrome 原生输入事件。因此这是真实配对链路检查，**不是 iPhone Safari 真机验收**。
- 语音的合成音源、思考区样本、上传故障注入均单独标注。测试脚本、JSON 与截图在 [本轮证据目录](../_shots/full-check-20261023/)，没有把凭据备份写入本文。

## 4. 思考区滚动的定向结果

使用同一浏览器、现行 `paintThinking()` 和两个临时可溢出区域，附加 Chrome 原生滚轮事件；正文追加为受控样本，没有替换产品函数。

| 场景 | 观测 |
|---|---|
| 从内部底部轻微上翻 25px | `top` 为 1050、原底部 1075；追加后底部增至 1117，`top` 仍为 1050。 |
| 再较大幅度上翻 | `top` 为 905，继续追加后保持。 |
| 用户主动回到底部 | 追加后 `top = max = 1159`，恢复跟随。 |
| 另一框一直停在底部 | 同步追加时正常跟随，未受第一框暂停影响。 |
| 真实短历史的轮次滑块 | 上一轮/下一轮定位、整块高亮、拖动及收起通过。 |

证据在 [原始尝试记录](../_shots/full-check-20261023/results.json) 的 `thinking-inner-scroll-controlled` 与 `turn-navigation-rail`。这是受控 Chrome 结果，不能证明实体 iPhone Safari 的全部跳变和卡顿已解决。

## 6. 重试、误判与证据可靠性

保留 [results.json](../_shots/full-check-20261023/results.json) 中的原始错误，并另列审核结论；没有删除失败行来提高通过率。

- Cursor 项目往返：首次测试页卡死中断；第二次重复使用相同消息标记，隔离断言无效；第三次换唯一标记后通过。Codex 项目往返首次在原生未就绪时读到 null，修正测试等待后第二次通过。
- 设备组、电脑文件添加、输入历史、终端刷新等首次错误包含异步等待不足或选择器不正确。修正后仅补测该失败项，不重跑全部功能。
- 图片首轮在画布加载前按比例按钮，实际仍为原图；缩略图打开原图 1200×900 却被脚本错误要求为 900×900。这不构成预览缺陷。第二轮等待画布后确认比例选中、保存为 900×900；首轮原图预览和历史恢复证据仍有效。
- Fusion 前两次配置尝试分别有 JSON 选择器转义错误、误点尚未更新的 A 选择列表；第三次 B 模型菜单空才是本轮实际功能异常。
- 审批首次错误地等待快照中的空 `permission` 字段；核对原生已选 Ask for approval 后第二次完成实际命令审批。
- 千问第一次模拟录音发生在 Fusion 配置向导仍隐藏录音入口时，未开始采集；返回正常对话后第二次通过。该成功行曾被另一计时脚本的结果保存覆盖，已从同一轮工具输出补录并标明，不计为第三次测试。
- Sherpa 恢复时脚本第一次过早寻找切换按钮；清理阶段已重新核对引擎为 Sherpa、本测试入口语音关闭。不是把报错行改成通过。

### N5：Cursor 窗口重启后手机误报已关闭

窗口发现和连接使用的是动态 CDP 页面目标 ID。`server/windows.mjs:18–27` 每次从 `/json/list` 生成当前 `cursor:<pageId>`；Cursor 重启或重新打开窗口后，该 ID 会变化。服务端 `server/session.mjs:150–155` 按手机传入的 ID 在最新窗口列表精确查找，找不到就发送 `closed` 和“这个窗口已经关闭，请重新选择”。

问题在手机端的窗口行覆盖：`app/js/sheets.js:99–108` 的 `windowEntries()` 用持久化 `currentComputer().selections[w.app].id` 覆盖服务端刚发来的 `w.id`，点击时又把旧选择一并传给 `attach`。如果 Cursor 已重启，列表看起来仍有 Cursor，但点击发送的是旧页面 ID，于是稳定进入上述关闭提示；失败后 `net.js:666–667` 只刷新列表，旧 selection 仍会再次覆盖，形成重复失败。

隔离配对浏览器在不操作真实 Agent 的情况下复现了这个覆盖：当前实时行是 `cursor:81BC4729CB5574E1F82964EE8377AFAD`，把保存的 Cursor selection 临时改为 `cursor:stale-after-restart` 后，`windowEntries()` 返回的可点击行即变成旧 ID。记录见 [Cursor 窗口旧 ID 复现](../_shots/full-check-20261023/new-issues/cursor-closed-window.json)。
