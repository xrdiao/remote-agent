# 完成回复按钮与同项目会话切换修复

日期：2026-10-27。核对起点：`f0b2a6c`／网页 v273。范围由用户确认：恢复 Codex 完成回复动作、纠正同项目切会话的窗口选择，确保 Retry 不受影响。其余功能不在本次改动范围；Fusion 不修改、不测试。

## 已确认根因

1. **完成回复动作依赖原生 DOM。** Codex 虚拟化移除了轮次节点后，原生历史仍提供正文，但提取器把该轮动作清空。缓存仅保留已经见过的动作，且白名单遇到 `View file changes` 会连带丢掉 Copy 和 Fork，导致完成后的入口不稳定。
2. **切会话误用项目窗口调度。** 用户选择同项目另一个会话时仍进入 `useProject`。该流程会考虑窗口忙闲和列表中的所属窗口；因此当前窗口忙碌或来源窗口不同，就可能换窗口。来源窗口和目标项目的身份被当成了同一件事。

## 修改内容与影响

| 相关位置 | 修改 | 保持的行为与影响范围 |
|---|---|---|
| `server/page/chat-extract.js` | 从已完成回复正文建立 Copy；从原生会话能力读取 Fork，不要求该轮 DOM 已挂载 | 工作过程、思考和工具不新增 Copy；复制对象仍为该条完成回复 |
| `server/page/codex.js`、`controls.js` | 未挂载轮次的 Fork 使用同一原生会话的 `onForkTurnMessage`，传入该轮真实 turnId | 执行真正的原生分支操作，保留原始前缀和项目；不通过开关原生菜单寻找入口 |
| `server/apps/codex.mjs` | 缓存按按钮逐项合并稳定动作及其映射，补全已有动作名称；Retry 不作为稳定完成动作恢复 | 现存、禁用、倒计时及消失的 Retry 继续按实时原生状态处理 |
| `server/agent/projects.mjs`、Codex 用户切会话入口 | 先核对真实路径和远程主机，同项目直接在当前窗口切会话；来源窗口不再强制成为目标窗口 | 当前正在生成也不为切会话换／新开窗口；不发送停止任务命令。实际跨项目仍使用原项目窗口流程 |
| `server/apps/cursor.mjs` | 原生会话切换成功文案由“已切换 Agent”改为“已切换会话” | 与本次直接切会话的操作语义一致 |
| `app/index.html`、`app/js/core.js`、`app/sw.js` | 缓存版本升至 v274 | 网页交付更新；不清理配对、草稿或历史，不构建原生 App |
