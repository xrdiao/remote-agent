# Windows Devin 维护

> 当前验收以 [2026-10-23 功能检查报告](functional-check-report.md) 为准。下文旧验证段落仅为当时的实现历史，不能作为当前版本全部通过的证明；本轮已复现 Codex 强度、队列、Question 及 Devin/Fusion 等问题。

本文记录 Windows Devin 的接入、更新和排查方法。Linux 仍使用 README 中的启动脚本；Android 共用网页交互，但原生功能需要单独做 APK 验收。

## 2026-10-12 Editor 与 Codex 闪动修复

保存与 Codex 提问修复（网页缓存 v16）：Windows 本地文件的保存范围比较忽略盘符及目录大小写，返回的实际路径保持原样；Linux 和 SSH 路径仍区分大小写。Editor 内直接显示保存中、保存成功和写入错误，避免主页面提示被覆盖。文件保存独立于原生 Agent 调试连接，仍沿用项目文件范围校验。三个 Agent 使用大小写不同路径保存独立临时文件并重新读取，均通过实测，未修改用户正在编辑的 README 内容。

Codex 中途提问读取新版原生组件的 `questions`、`questionIndex`、草稿与回调，显示完整问题、选项、自由回答、Skip、Next 和 Send；用户操作时调用原生选项／草稿／提交回调，读取时不调用回调、不展开或滚动桌面页面。空聊天面板也读取待答请求；Codex 待答卡片不因普通输入框暂时消失而被当作只读会话隐藏。新版组件结构、网页卡片、回答与翻题流程通过模拟检查；已从本轮真实待答提问只读验证完整正文、5 个按钮和回答框；用户刷新手机后确认 README 保存反馈和提问卡片两项都正常。Chrome 自动化页面验收仍受插件连接失败限制。

历史滚动调整（网页缓存 v15）：删除「＋ → 粘贴图片」，保留输入框直接粘贴图片。取消 Codex 原先距离顶部 5000px 就触发的历史预加载，三个 Agent 统一在上滑至顶部 100px 范围、滚动停止后加载一批；本地缓存每批显示 80 条，电脑历史每次只发一个请求。完成后必须再次上滑才会继续，显示加载中、已到最早消息或生成期间暂缓提示。

渲染前记录顶部可见消息及偏移，批量插入新增节点并复用原有节点；图片高度变化后继续保持阅读位置。上滑期间延后渲染，Codex／Cursor 已加载的历史不会被后续最新消息轮询覆盖。Codex 历史响应保留本次读取的旧消息，避免其被最新 400 条缓存截掉；新协议返回带会话选择和请求 ID 的完成信号。锚点、批量插入、单次上滑触发、缓存优先、生成期间暂缓及三个 Agent 的完成响应通过模拟回归检查，没有为测试滚动桌面 Agent。Chrome 连接仍失败，实际手机流畅度待页面验收。

后续菜单与项目切换调整（网页缓存 v14）：移除「… → 查看文档」，文件浏览统一使用 Editor；权限入口从输入栏与「＋」移到「…」。Devin 的 Bypass 与 Code／Ask／Plan 属于同一个原生模式菜单，该入口整体移到「…」。输入栏按钮使用弹性宽度，保持一行。

项目与会话列表按电脑和 Agent 缓存，再次打开立即显示缓存并后台只读更新；数据相同时不重绘弹窗。Codex 后台读取已有会话元数据，Devin Editor 后台读取已打开标签并保留缓存中的其他会话，Cursor 和 Devin Agent 后台读取原生列表。完整读取只在首次打开或主动点击「刷新项目与会话」时触发，不增加定时轮询。Devin 缓存会话按名称重新定位原生搜索项，避免列表序号变化后打开其他会话。三个 Agent 的只读更新及网页缓存流程通过模拟检查；Chrome 实际页面验收仍待完成。

Cursor、Devin、Codex 共用输入栏的 Editor 文件入口，可浏览项目目录、查看图片、编辑和保存文本文件（包括空文件），关闭文件后返回打开前的目录。Devin 原生 Agent／Editor 界面切换放在「＋」菜单；它与网页文件编辑是两个入口。输入栏保持一行，空间不足时权限按钮收进「＋」菜单。

Codex 生成期间，定时读取不再自动滚动桌面对话或展开／收起思考块，网页也不再自动预加载历史；后端收到已排队的自动历史请求时重新读取生成状态。会话列表、切换失败和归档后的菜单关闭使用原生菜单按钮，不发送 Escape。生成期间不消耗尚未读取的思考详情重试次数。

Windows 下三个 Agent 的项目识别、目录读取、空文件编辑、保存和重新读取均通过原生调试接口实测；测试只写入并删除独立临时文件，没有发送消息。网页流程通过模拟组件检查，尚未完成 Chrome 实际页面验收：插件连接失败，Windows Native Messaging Host 注册项缺失，需要从 Codex 插件界面重装 Chrome 插件。Linux 原生应用待实测。本次仅重启中继，保留隧道和配对，网页缓存版本为 v13。

## 接入与更新

需要 Node.js 22 或更高版本、可执行的 `cloudflared`，以及打开远程调试端口的 Devin。默认 Devin 调试端口是 `9223`，中继端口是 `3939`。Windows 下应给 Devin 可执行程序添加 `--remote-debugging-port=9223` 启动参数；已经运行但没有开放调试端口的实例需要先退出再启动。

在仓库目录的 PowerShell 中，首次运行：

```powershell
npm install
npm run public
```

在另一个仓库终端生成手机配对链接：

```powershell
npm run pair
```

更新已安装的仓库：

```powershell
git pull --ff-only
npm install
npm run check
node --check app/i18n.js
git diff --check
```

有本地未提交修改时，先处理这些修改再拉取，不用重置仓库。更新 `server/` 代码不会让正在运行的 Node 进程自动加载新代码：在原中继终端按 Ctrl+C，再运行 `npm run public`。不要结束全部 `node.exe`、Devin 或 `cloudflared` 进程。

检查中继端口和进程：

```powershell
$relayPid = (Get-NetTCPConnection -LocalPort 3939 -State Listen |
    Select-Object -First 1).OwningProcess
Get-CimInstance Win32_Process -Filter "ProcessId = $relayPid" |
    Select-Object ProcessId, CreationDate, CommandLine
```

电脑配置和配对信息在用户目录的 `.agent-remote` 中。`findTunnelPid()` 在 Windows 使用 PowerShell 查询 `cloudflared.exe` 进程，Linux 保留 Unix `ps`。更新代码时只重启中继，保留隧道进程，即可复用仍可访问的公网地址。隧道退出后重新创建可能更换地址；浏览器配对凭据按网站地址保存，电脑上的配对记录不会因此消失。

Windows 手机窗口列表只显示一项 Devin。打开多个 Devin 窗口时，在「Agent → Devin 窗口」选择具体窗口，再访问该窗口的会话。同名窗口仍按原生窗口 ID 区分；Linux 保留原有窗口列表。

## 区分三个版本

1. **仓库文件**：`git pull` 更新本地源代码。
2. **运行中的中继**：重启后才加载新的后端逻辑。
3. **手机网页**：中继提供的页面与公网静态页面可能不同。推送主线代码不等于静态站点已经发布。

公网启动会尝试同步 App 文件和发布地址；需要检查日志是否成功，再刷新手机页面。网页入口或服务工作线程（Service Worker）仍是旧版时，可能看不到新按钮，但这不代表按钮代码未实现。维护测试应记录使用的是中继页面还是静态站点页面，以及对应的提交版本。

## 常见问题与代码位置

| 现象 | 检查位置与正确行为 |
|---|---|
| 文件打不开，或打开了同名的其他文件 | `server/page/` 的 `devinEdit` 应保留 `fileUri` / `toolCall.rawInput.file_path` 中的完整路径；不能用界面上的文件名替代路径。`lib/files.mjs` 处理盘符和文件 URI。 |
| 全新安装后没有项目，或管理员窗口无法识别项目 | 在「菜单 → 打开项目」浏览文件夹、选择盘符或输入完整路径；父目录内可新建空项目文件夹。Windows 从调试端口对应进程获取安装目录，调用应用自带的命令行启动脚本并检查退出码，不依赖固定安装目录或命令在 PATH 中；项目标题解析会移除 `[Administrator]` / `[Administer]` 后缀，并识别 `项目 - Cursor` 标题。Windows 读取当前窗口标题，避免打开新项目后继续使用旧标题。Linux 保留原启动命令和家目录范围。 |
| 只能看到 Command 标题，看不到命令 | `devinCommand` 读取原生 `commandLine` 和 `outputs[].full`；`setCommandOpen` 负责展开原生命令卡。`app/index.html` 的 `renderTool` 分别显示命令与输出。目前输出最多显示 4000 字符。 |
| 修改文件列表为空 | 原生待审阅列表与历史编辑记录是两类内容。`listChanges` 在无待审阅改动时返回 `historical: true` 的会话记录；`showChanges` 显示“会话修改记录”，点击查看文件当前内容。 |
| 历史文件出现接受／拒绝按钮 | 历史记录不代表待审阅改动，不应提供此类按钮。真实待审阅改动继续使用 Devin 原生操作。 |
| 任务清单不能折叠，或进度与勾选状态不一致 | 检查 `devinTasks`、`setTasksOpen`、`mergeDevinHistory` 和前端 `scKeep`。仅在完成数和总数均未变化时保留缓存详情；详情读取成功后才记录当前进度，失败后下次轮询重试。读取后恢复原生展开状态。 |
| 新会话已创建，但手机仍像旧会话 | 创建完成时检查空会话和输入区就绪，向手机发送原生会话快照，并静默刷新 Agent 列表。手机清除旧消息缓存，持续显示「会话创建成功，尚未发送消息」，第一条用户消息出现后隐藏提示。 |
| Cursor 模型列表为空 | 当前 Cursor 的触发器使用 `.vscode-model-picker__trigger`，先打开参数菜单，再读取 Model 子菜单；旧触发器继续保留。读取失败应明确报告，不返回无提示的空列表。 |
| Devin 额度未获取，或 Pro 缺少日额度 | 读取原生状态栏 `codeium.windsurf.settings.planInfo` 的 `aria-label`，分别解析 Daily / Weekly。手机并排显示原生提供的额度；没有 Daily 的套餐不显示日额度。旧段落读取方式保留。 |
| Codex 已发送的文字仍留在手机输入框 | 发送使用独立请求 ID，原生接受发送后立即确认，不等待附件刷新。按请求清理对应草稿，同时保留发送后编辑的文字，以及其他会话或终端的输入。 |
| 切换会话后出现其他会话内容 | 检查原生当前会话 ID、可见 transcript，以及 `mergeDevinHistory` 的缓存键。Agent 侧栏和 Editor 标签页应读取各自当前选中的会话。 |
| 空会话仍显示旧消息 | 检查前端 `scSwitch`、`scMerge`：空会话应清除该会话缓存，旧会话的异步读取结果不能写回新会话。 |

不要仅凭两个会话都返回 50 条消息判断串会话：原生列表可能按相同条数分页。应比较原生会话 ID、消息 ID 和实际正文。

Android 的网页存储入口是 `app/index.html` 的 `nativeHist`，原生实现是 `android/` 中 `MainActivity.java` 的 `histGet`、`histMeta`、`histPut`、`histDel`、`histKeys`、`histSearch`。调整网页历史逻辑时保持这些桥接接口一致，检查 Windows 路径经过 JSON 存取后仍然完整。

## 最小验收

使用已配对的浏览器连接目标 Windows 电脑，优先检查现有任务，不必为展示功能新增任务。

项目流程：在手机「项目」弹窗选择文件夹或新建项目，再选择「在此项目新建会话」。核对完整路径；遇到限制模式时，分别验证「保持限制模式」不创建 Agent 和「信任此项目」通过原生信任操作后继续创建。窗口、项目分组及双 Agent 名称不应残留管理员后缀。Codex 的「菜单 → Codex 额度重置」应显示操作步骤及官方页面链接，验收说明入口不必消耗重置券。

1. 切到 Devin，分别打开两个有不同正文的会话；再打开空会话。标题、消息和修改记录应对应当前会话，空会话不显示旧内容。
2. 从已有编辑记录打开一个带目录的文件，核对完整路径和文件首行。代码应有语法高亮；存在相对 Git HEAD 的差异时应标记改动行。
3. 展开已有 Command 卡，核对实际命令和输出分开显示，不能只显示标题或把输出当成命令。
4. 展开、收起任务清单，确认自动读取不改变原生展开状态；完成一项任务或改变任务总数后，核对进度与详情同步更新。再切换 Agent / Editor，确认任务仍属于原会话。
5. 有真实待审阅改动时再验收接受／拒绝；没有时只检查历史修改记录，不用历史记录代替审批验收。
6. Linux 本地检查会话读取、文件路径、命令和任务卡，确保 Windows 修改未改变 Linux 行为。运行前述语法检查及 `git diff --check`。

涉及前端交互时，在手机宽度下检查按钮、卡片和弹窗；Android 还需在新 APK 上检查扫码、通知回复及本地搜索。
