# Safari 刷新后 Codex 加载与网页版本排查

日期：2026-10-27。用户现场：Safari，网页显示 v273，刷新后停在 Codex“正在加载对话…”且底部显示“正在打开项目窗口…”，切换 Devin 很慢。本轮只排查，未修改产品代码、未发布或重启；沿用原已配对 Chrome，没有再次配对，不测试 Fusion。

## 结论与证据边界

不能单凭版本号将 Codex 卡住归因于缓存。v274 与 v273 的本次前后端消息协议没有变化；服务端修复也不要求客户端必须先升级才能连接 Codex。已确认三个相关实现缺口，Safari 现场具体命中了哪组保存的窗口／会话身份尚不可直接读取，因此不能将隔离复现当成该手机的完整复现。

### 1. 网页更新允许继续使用 HTTP 旧入口

- 普通公网根入口、index.html、core.js 的新旧版本参数地址、sw.js 的新旧参数地址均重新核对为 v274，HTTP 200；不是只验证带随机参数的入口。公网响应 `Cache-Control: max-age=600`。
- `app/sw.js:33` 的网络优先使用 `fetch(e.request)`，没有要求入口 HTML 重新验证 HTTP 缓存；“发起 fetch”不等于绕过浏览器 HTTP 缓存。
- `app/js/notify.js:14` 注册带版本的 Service Worker、关闭脚本的 HTTP 缓存参与，但新 worker 激活后没有切换当前页面运行脚本的流程。新 worker 与页面 APP_VERSION 是两个状态，不能互相当作已升级的证明。
- 使用真实 sw.js 的隔离执行：当 fetch 返回 HTTP 缓存中的 v273 HTML，worker 会把该 HTML 写进当前 v274 的离线缓存。验证的是此条件下的源码行为，不声称已读取 Safari 的 HTTP 缓存。

建议：导航／入口 HTML 使用明确的缓存重新验证规则；将 worker 版本与页面实际资源版本的切换纳入更新流程，不能只增加缓存版本号。保留已有配对、草稿和本地历史；不通过清缓存解决连接故障。具体更新时机需避免打断进行中的输入与写操作。

### 2. 会话项目元数据在保存前被移除，休眠记录还会抢先决定恢复目录

- `server/apps/codex.mjs:111` 在发出列表时先移除了 workspace／host；`server/session.mjs:92` 随后才调用 catalogSessions。
- `server/project-windows.mjs:43` 在缺少会话 workspace 时使用来源窗口保存的目录推断会话项目。Codex 的最近会话列表包含其他项目的会话，来源窗口不等于会话实际所属项目。
- 只读比较当前保存记录和原生元数据：77 条有可比数据的记录中，32 条字面目录不同，其中 18 条在解析真实路径后仍不同。当前仓库项目的可比会话没有出现该错配；这些数字不能代表用户 Safari 保存目标已经确定错误。目前可比记录没有“目录错配且原窗口已关闭”的实际样本。
- `server/agent/projects.mjs:588` 遇到 dormant 记录时，先按保存目录恢复，没有先使用当前原生会话目录。隔离执行真实 openAgent 源码，提供过时休眠目录和正确原生元数据，确认调用了错误项目路径且没有读取正确的原生元数据。
- 初次恢复通过 `server/session.mjs:242` 进入同一入口，因此也会受影响。

建议：保存会话前保留其原生项目元数据，不能以展示时的来源窗口代替会话 cwd／host。恢复先核对目标会话的真实项目与已打开窗口，旧窗口 ID 和休眠记录仅用于缺失元数据的恢复；同实际项目仍按已确认规则在当前窗口切会话，只有目标项目确实未打开才启动项目窗口。

### 3. 项目窗口等待循环忽略取消，拖住后续切换

- `server/ws.mjs` 已在收到新的导航请求时取消原导航；问题不是缺少一套取消机制。
- `server/agent/projects.mjs:211` 的窗口匹配用 Promise.allSettled 收集失败，取消异常会被当成“不匹配”；`useProject` 的新窗口查找循环（约第 245–257 行）随后继续 fetch／等待，没有退出当前取消的操作。
- 隔离执行真实 useProject，取消后 300 ms 仍未结束，最终返回自己的“应用尚未打开所选项目”而非取消原因。测试将虚拟时钟推进到现有 25 秒截止点以结束，不需要真实等待 25 秒；这不是实测网络耗时。
- 后续 Devin 导航排在原操作之后执行，因此旧等待未结束时会显得切换很慢。

建议：复用既有请求取消信号，让窗口匹配及等待在取消时立即结束；allSettled 不能吞掉整项操作的取消。保留真实打开项目、信任、原生启动及首屏读取的必要步骤，不延长超时、不新增重试层，不停止已经在电脑端运行的任务。

## 建议修改范围

1. 网页入口 HTML／Service Worker 更新与版本切换。
2. Codex 会话目录保存、原生目录优先的刷新恢复和项目窗口选择。
3. 既有项目窗口查找／等待的取消传递。

以上修复需先经用户确认。修改后分别验证旧 v273 更新、刷新恢复、目标窗口不在前台／已关闭／项目错配、旧恢复中切 Devin，并回归同项目不换窗口。此次不涉及消息发送、Retry、完成回复动作、滚动、通知或 Fusion 的功能修改；检查范围以真实受影响调用为准。
