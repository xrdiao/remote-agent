# 连接与安全

[返回 README](../README.md) · [English](security.en.md)

## 连接方式

中继在运行 Agent 的电脑上通过 CDP 连接桌面应用；手机经过 HTTPS 公网隧道或局域网连接中继。固定网页入口可发现变化后的中继地址，使用已有凭据重新认证。GitHub Pages 入口与本机中继是不同组件；保留 `~/.agent-remote/`，并使用原操作系统用户启动中继。

## 配对与设备入口

- 在电脑运行 `npm run pair`，自动打开独立配对窗口并显示二维码、手动码及 3 分钟倒计时。同一码在期限内可重复申请；逐项核对入口地址及六位验证码后点击“允许连接”，无需勾选或填写名称。当前设备的入口自动归组，“开始配对另一台设备”切换分组且不延长时限；分组依据本次操作，不是物理设备自动识别。窗口关闭、到时或在配对终端按 Ctrl+C 会停止本次配对，未批准的申请失效，已批准的入口保留。启用两步验证时仍需 Authenticator 验证码。
- 每个入口使用独立 P-256 签名密钥。浏览器把不可导出的私钥保存在本来源 IndexedDB；Android 新版壳使用按来源区分的 Android Keystore 密钥。服务器只保存公钥，已有令牌必须同时带有效签名才能使用。
- 签名绑定电脑、令牌及请求方法/路径，带一分钟时效和单次随机标识；主连接、语音、HTTP API、上传和 Android 后台请求使用同一认证规则。保持设备时间自动同步。旧版仅令牌配对不再有效，所有旧入口需重新批准；Android 壳需升级至 1.4.0 后配对。清除网站数据导致私钥丢失时也需重新配对。
- 网页密钥功能需要安全上下文：使用 HTTPS 固定入口或 HTTPS 隧道；普通局域网 HTTP 入口不再支持网页配对，电脑 localhost 授权页面不受影响。
- 同浏览器、同源页面的刷新和切换可复用已保存凭据；不同站点入口或其他浏览器不会因为来自同一台手机就自动获得权限。
- 跨站点切换仅携带电脑名称、公开 ID 和入口地址，不携带已有电脑的长期令牌或地址解密密钥。目标入口使用自己已有的配对；首次使用需要配对或由可信入口批准。原入口的配对记录保留，可从电脑列表返回。
- 「已配对设备 → 添加入口」可邀请新浏览器，由已有可信入口核对验证码并批准。新入口取得独立凭据。
- 列表按“设备 → 入口”组织，自动归组依赖明确归属信息，不凭同名 iPhone、IP 或浏览器指纹推断物理设备。分组不共享授权；各入口可独立撤销。
- 移除入口会使其授权失效并断开相关长连接，不会结束已经在电脑执行的 Agent 任务或终端进程。

密钥证明防止仅复制令牌后冒用入口，不是端到端加密，也不校验每段业务正文；请求与响应内容仍依赖 TLS。被控制的网页脚本可能调用本入口签名能力，因此仍需信任前端来源。签名证明的边界可参考 [RFC 9449](https://www.rfc-editor.org/rfc/rfc9449.html#section-11.7)，浏览器密钥要求见 [Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/generateKey)。本项目使用自有签名封装，不声称实现 OAuth DPoP 协议。

## 保护电脑和手机

只授权可信设备，保管配对链接，不公开带令牌的地址、二维码、配置和日志。CDP 调试端口应仅供本机访问，不直接暴露到公网；远程入口经过中继认证。使用 HTTPS，按需要开启 `npm run 2fa`，手机丢失时及时撤销入口。

```bash
npm run devices
npm run devices -- remove <id>
```

`npm run reset` 会清除全部配对、两步验证和相关配置，不是日常重连操作。它不会替你终止已经运行的桌面任务或隧道进程。

这套工具可操作真实终端、项目和当前操作系统用户可访问的文件，不提供独立系统沙箱。隧道的 HTTPS 传输也不等于已实现端到端加密；不要把“自托管”解释为无需信任电脑、隧道服务或前端入口。Agent 本身的账号、订阅和权限仍由对应应用管理。
