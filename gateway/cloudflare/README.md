# RA Gateway / Cloudflare local prototype v0.1

This is a **loopback-only, read-only** prototype, not a public plugin or production OAuth service. It does not replace the existing phone relay, RA Core or RA Connect. The worker intentionally denies non-loopback hosts, workers.dev and preview routes are disabled, and the connector only accepts local ws URLs.

Architecture: MCP Streamable HTTP (stateless JSON response subset) -> Worker -> one SQLite-backed Durable Object -> authenticated, hibernatable device WebSocket -> existing RA Connect owner-only Unix socket -> actual RA file/session read. No cloud storage of file bodies. The request/reply frames are HMAC-authenticated and correlated to a per-connection UUID and per-call UUID. The device independently rechecks local scope, pinned workspace roots and native thread IDs. It exposes no write/send/shell tools.

For local development use an isolated Wrangler installation, `wrangler dev --local --ip 127.0.0.1 --port 8797 --config gateway/cloudflare/wrangler.jsonc` with separate persistence and a private vars file/config (never commit tokens). Required secrets: RA_USER_TOKEN, RA_DEVICE_TOKEN, RA_LINK_KEY, distinct random 32-byte hex strings. Device settings are read from an owner-only JSON file in a 0700 directory, containing mode, url, deviceId, clientId, deviceToken, linkKey, policyPath, socketPath, pinned workspaces [{id,root}] and pinned sessions [{id,app,threadId,root}]. Scope must match the existing RA Connect policy. Run `node gateway/cloudflare/device.mjs /absolute/private/device.json`.

The free plan supports SQLite-backed Durable Objects. Use server-side WebSocket Hibernation and control frames, not continual polling or a running cloud process for each PC. Pending requests remain in memory only for a short timeout; reconnect does not automatically redispatch them. The hibernation API is wired in, but actual hosted hibernation, availability and billing require cloud verification. This MVP supports one registered test device; not yet a multi-tenant service.

Before a public deployment: implement OAuth/MCP authorization discovery and per-user device registration/revocation, authenticated TLS/WSS, independent local approval for writes/Agent requests, abuse and rate controls, end-to-end tests on real cloud with fail-closed auth, and ChatGPT review/connection. Do not change the loopback restriction merely to expose this test server. Pro custom MCP write permissions are a separate product limitation.
